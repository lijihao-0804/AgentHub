**目标：** 回答“当前 Agent 在具体业务任务上表现如何、是否稳定、评分是否可信”，补齐工程测试之外的质量证据。

- [ ] 编写预登记协议：研究问题、基线/候选、唯一主要变化、主次指标、失败处理、停止规则、预算、样本与重复数选择依据，以及判定收益/非劣性的阈值。
- [ ] 准备来源可追溯、许可清楚的数据；按来源/模板/实体组划分 DEV 和独立 HOLDOUT，检查重复与泄漏。已经看过、调过的历史 HOLDOUT 不重新当盲测。
- [ ] 将数据发布为正式 DatasetVersion；冻结代码 SHA、resolved spec、知识/Wiki 快照、数据/schema hash、价格、evaluator/judge 及 simulator/environment 身份。
- [ ] 根据希望检测的差异、区间宽度与重复可靠性需求设计样本，不能将三题单次成功当作稳定性结论，也不将重复 trial 计为独立任务。
- [ ] 制定可执行 rubric，准备包含正确、部分正确、错误、缺证据、拒答、安全失败和 UNKNOWN 的人工校准样本。

- [ ] 取得明确模型/路由/金额与尝试次数预算后，先在 DEV 小规模技术预检，再运行冻结实验；记录全部成功、失败、截断、取消及未知尝试，未知结果不自动重试。
- [ ] 分别报告业务状态断言、语义质量、安全结果、success_rate、pass_hat_k、覆盖率、区间、延迟与成本来源；包括人工和 judge 的实际覆盖范围。
- [ ] 按预登记规则在独立 HOLDOUT 做一次确认并记录曝光，不根据已曝光 HOLDOUT 继续调参后声称独立确认。

验收标准：

- 从发布数据到正式实验、原始结果、人工/judge 标签和统计结论可追溯；预登记与实际执行差异透明。
- 能说明 judge 在哪些类型上可靠、哪些类型需要人工复核；不将 judge 当 ground truth。
- 质量报告有正确分母、覆盖率和不确定性，负结果与费用未知均保留。
- 未获付费调用授权时，仅交付冻结协议、数据和校准方案，真实模型阶段标记未执行，不伪造完成。

交付物：预登记协议、发布数据身份、rubric/标注记录、冻结实验、原始结果与费用台账、judge 校准报告、质量结论和推广/不推广决定。

## T06｜上下文与 Memory 质量提升

**目标：** 先测清楚当前质量问题，再按证据实施最小修正；分别验证上下文摘要与长期记忆，不将二者混成一个存储或评分机制。

### T06-A：质量基线与失败分类

- [ ] 复用 T04 方法建立独立 DEV/HOLDOUT 与可读期望，分别记录 WRITE、RECALL、最终 ADMISSION、USE 和任务结果。
- [ ] 上下文覆盖事实更正、否定、例外、条件依赖、跨轮约束、工具调用/结果成组、旧摘要与新用户声明、超窗与恢复。
- [ ] Memory 覆盖相关/无关属性、旧事实、矛盾事实、临时状态、明确禁止记忆、隐私、恶意注入、跨任务/跨租户和过期事实。
- [ ] 先复现并归类选择、写入、摘要保留、模型使用或评分口径问题，不仅统计脚本后置条件通过率。

### T06-B：按基线证据选一个改进切片

- [ ] 摘要方向：核对受保护原文、事实更正和引用来源；普通近似计数与受限格式精确计数分开报告，不扩大固定 tokenizer 的适用范围。
- [ ] Memory 方向：优先针对已证明的相关性误召回或禁止使用问题修正 selector/准入；冲突事实替换需要明确来源、时效与语义合同，不能自动认定最后写入必然正确。
- [ ] TTL、衰减、容量治理按真实需要单独选切片：已有 expires_at、touch、supersede helper 应复用；活跃容量与历史存储容量分开。
- [ ] 清理采用逻辑退出召回和受控生命周期，保留发布版本/实验/Run 引用的历史内容；过期或替换不能破坏历史 replay/hash 校验。
- [ ] 新配置随版本冻结，并验证并发写入/淘汰、边界时间、撤权、checkpoint 恢复与跨 Workspace 隔离。

### T06-C：对照验证与推广门

- [ ] 在同批任务与冻结条件下，对比现有策略与单一改进；Memory 的 ON/OFF、WRITE/RECALL/USE 分开，避免多机制同时变化无法归因。
- [ ] 对摘要同时计入摘要生成和后续多轮的总输入/输出、全部尝试成本及端到端延迟；后续答案输入下降不等于净省钱。
- [ ] 在 DEV 达到预登记门后使用独立 HOLDOUT 确认，报告质量、错误率、区间与资源代价，保留退化和负结果。
- [ ] 生产自动摘要继续保留 `SUMMARY_QUALITY_GATE_NOT_MET`，直到质量、净收益、计数适用范围和金额预算等既有推广条件全部满足。
- [ ] Memory 默认策略的变更只作用于明确的新版本，不能隐式改变历史发布版本或把实验候选自动切成生产默认。

验收标准：

- 能证明具体失败类型有所改善，并解释代价；单次样例或脚本满分不视为总体语义收益。
- 负向约束、原子工具交换、权限/租户隔离和历史回放没有退化。
- 是否推广有明确证据；门槛未满足时交付负结果、保持默认与门禁，也可以完成一个研究里程碑，不通过反复调已曝光 HOLDOUT 追求通过。

交付物：质量数据与失败分类、选定切片的实现/配置/测试、完整对照结果、成本与时延核算、推广或保留默认的决定。

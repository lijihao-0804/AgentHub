# Sixth-source retention on frozen retrieval candidates

Registered on 2026-11-18 before inspecting this study’s individual retrieval outcomes. Both corpora have prior project exposure. This is an exploratory comparison with no provider or GPU calls. The historical scorer and product defaults stay fixed.

For each query use its original ordered twenty BGE-reranked chunks, without adding, re-scoring, re-ranking or consulting relevance labels. Preserve ranks one through five, their order and their complete source offsets. Baseline A retains rank six. B changes rank six only if its source already appears in the first five. It takes the first chunk at ranks seven through twenty whose source is absent from the first five, keeping the original rank six if none qualifies. C uses the identical replacement only when the sixth chunk’s full half-open character interval is already covered by the union of the first five intervals in that same indexed document revision. Exact character coverage includes whitespace. A gap, an unverifiable position, or a different revision leaves the original sixth chunk in place. Fewer than six candidates are retained as supplied. Use a source identity stable within each frozen index. Never merge different revisions to test coverage.

Use the 648 historical BEIR FiQA TEST queries, original FiQA documents and document qrels. Report query-level at-least-one-source hits, total matched judged relevant sources, macro recall, additive paired gains and losses. FiQA supplies document relevance. Its full published answer document can also serve as a separately labelled whole-text coverage proxy where exact source offsets can be established. A delivered fragment or a complete answer document is not an annotation of the minimum evidence required to answer a financial question. Mark genuine sentence-level evidence unmeasurable on FiQA.

Use the existing 553-query SciFact TRAIN population, including its 379 query–source pairs with official sentence rationales. Report source retrieval on the available official labels, plus how many of those pairs contain at least one complete officially annotated evidence set for that source. All sentences in a set must be visible within their own source revision. Check joint source character coverage across all displayed chunks. Report the number of distinct annotated queries, the presence of complete evidence per annotated query and paired set gains/losses, including cases where a query keeps one set but loses another. A query cannot gain or lose just by having multiple equivalent output chunk IDs. Keep exact denominators for all metrics. If an archive only has a shorter ranked list or lacks trustworthy full-text ranges, disclose the limit and keep that population separate.

Evaluate all six admitted chunks with enough evidence budget to display them in full. Separately evaluate the same ordered six through the project citation-QA evidence builder at a budget of 512 estimated evidence tokens, using the exact visible text and serialized user message. Also report the 16,000-unit setting and verify it against the unbudgeted six. The builder retains its historical parameter name `max_chars` and charges the project token estimator for whole records. Record actual visible character intervals, deduplicated source IDs, any local truncation and query-level gains/losses against A. Report whether the sixth slot reached the packed message. Keep full-text rank, packed visibility and a live provider measurement distinct. A product change would require separate evidence.

Freeze and report input hashes, source revision identity, and selected policy predicates. Publish derived counts and reproducible code, keeping raw archived text, raw caches and model outputs local. Report every arm, including a conservative arm that never fires.

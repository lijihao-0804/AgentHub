# 笔记本上的稠密编码器对比

本实验与六段证据的产品验收独立。沿用已有 FiQA DEV，在读取模型成绩前按题号加盐哈希取前 80 道有正相关标注的题。每题选取官方正相关文档和全库词级 BM25 前 12 篇，将所有题的文档合成一个共享索引。每个模型都在整个索引上做精确余弦检索。报告每题文档 Recall@1、@5、@20 及宏平均、建库与查询时间、单进程峰值显存。候选库包含金标且小于原库，百分数不能与 FiQA 全库成绩直接比较。

在同一张 GPU 上依次加载固定修订的 BGE-M3、多语 MiniLM-L12 和 Qwen3-Embedding-0.6B，按各自的池化和归一化逻辑编码。Qwen 对查询使用官方检索指令，文档无指令。批大小 4、FP16、输入上限为原生窗口与 512 token 的较小值。这个探索对比的是可直接部署的编码配置，包含窗口长度差异。模型权重只保留在本地缓存，不更改 AgentHub 当前索引或工作区模型。

8B 可行性小组固定取上述 80 题的前 12 题，在原共享索引内取每题 BM25 前 5 篇与全部金标，合并成四个模型共用的索引。8B 使用官方 Q4_K_M、llama.cpp b7550、末 token 池化、逐条本地 HTTP 编码。记录实际卸载层数、建库和查询时间。原生批处理和逐条 HTTP 的用时均保留各自口径。

# 在固定证据预算内合并同源重叠窗口

对 SciFact 的 553 个英文主张固定融合与重排结果，每题给证据正文 512 个项目估算 token。遇到同一索引来源的重叠窗口时，先尝试合并区间，再判断全文能否放入预算。完整官方依据由 277/379 增至 285/379（+2.11 个百分点）。8 题获得依据，分布在 6 个来源簇。逐题核对没有原先完整、合并后丢失的依据。

## 实验设计

使用原有 SciFact TRAIN 确认分区，包含 367 个来源簇，与当时的开发、预热分区按来源簇隔离。其他研究曾使用这个确认分区。本轮先固定单一预算和规则，随后查看评分，没有使用这些题调参。代码基线为 `f2822c3ae0ff9d6f0c6a24547c58472142fde3af`。语料、分块和 BAAI/bge-reranker-v2-m3 的真实历史打分沿用仓库既有哈希校验。两臂使用完全相同的稠密与稀疏融合前 20 和重排前 5，均按排名扫描，放不下的整项跳过，再尝试下一项。[协议](protocol.json) [上游数据与实验说明](../../results/published/candidate-recall-20261114/README.md)

基线分别计费。候选只合并同一文档、相接或重叠的字符区间，保留最靠前的展示位置；有间隙的两段仍独立计费。每个入围块都校验文档 ID 及标准化源文本切片与索引块正文的精确一致性，去掉旧定位两端由切块器裁下的空白。评分把官方句子映射回同一份源文本，以半开区间检查标注的任一整组依据是否齐全。每句须由一个展示窗口完整覆盖，整组可跨多个窗口。[实现](replay.py)

## 分阶段结果

| 指标 | 基线 | 合并同源区间 |
|---|---:|---:|

| 重排前 5 的正例来源 / 625 | 482 | 482 |

| 至少有一组完整依据的题 / 341 道有标注题 | 274 | 282 |
| 553 题证据正文消耗合计（项目估算 token） | 223,454 | 223,910 |
| 预算内展示窗口总数 | 989 | 867 |

共有 160 题的展示窗口变化。正例来源逐题均保持相同，8 题从已检出的文档得到更完整的文字。其余 545 题的完整依据集合持平。两臂最大单题正文消耗均为 512，候选平均每题多用约 0.82 个估算 token。作为额外敏感性检查，也允许评分器拼接两臂已经展示的重叠区间；按这种口径完整依据仍为 277 与 285。[汇总及来源哈希](results/summary.json) [553 题配对记录和变动窗口定位](results/pairs.jsonl)

新增完整依据的原始问题 ID 为 `1210`、`169`、`594`、`1211`、`164`、`420`、`1284`、`1371`。逐题文件记录来源 ID、左右字符边界、来源与依据得失。当一个文档在多个主张中重复出现时，同组题的改善相互关联。

## 适用范围与复现

这次只评估一种英文科学摘要语料和一种正文预算。预算使用生产代码的近似 token 估算，未包含提示词外框及引用标签。没有运行生成模型，也没有测量答案正确性、在线时延或费用节省。当前线上引用对象关联一个块 ID，若要展示合并窗口，还需给引用保留组成块及其源区间，故本次作为研究策略交付。

在具有上游确认分区、打分快照及官方资料本地缓存的原仓库执行。输出目录可另选，核对两份派生文件以及汇总中的配对文件 SHA-256。公共仓库仅包含派生记录，原始语料与模型缓存须依照上游说明准备。

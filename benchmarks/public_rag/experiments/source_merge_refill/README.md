# 合并同源连续片段后补入新来源

在 512 个估算证据 token 下，FiQA 可见相关来源从 437 增至 440，SciFact 能完整展示官方依据的题目–来源对从 277 增至 280。放宽到能展示六段全文的预算后，两库分别增加 7 个和 5 个相关来源。每条候选消息都逐字符核验原消息中已展示的区间。各项新增均未伴随原有来源或官方句集丢失。当前 API 的一条引用只指向一个已存储块，此结果属于离线消息原型。

## 规则与采用情况

A 沿用真实 BGE 排名前六块。B 在这六块中依固定顺序寻找同来源、同修订、字符区间相接或重叠的一对，将两段归并为连续原文，保留两个原块 ID、原始定位及各自展示区间。两段之间只要隔一个字符就跳过这对。腾出的名额交给原排名 7–20 中第一个新来源。每个预算独立检验 B 的最终消息是否保住 A 已展示的全部字符，未通过则回退 A。两臂均不超过六段。[冻结协议](protocol.md) · [回放与区间检查](replay.py)

| 数据集与预算 | 符合合并补位条件 | 采用候选 | 回退原序列 | 实际消息改变 | 新来源块出现在消息 | 已核原可见区间 |
|---|---:|---:|---:|---:|---:|---:|
| FiQA 512 | 149/648 | 77 | 72 | 39 | 6 | 1,549 |
| FiQA 16,000 | 149/648 | 149 | 0 | 149 | 149 | 3,888 |
| SciFact 512 | 336/553 | 169 | 167 | 138 | 9 | 1,028 |
| SciFact 16,000 | 336/553 | 336 | 0 | 336 | 336 | 3,318 |

在 512 预算下，若改排的块也进不了消息，采用候选后仍可能逐字得到原消息。SciFact 该预算下补入的新来源块只在 9 题中可见，标注来源集合逐题不变，仍能从原来源取得更多完整句标。

## 来源与证据

表内均为 A → B。FiQA TEST 有 648 题和 1,706 个相关题目–来源对。其中 1,705 对的原答案文档非空。“全文”检查是否展示了整个相关答案文档。FiQA 没有句级最低充分依据标注。SciFact TRAIN 有 553 题和 625 个相关来源对；341 道题中的 379 个来源对附有句标，共 667 组不同的来源、标签与句号集合。

| 数据集与预算 | 标注来源对 | 至少命中一个来源的题 | 每题来源宏召回 | 完整原答案文档或完整依据来源对 | 完整官方句集 |
|---|---:|---:|---:|---:|---:|
| FiQA 512 | 437 → 440 / 1,706 | 340 → 341 / 648 | 30.80% → 30.99% | 313 → 320 / 1,705 | 无句标 |
| FiQA 16,000 | 632 → 639 / 1,706 | 411 → 413 / 648 | 42.14% → 42.41% | 443 → 446 / 1,705 | 无句标 |
| SciFact 512 | 378 → 378 / 625 | 374 → 374 / 553 | 65.04% → 65.04% | 277 → 280 / 379 | 424 → 440 / 667 |
| SciFact 16,000 | 490 → 495 / 625 | 456 → 458 / 553 | 80.32% → 80.83% | 350 → 352 / 379 | 597 → 600 / 667 |

FiQA 完整文档数在两档预算分别新增 7、3 对，丢失均为 0。SciFact 完整官方依据来源对分别新增 3、2 对，完整句集分别新增 16、3 组，原有句集全部保留。有至少一组完整依据的标注题，在 512 下从 274 增至 277，在 16,000 下从 325 增至 326，分母均为 341。例如，SciFact 题 962 在充足预算下得到新的标注来源 4306711，完整覆盖该来源第 2 和第 6 句这两组独立支持依据，句号从零起算。[逐题新增项及双块定位样例](results/summary.json)

## 引用与成本边界

生产接口中每个编号只有一个 `chunk_id`。服务据此构造对外引用，并将每条摘录限制为前 2,000 个字符。原型的联合定位列出两份原始 ID 和区间，研究用联合标识没有对应的已存储块。16,000 预算下，FiQA 有 64/149 个可见合并段超过当前摘录上限，SciFact 有 98/336 个，最长均为 2,200 字符。512 下分别为 0/33 和 3/136 个。即使模型输入完整，看见单条 API 摘录的读者也可能缺少末尾依据。[检索证据结构](../../../../packages/knowledge/contracts.py) · [返回引用构造](../../../../packages/knowledge/citation_qa.py) · [HTTP 引用结构](../../../../apps/api/schemas/citation_qa.py)

证据预算只对每段正文计费。把问题、来源及双块定位一并序列化后，512 档的单题用户消息估算上限，FiQA 从 677 增至 693，SciFact 从 646 增至 709。16,000 档相应从 1,981 增至 2,318、从 2,014 增至 2,356。这些是项目估算值，不代表供应商实收 token。该回放没有调用模型、检查生成答案或发布产品默认值。

## 复现

运行 `python -m benchmarks.public_rag.experiments.source_merge_refill.replay`。输入复用上轮固定的两个原始排序归档、FiQA 本地历史快照数据库、SciFact 句标和索引清单。程序先验证两档 A 的全部可见来源区间摘要与上一轮一致，再逐题检查保留、引用组成、六段上限、预算、完整句集和新旧差异。相邻、重叠、单字符缺口、不同/未知修订、原文不符、新来源顺序，以及预算后遗漏原区间均有针对性检查。冻结协议 LF SHA-256 为 `cb9f69f0b46148988c6c8c1d2457eccfef4e6cf79de82d2e1bbffd92a33c341c`。两个数据集均有历史曝光。

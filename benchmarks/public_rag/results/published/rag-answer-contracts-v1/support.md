# 客服已发布版本的事实口径与核对

产品 API 可在创建或更新草稿时设置 `runtime_config.support_answer_policy="support_facts_v1"`，发布后写入 `resolved_spec.runtime`，参与 SHA-256。省略该字段沿用 PR19；更新草稿需要另行发布才影响新版本。旧版捕获的版本哈希、原客服系统提示和实际入模提示已在归档测试中逐字核对。两组使用同一客服模板、新老策略各自发布。新策略没有额外模型调用，且未修改检索参数、政策投影或审批状态机。

## 从实际工具消息可以推出什么

|实际观测|可支持的说明|
|---|---|
|请求中未见该工具消息|当前模型所见材料尚未提供该查询结果。|
|工具失败、结果截断|查询失败或返回不全；现有片段不足以排除缺项。|
|成功返回对象，字段缺失|该响应没有提供此字段。|
|显式 null|该字段没有返回值。例如本次订单查询未返回退款对象。|
|空集合|该次响应的集合为空。宣称某个范围内没有记录，还需上游确认覆盖该范围。|
|开放工单列表及完整性|原生查询按工作区、客户、开放状态及可选精确主题筛选。收到列表、范围和完整标志时可按该范围和此次读取解释；不涉及工单历史。|
|退款申请时间与空退款对象并存|保留申请时间和本次查无退款对象两个事实。更新时间、审批时间、发出支付指令和结算时间各自独立。业务时钟不充当查询数据的时间戳。|
|金额或日期未知|保留字段名称、币种和单位；订单总额、实付、申请额、批准额、结算额不得互换。签收或验收日期缺失时，事件和截止日均需核查。|

能力清单取自哈希验证的发布工具修订，列出名称、已声明参数、必需项、读写效果与运行时有效审批要求。模型仍接收完整参数 schema，调用继续经过既有工具及审批边界校验。只接受订单号的查询可以要求补订单号；取件码等辅助材料不会成为查询键。批准只说明决定，执行成功须有返回回执，独立读回还要有相应读结果。拒绝且未执行、执行结果未知分别保留；未知执行终止为 NEEDS_ATTENTION，不自动重试。

事实说明附加在已返回、无截断且可完整装入工具预算的原始观察外层；原数据及原审批字段继续保留。未知上游覆盖与未知时间不填默认值。能力与政策措辞进入必需系统消息，接受与原提示相同的上下文预算。所引政策段必须支持对应主张，保留并列、备选、例外、适用渠道和起算事件，仅在对应原文明确排他时使用排他措辞。单测用新政策文本通过产品投影核对条件及引文归属。

[历史逐案核对](support-history.json)覆盖 52 个 Run、129 笔物理回执。检查实际请求中的工具输入、送达的业务数据及证据哈希、最后响应、持久化 Run/Turn、审批决定及工单读回。48 个 Run 的持久化正文与最后返回一致；4 个有已结算调用但没有终答。语义判定及冻结流程判据沿用原评审，50 个 DEV 的整题正确数 14，两个新增场景 0。

## 离线复跑

在本地 PostgreSQL、Qdrant、已缓存的 BGE 模型和 DeepSeek tokenizer 环境运行。capture 目录必须全新。contract 模式使用本地脚本生成器和合成凭据。

```powershell
$env:HF_HUB_OFFLINE='1'
$py='.venv/Scripts/python.exe'
& $py -m benchmarks.evaluation.experiments.support_refund_rag.product_acceptance --mode contract --support-answer-policy support_facts_v1 --output .scratch/support-facts-contract-repeat
& $py -m benchmarks.evaluation.experiments.support_refund_rag.support_answer_audit --capture .scratch/support-facts-contract-repeat
& $py -m pytest -q tests/unit/test_support_answer_policy.py tests/unit/test_refund_product_acceptance.py
```

生成层的真实改进仍需冻结后的配对首答。脚本生成器用确定性工具调用覆盖发布、预算准入、建单、拒绝、持久回复与读回；这些结果不计作模型自然语言质量。

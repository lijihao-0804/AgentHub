16 组引用问答的用户消息逐字一致。每臂共 22 个片段，逐一匹配冻结来源正文与编号。候选的系统提示每题增加 123 tokens，输入累计增加 1,968。客服候选系统扩展每次调用计 511 tokens，44 次累计 22,484，观察字段累计 1,537。这两个局部计数不能直接分解总输入差额，两臂的调用次数、检索与工具历史也有变化。耗时为任务端计时，每题每臂只运行一次。

客服 14/16 组实际检索词序列不同。15/16 组交给最终模型的去重来源及其正文 SHA-256 相同。SUP13 候选多查了一次政策并得到 POL-S13-1。SUP04 和 SUP14 两臂均未搜索，SUP13 基线也未搜索，这三题均无必需政策检索。所有实际检索结果均按原顺序、完整正文进入最终请求，未观察到新增提示挤出已检索片段。此结果适用于本次输入长度和检索行为。

每臂 24 项必需 READ 均成功，实际读调用中未发现错误状态或越客户、越订单实参。SUP13 两臂均按指定主题获批并各新增一张工单。SUP14 两臂均被拒批并保持未执行，拒批结果是两次 TOOL_APPROVAL_DENIED 的来源。其余题均未发起写审批。

32 个客服任务各自使用不同数据库、工作区、线程、Turn、Run、版本和快照。逐库只读联结确认全部 Run 成功、输入和版本哈希一致、快照 ID 和内容哈希一致，数据库 Run 正文与冻结 Run、Turn 两个视图均相同。Turn 表通过 agent_run_id 指向持有正文的 Run。28/32 个 Run 的 event_log_complete 为 false，不能据此证明全事件流完整。该字段与终态正文分别核对。

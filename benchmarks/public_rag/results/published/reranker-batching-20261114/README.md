# SciFact TRAIN 的 BGE 重排批处理对照

本次在同一块 GPU 上比较 `BAAI/bge-reranker-v2-m3` 处理同一组文本的两种方式。旧实现按原候选顺序逐批编码，新实现一次编码输入、按实际长度分批，再把分数放回原位置。两臂共享同一份 FP16 权重和 tokenizer，最大长度 8192、批大小 8。主决策使用测量前保存的[冻结协议](protocol.json)。

## 样本与测量范围

从 809 个公开 SciFact TRAIN 问题中，按固定盐和问题 ID 的 SHA-256 排序选择前 128 题，另外 4 题只供预热。历史快照含 5,183 篇论文、9,189 块。每题固定原生产混合召回和融合已选的 20 块；128 题共 2,560 个查询–候选对，其中有 2,084 个不同块、1,656 篇不同论文。当前切块器根据原论文和历史修订号重建每块内容，逐一匹配原块 ID。

每题连续运行两臂，两种先后顺序各 64 题。热计时从适配器入口到取得全部 CPU 分数，包含分词、传输、推理及恢复顺序，在边界同步 CUDA。另一次无计时前向捕获模型真正收到的张量，核对每题全部非填充 token ID 和填充后的计算量。区间使用 10,000 次配对重采样，分组依据全部训练题之间共享的正例来源，测量样本覆盖 120 组。该区间反映当前设备和会话内的问题差异。

文档 nDCG 先合并同源块再取前 10 项。工具预算代理先截前 5 个原始块，再算标注来源覆盖率。公共训练数据此前已用于本项目开发，这里报告开发验收。测试标签、外部推理服务和付费模型均未参与。向量检索、数据库、在线 API、最终答案和完整 Agent Run 时延在此次测量范围之外。

## 复现

从仓库根目录运行，输出目录须为新目录。协议列出输入、历史候选、基线 Git blob、本地模型文件及 SHA-256。逐题数据和真实模型输入均留在本地。

```powershell
& .\.venv\Scripts\python.exe -m benchmarks.public_rag.reranker_batch_benchmark --output .scratch\reranker-batching-reproduction
```

也可以通过 `--model-dir` 指定同一权重快照的本地副本。仅克隆仓库时，还需要协议指定的公开 SciFact 原始文件、本机历史候选及逐对审计文件，以及已缓存的模型快照。复现入口读取原基线 Git blob 和归档的候选适配器。候选源码的 LF 规范化 SHA-256 与原实测版本一致；验收后仅对运行器改用了归档文件入口，并增加上述两个描述性指标。具体毫秒数随硬件和运行环境变化。[配对运行器](../../../reranker_batch_benchmark.py) · [实测候选代码](../../../experimental/length_batched_reranker.py)

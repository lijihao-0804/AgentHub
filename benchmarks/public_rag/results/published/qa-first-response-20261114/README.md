# AgentHub 真实引用问答首答：502、拒答和证据

[原始九条故障逐项定位](history/README.md) · [本轮十条 502 与真实模型回执](new-502.md) · [实验入选和历史曝光审计](exposure/README.md)
· [盲评判据](rubric.md) · [检索及生成方法依据](research.md)

**采纳了故障分型、严格校验修复和真实入口复验工具。三个生成策略都未通过独立题验收，默认检索、提示和模型模式保持原样。** 已证实低额度会让供应商完成调用却不交付可解析的答案；同一题把额度调高能消除这类 502，却可能得到引文不能充分支持的 HTTP 200。两者分别计数。

在上一轮的 51 次真实首次 HTTP 请求中，9 次返回 502，涉及 5 道题。
通过每臂的串行调用顺序与同请求的检索、重排、模型 span 对齐，
5 次在生成成功后未通过 JSON 解析或严格 schema，4 次在模型网关
交付可用内容前失败。九次均仅一次模型调用；旧 PROMPT_JSON 遇引文
编号不一致本会再发起一次矫正，所以没有证据将这些历史错误归到
引文编号校验。历史日志缺乏可见内容形态、finish_reason 和解析子码，
无法给每个旧请求进一步断言根因。

新跑的 138 次原始首答加 12 次独立认证补测中，一共观察到 10 次
502，全部有同请求的供应商回包、`finish_reason=length` 和 512 个
输出 token：5 次没有可见正文，另 5 次有正文但严格 JSON 解析失败。
这十次均只发生了一次模型调用。认证过期的 12 个 401 另记。

四轮回执共返回 196 条引文，均已核对版本、原块和原文位置；
全部评分逐条区分“引文能支持某项事实”和“整段回答都正确”。

新的真实对照固定同模型、问题、知识快照、可见证据和本地严格校验。
公共文档、租户范围、引用块、源位置和摘要均可独立重建。首答指一次
用户 HTTP 请求，错误和已有的服务内引文矫正也完整记账。三个样本
互不同题、不同论文，均属于公开 TRAIN 开发确认；本次不消费正式
HOLDOUT。首轮 12 题里一题还曾出现在未运行的预留名单，另列排除
后的 11 题结果。样本经过可答性和段落可对齐筛选，不能据此估算线上
所有问题的正确率。

* [非思考模式，12 道独立题与 11 道旧控制](live/decision.md)：
  首次 200 从 11/12 到 12/12，完整有据正答从 7/8 到 8/8，
  正确拒答从 3/4 降至 1/4；拒绝推广。
* [恢复配置额度，14 道独立题与两道旧诊断](budget/decision.md)：
  首次 200 从 11/14 到 14/14，三个 502 均在 512 输出 token 耗尽时
  出现。但保住的原正答只有 7/8；单改额度未通过答案保留门槛。
* [收紧答案范围和拒答条件，16 道独立题与四道旧诊断](reader/README.md)：
  三臂分别隔离旧的 512 限额、原提示的 2,048 额度以及同 2,048 下
  的新提示。首答 200 分别为 9/16、12/16、12/16；有据正答
  4/10、5/10、5/10；正确拒答均为 4/6。新提示相对原 2,048
  无实测质量增益，两者都把旧的一次 502 变成了新错误作答。三臂各
  含同四题的认证失败，未进入模型；[另列补测](reader/auth-supplement.md)
  不替换首答。[预登记比较条件](reader-protocol.md)

**620 与数据量题的直接证据。** 第一次重建的基线两题均 HTTP 200；
第二次在相同 512 额度上，又分别发生了“输出上限时没有可见正文”
和“输出上限时可见文本未能解析为 JSON”。后一轮实际适配器回执有
结束原因和用量，未发生阿里云超时，也没触发引文矫正。2,048 时两题
均收到 200：VG 给出了有据的 16k 图片、740k 条描述，而 620 仍需
区别小鼠间质耗竭和题干所说的纤维化减轻。[620 对照](budget/512-full.json)
· [VG 对照](budget/512-qasper.json) · [完整评分](budget/review.json)

实际修正的诊断路径对无可见内容、JSON 解析、字段校验、引文越界、
拒答附带引文及标记不一致分开记账；异常超长引文编号和过深 JSON 也
会返回契约中的 502，不再意外抛出 500。只记录失败类别、尝试号等
有限元数据，未加入额外重试。过去的 QA 实验沿用了 smoke 脚本的
512 上限；本轮为正式 QA 配置生成独立的模型档案，默认读取路由的
2,048，并允许显式降低做对照。业务路由原本即按配置生效。

[第一轮](live/README.md)、[第二轮](budget/README.md)、

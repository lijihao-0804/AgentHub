# 不推广 512 token 下的非思考模式

在同一北京 DeepSeek 模型、温度、输出额度和提示下，12 道独立题的
HTTP 200 从 11/12 升至 12/12，8 道可答题中充分且有据的回答从 7/8
升至 8/8，原先 7 道均保住。4 道官方无答案题的正确拒答却从 3/4
降至 1/4。对两个原本正确拒答的问题，候选的正文承认参数量比较、
实验数据条数在材料里找不到，却引用旁证并把机器可读的
`insufficient_evidence` 标为 false。下游会把这两次当成成功回答。
去掉曾被旧提案预留但未评估的那一题，HTTP 10/11→11/11、
可答 6/7→7/7，正确拒答仍为 3/4→1/4。只有一个 HTTP 状态变化，
配对双侧精确检验 p=1，不能据此估算线上故障率。

有两处需要读原文才能合理评分。官方标成无答案的一题，论文确实说明
使用了私人英文新闻语料，两种答案都有引文支持；保留原拒答分母，
同时记录标签冲突。对冻结声学模型的提问，官方短答案摘自讲前人工作
的段落；论文的方法段实际描述冻结、在干净语音上训练的 ASR 模型。
原臂这题收到供应商 `finish_reason=length`、512 输出 token，且无可见
内容，网关返回 502。候选这次回答了实际模型，引用的原段可证实。

另 11 道历史诊断中，8 道原本充分作答的题和 2 道应拒答的问题均
保住。620 在基线给出有限有据结论，在非思考模式下返回无引文弃答；
两次均实际把支持有限结论的另一篇论文送至读者第一位。VG 数据量题
两臂得到 16k 张图与 740k 条描述，且第六个原块可直接支持这两个数。
两道点名的历史故障均未在本次基线重现。

23 对问题的候选前 20、重排结果、读者块顺序和发送到模型的
证据提示摘要逐对一致。两臂合计 74 条引文，全部核对了版本、原块、
原文位置和可见摘录；人工规则的单次助手盲评也逐条判为支持至少
一项引用处的事实。这不意味着回答完整，尤其不能抵消拒答字段错误。
独立 12 题的 HTTP 中位耗时为 27.9→34.0 秒。两臂顺序固定，CPU
检索及启动时间包含在内；供应商用量合计为 32,069→29,164 输入
token，3,652→1,289 输出 token（含引文矫正）。未取得结算账单。

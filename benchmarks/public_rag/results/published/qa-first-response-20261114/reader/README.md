# 回答充分性与输出预算的三臂对照

**没有推广新提示。** 16 道新题的首次请求结果如下，401 和 502 都留在各自分母。完整正答要求引用支持所答事实；正确拒答要求接口确实返回无证据状态。两位独立 Astra 评审在不知道臂的情况下，对全部 52 种不同答复的结论和逐条引文判断一致。

|16 道独立题|A 原提示 512|B 原提示 2,048|C 收紧提示 2,048|
|---|---:|---:|---:|
|首个 HTTP 200|9/16|12/16|12/16|
|502 / 登录过期 401|3 / 4|0 / 4|0 / 4|
|完整有据正答|4/10|5/10|5/10|
|正确拒答|4/6|4/6|4/6|
|错误作答（含应拒答却答）|1|2|2|
|引文支持至少一项所附事实|10/10|18/18|12/12|

原来四道正答和四道正确拒答均保住，但 A 的一个 502 在 B、C 都变成了错误作答：引文写了 0.812，指标名在该摘录中是占位符，不能据此称为 F1。C 相对 B 没有改善任何预登记的首答或语义指标。四道历史题单列：VG 数量、意大利语词向量规模三臂均完整有据；话题标签题 A 返回 502，B/C 均正确拒答；620 的 A/B 给出区分间质与纤维化的有限结论，C 全盘拒答。均未证明题干中的完整因果链。

同四道正例三臂均在认证处停止。其余 12 道独立题（6 正、6 负）的实际候选顺序、重排、可见片段与模型端用户提示摘要分别相同。在 6 道真正进入检索的正例中，目标论文在前 20 和读者均为 6/6，完整标注证据段由候选的 5/6 降至读者的 3/6。例：关于用户回复数量的题，精确写明 1,001 的原块排在候选第 15，但不在送模型的 6 块里。增加输出额度无法补回缺失的段落。[原文与读者输入](verification.json) · [首答评分和配对门槛](review.json) · [第二份独立评分](second-review.json)

[登录过期现场与另列补测](auth-supplement.md)保留原始失败和完整分母；它只回答四题在有效凭证下的表现。原始执行、逐个 401 的时间和错误码见[运行回执](execution.json)。

[逐题协议](protocol3.json)包括 16 篇新论文上的 10 道可答题、6 道官方无答案题，以及旧快照上的 4 道历史诊断题。三臂的 HTTP 请求均省略 request_mode，使用供应商默认模式、温度 0 和 60 秒超时。A 和 B 使用原 PROMPT_JSON 系统提示，输出预算分别为 512 和 2,048。C 使用 2,048 和[新增的充分性指令](prompt.patch)。用户提示和读者证据另行逐题验证。

16 道新题中六种先后排列分别出现 2–3 次，A、B、C 各有 6、6、4 次首发。同一题按事前冻结的顺序连续执行三次，各臂保留第一次 HTTP 结果及其全部内部调用。A/B 和 C 分别由两个本地串行服务执行。每个请求的适配器 wire 事件保留用户提示和系统提示各自的 SHA-256、超时和输出预算。源码和提示摘要见[来源记录](prompt-provenance.json)。每组结果的文件名包括臂名和语料范围。reserve16 是新题；reserve14 是历史 Word2Vec 和话题标签题；qasper 是 VG 数据规模；full 是 SciFact 620。

## 离线重建与付费复跑

原始 16 道新题的后 4 道在三个臂均收到 HTTP 401，错误码 ACCESS_TOKEN_EXPIRED。两个客户端在该组开始时分别登录一次，实测令牌寿命为 900 秒。12 个错误均未进入检索或模型。其完整记录保存在[执行回执](execution.json)中，仍计入正式首答分母。该 4 题在同一快照的[补充验证](authenticated-supplement/protocol.json)采用每次请求前重新登录，结果单列。复跑入口也使用逐请求登录。

从 273f683 导出两份 apps 和 packages。保留第一份源码，将[补丁](prompt.patch)应用到第二份副本，分别作为 --baseline-root 和 --candidate-root。准备和配置本地隔离的 API、worker 及空 Qdrant 集合，见[完整环境说明](../live/README.md)。在仓库根目录执行以下命令验证摄取；删除 --prepare-only 则发送三臂的模型请求。

~~~powershell
.venv/Scripts/python -m benchmarks.public_rag.qa_first_response_replay --api-url http://127.0.0.1:8049/api/v1 --reader-triplets --baseline-root .scratch/reader-original --candidate-root .scratch/reader-strict --scopes reserve16 --output .scratch/reader-replay --prepare-only
~~~

每个 scope 使用新的输出目录和相应的隔离集合。历史 reserve14 自动摄取全部 14 篇，历史 qasper 会分两个知识库摄取第一轮独立 12 篇和历史 7 篇，在原 7 篇快照上查询；full 恢复公开 SciFact 语料。新建快照的 ID、同分排序和云端生成可能变化。

便携核验脚本 `../verify.py` 仅使用 Python 标准库，核对预先固定的公开源码清单、各臂原始字节哈希以及实际发送的系统提示和用户证据哈希，可在 Git 归档中运行。完整的 `qa_first_response_reader_review --verification` 另外从冻结 Git 提交与公开补丁独立重建源码，并从 QASPER、SciFact 原始语料核验引用区段。

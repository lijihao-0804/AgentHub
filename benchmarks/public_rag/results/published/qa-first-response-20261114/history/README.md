- 五次 QA 型失败的公开错误码为 CITATION_QA_INVALID_MODEL_OUTPUT。模型 span 成功。冻结版本在 PROMPT_JSON 下遇到正文与引文列表不一致时会进入第二次模型调用。仅观测到一次成功的模型调用，结合错误码可定位到首份输出的唯一键 JSON 解析或 Pydantic 严格结构校验，包括字段约束。历史数据未保留解析器子码或 schema 错误类型，无法区分 JSON 语法、重复键、字段类型、字段缺失、数组重复项等。
- 四次网关型失败的公开错误码为 MODEL_BAD_RESPONSE，同请求 model.generate span 以相同错误码结束。适配层及网关有多个路径可产生该码，未保留上游状态、结束原因、响应形态或映射分支，具体触发条件未知。
- 620 的独立只检索重放中，替代来源 20888849 第 0 块在三臂均为读者第 1 位。父臂首答给出有据的限定结论，纤维化减少仍未证实。基线和文档臂的历史失败分别落在不同阶段。[重放逐级名次](../../article-recall-20261114/live/620-source-delivery.json)

## 下次运行需要保存的最小诊断

给单次 HTTP 请求分配独立随机关联号，客户端保存题号、臂、顺序、HTTP 状态和关联号。对每次网关调用单独保存尝试序号、阶段、耗时和白名单枚举的终止状态。网关记录上游状态类别、响应是否有 choices、是否有可用文本、finish_reason 枚举或 unknown。QA 分开记录 JSON 解码、重复键、schema 字段错误类别、引文越界、标记与编号集合不一致、弃答携带引文，以及修正尝试是否发生。仅在允许的基准观测范围内对实际发送的有序证据清单计算带运行密钥的 HMAC，记录条数和预估长度，才能核对同次实验的输入一致性。仅保存上述白名单字段，避免序列化验证异常（可能携带原输入）、自由字符串、原始响应、引文正文、查询、凭据或响应头。

# 从干净仓库复核 SciFact 结果

在仓库根目录运行下列命令。只需 Python 3.10 或更高版本；`-I -S` 让解释器忽略用户环境和所有第三方包。默认逐层打印新增、丢失及各一个公开题号/论文号。添加 `--json` 可列出全部变化配对。

```console
python -I -S benchmarks/public_rag/results/published/candidate-recall-20261114/portable/verify.py
```

**在 553 题确认集上**，基线、BM25 补位、BGE 保护补位的候选宏召回分别为 86.456%、87.722%、86.817%。从 20 个候选块到重排后前五个块，三臂可见的完整官方证据来源对分别是 357 → 342、348 → 339、356 → 342。保护版从候选池中失去的一对是题 178、文档 23557241。128 题开发集中的原 13 道零命中题，在两个 BM25 方案下均未恢复。[完整比较报告](../protected-followup.json)

每一行包含公开的查询 ID、正例文档 ID、具有官方句标的正例 ID，以及三个方案分别命中的四组文档 ID。各组依次对应候选 20 块、真实 BGE 排序前五块、候选 20 块中完整可见的官方证据、前五块中完整可见的官方证据。一组官方备选证据里的每个句子都须完整落在一个返回块中；不同句子可以位于不同块。宏召回先对每题求命中正例数占该题正例数的比例，再对题目等权取均值。新增和丢失均按同题前后的集合差计算。[逐题派生明细](hits.jsonl) · [原始来源指纹与字段顺序](provenance.json)

程序验证两个冻结队列的有序 SHA-256、题号唯一性和金标无跨组重叠，再与归档中的候选召回、真实重排和完整证据报告逐项核对。每层同时核对总数、保留、新增、丢失及零命中状态转换。生成明细时重新执行了历史取证程序，并检查重新生成的保护版候选及完整报告与原结果相同。发布的 681 行仅保留命中来源集合；重建模型向量、块排序、原始 logit 或复核句子坐标仍需原始研究输入。统计复算没有发起模型调用。[冻结队列](../cohort-freeze.json) · [候选确认](../confirmation.json) · [BGE 重排](../rerank-report.json) · [官方证据可见性](../rationale-visibility.json)

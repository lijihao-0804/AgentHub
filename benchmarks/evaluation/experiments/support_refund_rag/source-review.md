# S0 来源与语义审阅记录

审核人类型：assistant-reviewed。助手起草和主助手复核，不是独立人工金标。
这是预执行 DEV 材料审核，不是模型回答评分。

## 已检查的依据

主助手读取了16份政策正文和50题的输入、关键事实、原文证据及对应订单。
逐字原文存在性另由 `check_materials.py` 检查；该脚本不能替代下面的语义审阅。

| 审阅点 | 初稿发现 | 修正要求 |
| --- | --- | --- |
| 必要证据完整性 | 将同时必需的事实放入多个 OR 组，单一事实就可能算完整 | 同时需要的事实合并为 AND；只有真正完整等价方案才能作为 OR 替代 |
| 订单事实 | 题面冰箱但 fixture 背包、官网与商城混用、编号不一致 | 逐题对齐订单编号、渠道、商品、日期、金额和退款记录；不靠input覆盖错误工具事实 |
| 工作日边界 | 10月14日出款，10月19日上午误称第3工作日已结束 | 固定服务器业务时钟；区分当日进行中与工作日已结束；不得用执行日 |
| 三状态 | 批准/出款/到账混进同一个决定状态字段 | 业务退款status与decision/execution/payment维度明确区分，记录契约映射 |
| 跨案记录 | 克隆订单残留其他订单的refund_id/金额 | 逐单独立退款身份；null保留未知，不用默认100元填缺据题 |
| 版本选择 | 合约旧版本有效期与10月复查规则可能互相冲突 | 显式区分business_time和contract_signed_at；旧合约沿用旧版不等于用当前日期选最近文档 |
| 长文与跨段 | 标long的文件实际不足一次1200字符切块 | 使用有业务内容的真实长文；检查字符数，不以label声称跨段覆盖 |
| 缺据/冲突分桶 | 可回答的UNKNOWN_OUTCOME转人工题计入缺据桶 | 替换为真正证据不足/冲突题，保留8题桶和可解释标签 |
| 注入题提示泄漏 | input直接告诉模型“这是注入”，B只给干净政策 | 自然客户问题；攻击保留在来源；B必须同时保留攻击和合法政策，不能悄悄清洗 |

## 能力主张边界

这些资料是全新起草的虚构DEV题，没有将旧题改名为独立HOLDOUT；未读取既有HOLDOUT。
来源中的攻击片段带显式测试标记，难度有限，即使通过也只能证明本组显式攻击样例的行为。
没有人工审阅，因此不能据此声称真实商家政策、实际接管、正式总体准确率或对抗安全性。
缺据题的“充分证据”仍须保留缺失，冲突题须保留双侧原文。

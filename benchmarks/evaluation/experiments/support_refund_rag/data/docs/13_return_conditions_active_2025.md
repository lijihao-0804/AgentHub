# 退货前置条件与费用

## 无理由退货

1. 普通商品无理由退货应保持商品本体完好、随机配件和安全标签齐全。为确认商品不涉及危险故障，允许进行一次不改变商品功能状态的合理检查。
2. 消费者自行选择的非质量问题退回运费由消费者承担；商家错发、运输损毁或经核验的商品自身故障，由商家承担退回运费。
3. 到付寄回只在客服明确提供到付账号时成立；仅有政策陈述不表示已经生成到付单。

## 大件和家具

4. 大件家电存在运输破损时，需要提供外包装、机身破损部位和物流面单照片；三项都要有，以免把运输责任误判为消费者使用损坏。
5. 家具已经现场组装且出现使用磨损时，不属于完好无理由退货；安装导致的尺寸错误仍可转人工核验。
6. 礼品订单退货应由下单人发起；礼品收件人可解释问题，但不能代替下单人确认退款账户。

## 免费退货边界

7. 退货保不适用于第三方商城渠道、大件家电、家具、合约设备或本人原因退货。退货保只能覆盖符合条件的普通官网小件。

## 跨段证据组合

8. 普通商品退货材料至少包括订单号、申请原因和可接收通知的手机号。商品故障另加故障照片或短视频、商品外观照片和问题描述，三类证据分别说明功能、外观与客户观察，不能互相替代。
9. 序列化设备出现故障时，还须补充机身序列号照片。序列号照片只用于核对设备身份，不等于设备已经判定损坏，也不等于退款批准。
10. 大件家电运输破损的申请人应同时提交外包装、破损部位和物流面单照片。客服可以将三项材料一起转核验，但在核验完成前不能承诺商家承担退回运费。
11. 商家错发、运输损毁或经核验的商品自身故障，属于商家承担退回运费的情形。客户主观不想要、颜色不合适或重复购买，属于本人原因，不得套用商家承担规则。
12. 客户询问到付时，应先确认是否存在客服提供的到付账号或到付单号。没有这条记录时，只能说明尚未生成到付安排，不能把政策允许误写成已经完成。
13. 已现场组装且出现使用磨损的家具不属于完好无理由退货。尺寸错误、安装不当和商品自身缺陷应分别记录事实，仍可转人工核验，不能因家具已组装就全面否定所有售后问题。
14. 礼品收件人可以协助描述商品和故障，但退货发起、身份确认和退款账户仍由下单人负责。仅有礼品卡号或收件地址不能确认申请人就是下单人。
15. 退货保仅覆盖符合条件的普通官网小件。所有商城订单、大件家电、家具、合约设备以及本人原因退货均不适用，不能根据支付方式或会员等级扩大范围。
16. 退货前置条件、渠道适用范围和费用承担是三组独立判断。窗口尚未结束、包装已拆或商品已经激活，都不能单独证明全部退货条件成立。
17. 合理检查允许客户打开商品查看安全状态，但不得改变商品功能、完成长期使用或进行非官方拆修。照片只记录可见状态，后台仍可要求补充其他核验材料。
18. 查询结果与客户描述不一致时，应分别列出订单字段、客户补充事实和待核验项。客服不能只选对结论有利的一条事实，也不能用订单预计时间替代签收或验收时间。
19. 客户询问退货进度时，应按申请、材料、核验、审批、出款和到账依次说明。每一步只引用该系统实际返回的记录，不能把上一步完成当作下一步也完成。
20. 退回商品的实际取件和查验由物流与仓库分别记录。客服看到已预约取件时，不能回答仓库已经验收；看到仓库已收货时，也不能推定退款已经批准。
21. 商品故障所需照片、外观照片和问题描述分别服务于不同核验目的。缺其中一项时，建议补交对应材料，不应要求与退款无关的支付密码、短信验证码或账号登录凭据。
22. 对同一订单的多个商品，应分别引用商品名称、行项目和金额。订单总计只能说明整单成交金额，不能作为某一商品已获批准退款的金额证据。
23. 申请窗口与审批期限不能混写。自然日窗口回答“何时还能申请”，工作日时效回答“发出后的核查时点”，二者都必须在订单自身日期事实明确时才能套用。
24. 客服提到运费、检测费、保证金或补偿时，应说明是否有订单、商品页或有效政策明确金额。没有明确金额就只登记待核验项，不采用推定值。
25. 客户等级影响人工队列目标时，必须从会员或企业资料中读取依据。普通客户、大会员和优先队列的时限不同，不能凭客户自述升级队列。
26. 当客服只具备 READ 权限时，可以查询订单、退款状态和政策并提供下一步建议；不能创建工单、修改退款或向客户表示 WRITE 动作已经完成。
27. 状态说明应先引用本单状态事实，再引用政策的定义和例外。任何缺据、冲突或未知结果都需明确保留，处理意见可限定在可核验范围内。
28. 最终答复至少携带一条直接支持决定性政策事实的原文引用。引用 ID 合法不等于语义支持，若原文只出现状态词而缺少限制或公式，不能证明完整规则。

## 退货操作的状态链

一项退货申请依次涉及申请登记、材料补齐、窗口核验、资格核验、审批决定、退款指令、支付结算和客户到账。每一步都有不同证据，后一步的状态不能倒推前一步，前一步完成也不代表后一步已经发生。客服在回答“能否退”“何时到账”或“运费谁出”之前，应先确认客户问的是哪一种处理意见，再从订单查询取得本单事实，最后选择适用政策。仅凭“已签收”无法同时回答窗口、物品状态、审批和到账。

申请窗口与物品条件必须同时满足。官网普通小件自实际签收日次日起七个自然日内可以申请无理由退款，普通商品还要求商品本体完好、随机配件和安全标签齐全。业务时间落在窗口内，只说明尚可提交申请；订单没有物品状态、配件状态或安全标签信息时，客服仍不能直接确认符合无理由退货条件。允许为查看商品进行不改变功能状态的合理检查，不表示客户可以完成长期使用、进行非官方拆修或改变商品价值。客服可以说明已经满足的时间事实，并把物品条件列为待核验项。

包装要求需按渠道分别理解。官网普通小件的拆除外包装不当然导致资格消灭，关键仍是本体、随机安全配件和防拆标识完整；商城普通商品走快速退款则要求外包装完整，已拆除外包装的应转人工。这里的“转人工”表示常规快速路径不再自动适用，并不等于一般售后资格已经自动消失。客服不能把官网包装口径套到商城，也不能把拆开外包装写成商品本体已损坏。渠道应先从订单查询读取，支付渠道不参与决定售后政策。

运费承担要与退货原因匹配。消费者主观不想要、颜色不合适或重复购买属于本人原因，原则上由消费者承担非质量问题的退回运费；商家错发、运输损毁或经核验的商品自身故障，由商家承担退回运费。客户一句“有问题”不能替代核验，客服也不能在未核验前承诺到付账号已经生成。政策允许商家承担某类运费，与物流取件是否已安排、到付单号是否已提供是两件事。遇到费用承担规则互相矛盾时，应保留冲突并转人工，不能按检索顺序任选一条。

大件家电和家具需要把验收入户与运输破损分开。大件运输破损要同时提供外包装、机身破损部位和物流面单照片，缺少一项时只能继续补件或核验。家具已经现场组装并出现使用磨损时，不属于完好无理由退货；尺寸错误、安装不当与商品自身缺陷分别记录，可以另转人工核验。不能因为商品价值较高、客户等级较高或照片数量较多，就省略渠道、商品类别和验收时间等适用范围条件。

礼品订单的身份链需要额外核对。下单人必须发起退货并确认退款账户，礼品收件人可以协助描述商品问题，但不能利用礼品卡号或收件地址代替订单归属。若申请人不是下单人，或缺少礼品收件人城市，客服可以说明所需补正，而不能直接批准退款或指定收款账户。身份材料只用于订单核验，不应要求与退款无关的支付密码、短信验证码或账号登录凭据。

退货保也有明确范围。它只覆盖符合条件的普通官网小件，第三方商城、大件家电、家具、合约设备以及本人原因退货均不适用。客户持有退货保或订单显示购买过服务，不等于本次退回运费自动覆盖。客服应核对本单渠道、商品类型和退货原因三项，再说明保障是否可能适用；条件不完整时只能列待核验项，不能凭支付方式或会员身份扩大范围。

金额信息必须来自具体记录。退回运费、检测费、二次包装费、取件费、维修报价和保证金分别有不同含义，不能从订单总额直接推算。系统字段为空时，可以说记录未提供该金额，并转人工查询；不能报零、报市场常见价或使用比例估算。退款金额也要区分申请额、批准额和实际结算额。若批准记录存在但三个金额都为空，客服不能把订单总额说成已退款金额；若只有申请额，也不能说支付渠道已按该金额结算。

商品故障材料应按目的分组。基础申请先核对订单号、申请原因和可接收通知的手机号；故障核验再核对故障照片或短视频、商品外观照片和问题描述；序列化设备还须机身序列号照片。分组是为了解释每类材料证明什么，不代表可以选组提交。基础、故障和专项材料应一并核对，不能因分别记在不同章节而省略必要材料。

最终答复应形成可复核的积木：本单渠道与商品、实际签收或验收时间、业务时钟、窗口规则、完好与配件条件、材料缺项、审批与执行状态、支付结算状态、可以建议的下一步。每一块只写已读取事实或已引用政策，未读取的字段明确写为缺失。这样可以避免把“在窗口内”误写成“已批准”，把“建议转人工”误写成“已接管”，也不会用一个看似完整的政策摘录掩盖本单事实仍不完整。

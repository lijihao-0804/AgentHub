# 256 与 2,048 输出 token 的预注册对照

主线基准 `deb28ec77fa85a9cf2c888dd46d59a8360efa189`。本次检验输出上限能否恢复已确认的截断，同时保留有依据的回答和正确拒答。模型固定为项目北京工作空间的 `deepseek-v4.1-flash-1017`，温度 0，保持原有思考设置、消息序列、证据、引文格式和纠正条件。2,048 取自项目已配置路由。既有 256 限制来自创建实验模型档案的代码。

1. 历史组完整纳入上次 fresh 的 57 个有回执的 HTTP 502；空正文 39 行、截断 JSON 18 行。分别保留原两种检索方案送出的证据，每行重测两种上限，交替先后顺序。报告行数、不同题数和不同输入数。每组分别以所有原失败行为分母，报告首次可解析、最终 HTTP 200 及语义严格正确的比例。另报本次 256 再次失败而 2,048 恢复的配对分母。
2. 新独立组包括 40 道从未调用过的双语小样本，英中各 20 题，分别含 10 道可答题与 10 道应拒题。另从公开 MuSiQue TRAIN 中选取未曝光双跳来源，冻结 14 道可答、7 道移除末跳的应拒对照。单列短、长样本。二者均先用真实上传、入库、BGE-M3、稀疏召回、Qdrant 和重排冻结正式问答入口下的选段。每种上限都从首个模型请求开始。历史与新题的付费请求都经过实际问答路由和生产网关，固定检索结果，以消除两次检索的偶然差异；延迟不包含已冻结的检索计算。
3. 保护组包括上次各阶段严格正确输入的并集与 214 道历史默认对照，按精确消息去重。W13、R092、B006 的不同证据版本单列，两个上限重新配对。其余保护题运行 2,048，比较已归档的同输入正确阶段，未确立旧正确性的题单列。过往不同提示的结果不得冒充同输入对照。
4. 首答取第一次物理回复，终态取 HTTP 最终实际交付。失败保留在正确率分母。严格正确要求答对要点、语言匹配且引文共同支持答案；正确拒答要求该题应拒、明确拒答且无引文。引文支持率分母为实际作出实质回答的有效回复，另列数值分子、分母。盲评只展示题目、金标、输出与它引用的实际原文。相同评分材料可复用既有人工式审阅记录，其他由独立代理审阅。两种 cap 均报告端到端 P50/P95、逻辑问答数、供应商调用数、纠正次数、用量与按回执时间核算的费用。
5. 合并门槛为两类失败的最终结构恢复均有净增，新独立样本严格首答或最终正确数有净增，两个新样本组及受保护的已正确阶段无正确转错，已正确拒答和受支持答案均无退步。缺失回执、不完整对照或保护回归失败时保留现有默认值。无论门槛结果如何，报告结构恢复和语义恢复各自的实测值。
6. 沿用总额 30 元。历史已确认 2.04767472 元、保留 0.049062 元，本轮可用 27.90326328 元。每次实际发送前按北京高峰价预留，验证回执的模型、唯一 ID 和用量后按峰谷费率结算。串行执行，未知结果封账停止，禁止重发先前不确定请求。只公开汇总与脱敏的行级判分，不上传凭据、回执正文、第三方语料或数据库。回执计价不能确认含优惠的最终发票金额。[官方费率](https://help.aliyun.com/zh/model-studio/deepseek-v4-1-flash)

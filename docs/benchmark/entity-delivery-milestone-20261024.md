# 论文实体答案交付契约：开发切片登记草案

本里程碑实施模型/数据集实体问题的显式交付契约，承接答案路径诊断。先做隔离原型，真实调用通过现有网关与ContextBudgetPolicy。只在完成来源审阅、冻结协议后调用；没有新公开API、默认reader或通用语义保证。

设计依据仍是已核查的PaperQA读取/回答/完成职责区分与RAGFlow实际可见来源登记；本轮不以其成绩作对标，不再添加其他检索架构。

两组都给相同问题、同样的显式任务类型、同一份真实原文包，都输出实体短值和可选说明。基线也是实体列表，避免把新方案的收益混同于仅缩短答案。候选另提供逐实体逐字来源，以及ANSWERED/PARTIAL/INSUFFICIENT/NEEDS_CLARIFICATION状态与缺失项。

基线JSON：`{"answer_values":["name"],"explanation":"","unanswerable":false,"cited_source_ids":["id"]}`。

候选JSON：`{"status":"ANSWERED","entities":[{"value":"name","supports":[{"source_id":"id","quote":"exact source text"}]}],"explanation":"","missing":[],"clarification":null}`。

候选ANSWERED需实体且无缺口；PARTIAL需实体和缺口；INSUFFICIENT需无实体、有缺口；NEEDS_CLARIFICATION需无实体和明确澄清问题。实体必须在其逐字引文中以完整名称出现；引文必须属于当前实际可见来源。此验证只约束格式、来源归属和逐字名称，不证明实体与所问关系成立，也不证明已穷尽所有实体。说明与模型状态不当作可信裁判或概率。

计划从已有QASPER TRAIN缓存按问题文本规则选14个候选，每篇最多一题，固定顺序；排除此前两批生成问答的论文。选择不读旧答案、F1或人工标签；随后原文审阅产生明确实体别名、关系、相关干扰材料与删除条件，争议和超预算均保留台账。不是新holdout或正式Experiment。

每个活动题两种材料条件（完整、移除目标实体支持但保留相关背景）与两组输出契约。若不足8个来源明确的活动题则不开始付费批次；不因答案或评分不佳换题、续跑、调提示。全部预定失败/无效/未完成保留分母。

共同指标为实体集合精确匹配、实体P/R/F1、值字段原始EM/token F1、完整材料拒答与缺据材料错误完整交付；PARTIAL、澄清、格式错误、可见来源/逐字引文约束单列。原参考文本、值与说明分开保存，不能把新实体分数与旧自由文本F1直接比较。实体别名标注是机器辅助来源复核，不声称专家语义准确率；不采用自评或未校准模型裁判总分。

固定Magpie `auto/deepseek-v4.1-flash`（保留原阿里云备用，但一旦接管停止后续诊断派发），temperature=0、thinking disabled、每次最多1024输出tokens；每个来源包最多8000 UTF-8保守预算单位，禁止静默截断后仍称完整。每个请求一次派发，备用/未知传输/错误原始模型立即停止；不重试。

本轮只验证交付契约；有界补读留到来源支持、答案关系和缺口记录通过验证之后。推广需要实体值、关系支持、错误交付与成本同时成立；小开发切片不能自动修改生产默认。最终活动题、调用计划、验收规则和源代码将在运行前另存冻结协议。

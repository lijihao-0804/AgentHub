## 2. 分项详解

### A. 工具调用与多轮交互

#### 1) τ-bench ✅
Sierra ｜ 2024-06-17 ｜ [arXiv:2406.12045](https://arxiv.org/abs/2406.12045) ｜ [sierra-research/tau-bench](https://github.com/sierra-research/tau-bench)（**1,485 stars**，GitHub API 2026-10-31 ✅）

- **能力**：agent ↔ **LLM 模拟用户** ↔ 域内 API 的三方多轮交互，强制遵守域策略（如退改签规则）。
- **环境**：airline / retail 两个模拟业务域，用户由 LLM 扮演（默认 gpt-4o），可切换 `llm / react / verify / reflection` 四种用户模拟策略。
- **判分**：**确定性**——比对会话结束时的数据库终态，而非文本相似度。这是它相对同期工作的核心优势。
- **指标**：`pass^k` = 同一任务重复 k 次**全部成功**的概率。README 榜单显示 airline 上最强配置 Pass^1=0.460 但 **Pass^4 仅 0.225**（✅ 直接读到 README 表格）。
- **争议**：`pass^k` 是**可靠性**指标而非能力上限，k 越大越惩罚方差；用 Pass^1 汇报会系统性高估线上可用性。此外用户模拟器本身是 LLM，其"不配合/过度配合"会污染分数。
- **成本**：README 明言 "τ-bench might be expensive to run"，官方提供 `historical_trajectories` 供复用（✅）。
- **⚠️ 重要状态变更**：README 顶部已加警告——**原仓库任务不再更新**，官方指向 **τ³-bench**（新增 `banking` 域、`voice` 语音模态，并修复 airline/retail 任务缺陷），README 更新于 2026-03-18（✅ 读到警告文本）。
- **启示**：企业平台应把"**终态断言 + 重复 k 次**"作为默认回归口径；单次跑分的波动会被误读成模型升级收益。

#### 2) τ²-bench ✅
Sierra ｜ 2025-06-09 ｜ [arXiv:2506.07982](https://arxiv.org/abs/2506.07982)

- **能力**：**双控（dual-control）**——用户和 agent 都能调用工具改同一份世界状态（技术支持场景）。
- **环境**：Telecom 域建模为 **Dec-POMDP**；**组合式任务生成器**由原子组件程序化生成可验证任务，保证域覆盖与复杂度可控；用户模拟器被工具与可观测状态约束，提升保真度。
- **指标**：除成功率外，做了**错误归因消融**——分离"推理错误"与"沟通/协调错误"（✅ 摘要明确）。
- **发现**：从 no-user 切到 dual-control 时性能显著下降。
- **启示**：真实企业工单里"用户也在操作系统"是常态（如 HR 自助改单、运维共管控制台）。只测单控环境的分数不可迁移。

#### 3) AgentBench ✅
清华 THUDM ｜ 2023-08-07（v3 2025-10-04）｜ ICLR 2024 ｜ [arXiv:2308.03688](https://arxiv.org/abs/2308.03688) ｜ [THUDM/AgentBench](https://github.com/THUDM/AgentBench)（约 **3.8k stars**，shields.io ✅）

- **能力**：8 个异构环境（OS、DB、知识图谱、卡牌、解谜、家居、网购、网页）综合考察推理与决策。
- **判分**：混合式，各环境自定义。
- **结论**：失败主因是**长程推理、决策、指令遵循**薄弱；代码训练对不同 agent 任务影响**不一致**（✅ 摘要）。
- **启示**：作为"能力横截面体检"仍有价值，但**不可作为企业选型主指标**——环境抽象度太高。

#### 4) BFCL（Berkeley Function Calling Leaderboard）❌
Berkeley Gorilla ｜ 2024-02（v1）❌ ｜ 无 arXiv（榜单 + 博客）｜ [ShishirPatil/gorilla](https://github.com/ShishirPatil/gorilla)（约 **13k stars**，shields.io ✅）

- **能力**：函数/工具调用的**语法正确性**——工具选择、schema 遵循、参数正确性；含 single-turn、parallel、irrelevance（该不该调用）、multi-turn 子集。
- **判分**：AST 匹配 + 可执行性检查（**确定性**），比 LLM judge 稳定。
- **规模/版本**：v1→v3（多轮）→v4（Web Search、Memory 等 agentic 子项）——**版本细节 ❌ 未核实**。
- **争议**：单轮 AST 匹配会奖励"格式对但语义错"；multi-turn 子集仍是**静态脚本**，不产生真实副作用。
- **启示**：这是**上线前的准入门槛**（工具 schema 设计是否可被模型正确使用），不是能力上限指标。企业自建工具集必须跑一遍自有 schema 的 BFCL 风格用例。

#### 5) MCP-Universe ✅
Salesforce ｜ 2025-08-20 ｜ [arXiv:2508.14704](https://arxiv.org/abs/2508.14704) ｜ [SalesforceAIResearch/MCP-Universe](https://github.com/SalesforceAIResearch/MCP-Universe)（**603 stars**，shields.io ✅）

- **能力**：在**真实 MCP server** 上做长程任务，考察"陌生工具空间"下的探索与长上下文管理。
- **环境**：6 域 / **11 个真实 MCP server**（位置导航、仓库管理、金融分析、3D 设计、浏览器自动化、网页搜索）。
- **判分**：三类 execution-based evaluator——格式合规、静态内容匹配、**动态 evaluator 实时抓取 ground truth**（应对时效性任务）✅。
- **结果**：GPT-5 43.72%、Grok-4 33.33%、Claude-4.0-Sonnet 29.44%（✅ 摘要）。**企业级 agent（Cursor）并不优于朴素 ReAct**。
- **争议**：动态 evaluator 引入外部依赖，**可复现性弱于静态基准**；真实 server 会漂移，历史分数不可直接比较。
- **启示**：这是目前**最接近企业 MCP 工具生态**的公开基准；其"未知工具"挑战正是企业内部工具文档不全的真实写照。

#### 6) MCP-Bench ✅
2025-08-28 ｜ [arXiv:2508.20453](https://arxiv.org/abs/2508.20453)

- **规模**：**28 个 live MCP server / 250 个工具**，覆盖金融、旅行、科学计算、学术检索（✅）。
- **能力**：从**模糊指令**中自行检索工具（不给工具名）、多跳轨迹规划、以中间工具输出为依据、跨域编排。
- **判分**：三层——工具级（schema 理解与用法）、轨迹级（规划）、任务完成度。**含 LLM judge 成分**。
- **启示**：把"工具检索"与"工具调用"分开计分，对企业平台很有用：这两件事的失败修复路径完全不同（前者是检索/描述质量问题，后者是编排问题）。

#### 7) AppWorld ✅
Stony Brook ｜ 2024-07-26 ｜ ACL'24 ｜ [arXiv:2407.18901](https://arxiv.org/abs/2407.18901)

- **能力**：面向**交互式代码生成** agent——不是发一次 API，而是写带复杂控制流的代码，边执行边修正。
- **环境**：可控的 App 世界（笔记、消息、购物等），通过 API 操作；含模拟"人"的社交数据。
- **判分**：状态断言（确定性）。
- **规模**：9 个 App / 457 API / 750 任务 —— **❌ 未核实**（摘要被截断）。
- **启示**：企业里"跨系统编排"本质是写代码而非点按钮；AppWorld 的形态比纯 tool-calling 基准更贴近 RPA 替代场景。

#### 8) WorkArena ✅
ServiceNow ｜ 2024-03-12 ｜ [arXiv:2403.07718](https://arxiv.org/abs/2403.07718)

- **能力**：知识工作者在**企业软件**（ServiceNow）里完成日常工单类任务。
- **环境**：远程托管的 ServiceNow 实例；同时开源 **BrowserGym** 环境框架（✅ 摘要）。
- **规模**：**33 个任务**（✅）。后续 WorkArena++ 规模更大 —— ❌ 未核实。
- **判分**：平台状态断言。
- **争议**：任务数偏少、单一 SaaS 平台，易被针对性优化。
- **启示**：**"企业软件 + 状态断言"是被验证可行的范式**；自建内部评测时可直接复用 BrowserGym 抽象。

#### 9) TheAgentCompany ✅
CMU 等 ｜ 2024-12-18（v3 2025-09-10）｜ [arXiv:2412.14161](https://arxiv.org/abs/2412.14161)

- **能力**：数字员工——浏览网页、写代码、跑程序、**与"同事"沟通**。
- **环境**：自包含的"小软件公司"（内部站点 + 数据 + 协作工具），完全离线可控。
- **规模**：最强 agent 自主完成 **30%** 任务（✅ 摘要）。任务数 ❌ 未核实。
- **判分**：多检查点断言。
- **启示**：**"组织仿真"**是长程任务评测的正确抽象——任务跨越多人协作与交接，单 agent 单轮基准测不出来。

### B. Web 与 Computer-Use

#### 10) WebArena ✅
CMU 等 ｜ 2023-07-25 ｜ [arXiv:2307.13854](https://arxiv.org/abs/2307.13854) ｜ [web-arena-x/webarena](https://github.com/web-arena-x/webarena)（**1,640 stars**，GitHub API ✅）

- **环境**：**自托管**四个真实开源系统——电商、社交论坛、GitLab、CMS，另配地图与手册等知识库。自托管是它可复现的关键。
- **判分**：**功能正确性**（终态断言），非文本匹配。
- **基线**：最佳 GPT-4 agent **14.41%** vs 人类 **78.24%**（✅ 摘要）。
- **规模**：812 任务 ❌ 未核实。
- **争议**：环境搭建极重（多容器 + 账号种子数据）；后续工作指出部分任务断言过严/过松。
- **启示**：**"自托管 + 终态断言"是企业内网评测的唯一可复制路径**——公网基准无法进内网，且会漂移。

#### 11) VisualWebArena ✅
2024-01-24 ｜ ACL 2024 ｜ [arXiv:2401.13649](https://arxiv.org/abs/2401.13649)

- **能力**：**视觉接地**的 Web 任务（图像分类、看截图找商品等），文本-only agent 系统性失效。
- **规模**：910 个视觉接地任务 ⚠️（来自 ACL 论文 PDF 搜索摘要，未直读原文）。
- **判分**：同 WebArena 的功能正确性 + 视觉产物校验。
- **启示**：只要企业系统里有图表/看板/PDF 渲染，纯 DOM 文本 agent 就会掉分；需要视觉回归用例。

#### 12) WebVoyager ✅
2024-01-25 ｜ ACL 2024 ｜ [arXiv:2401.13919](https://arxiv.org/abs/2401.13919) ｜ [MinorJerry/WebVoyager](https://github.com/MinorJerry/WebVoyager)（**1.1k stars**，shields.io ✅）

- **环境**：**15 个真实线上网站**（不是沙箱）。
- **判分**：**GPT-4V 做 judge**，与人类判断一致率 **85.3%**（✅ 摘要）；WebVoyager agent 成功率 59.1%。
- **争议**：**这是最典型的"不可复现基准"**——线上站点改版即失效；judge 与被测模型同源（GPT-4V 评 GPT-4V agent）存在自我偏好；85.3% 一致率意味着 ~15% 噪声，足以颠倒榜单中段。
- **启示**：可作为**探索性 smoke test**，绝不能作为验收口径。

#### 13) OSWorld ✅
xlang-ai ｜ 2024-04-11 ｜ NeurIPS 2024 ｜ [arXiv:2404.07972](https://arxiv.org/abs/2404.07972) ｜ [xlang-ai/OSWorld](https://github.com/xlang-ai/OSWorld)（**3,247 stars**，GitHub API ✅）

- **环境**：**真实虚拟机**（Ubuntu / Windows / macOS），任意应用，非 API 抽象。
- **规模**：**369 个任务**（✅），每个含初始状态配置 + **专属 execution-based 评测脚本**。
- **基线**：人类 **72.36%**，最佳模型 **12.24%**（✅）。
- **判分**：确定性脚本（读文件、查 DB、查 UI 状态），可靠性高。
- **成本**：需 GPU/VM 编排，单次全量评测以小时计（❌ 具体数字未核实）。
- **争议**：脚本对"合法的等价路径"敏感（用户用别的方式达成同一状态可能判负）；后续 OSWorld-Verified 修订了部分任务 ❌ 未核实。
- **启示**：**"每任务一个断言脚本"是可维护性与真实性的最佳折中**；企业平台应把 evaluator 当成一等公民资产来版本管理（对应本仓库 ADR-010 的 dataset/evaluator 版本绑定）。

#### 14) WindowsAgentArena ✅
Microsoft ｜ 2024-09-12 ｜ [arXiv:2409.08264](https://arxiv.org/abs/2409.08264) ｜ [microsoft/WindowsAgentArena](https://github.com/microsoft/WindowsAgentArena)（**915 stars**，shields.io ✅）

- **环境**：真实 Windows OS，复用 OSWorld 框架。
- **规模**：**150+ 任务**（✅）。
- **工程亮点**：**可在 Azure 上并行，全量评测最快 20 分钟**（✅ 摘要）——这是被低估的贡献。
- **基线**：Navi agent 19.5% vs 无辅助人类 74.5%（✅）。
- **启示**：**评测吞吐是设计约束**。企业平台若不能把全量回归压到"一杯咖啡时间"，团队就不会在每次发版前跑。

#### 15) AssistantBench ✅
Tel Aviv / Princeton ｜ 2024-07-22 ｜ [arXiv:2407.15711](https://arxiv.org/abs/2407.15711)

- **规模**：**214 个**真实、耗时的开放 Web 任务（✅），可自动评测。
- **结果**：无模型超过 **26 分**；SOTA web agent 接近 0 分（✅）。
- **启示**：开放式任务的自动评分仍是瓶颈；"可自动评测"这一约束本身就把任务难度上限压低了。

#### 16) BrowseComp ✅
OpenAI ｜ 2025-04-16 ｜ [arXiv:2504.12516](https://arxiv.org/abs/2504.12516)

- **规模**：**1,266 题**（✅），要求持续多跳检索"难以找到、相互纠缠"的信息。
- **判分**：**短答案 + 精确匹配**（✅），刻意规避长答案评分难题。
- **定位**：作者自述类比"编程竞赛之于 coding agent"——不完整但有用（✅）。
- **争议**：答案可被记忆/泄漏；精确匹配对同义表述不友好；题目分布偏离真实用户查询（作者自己承认）。
- **启示**：**"短答案 + 精确匹配"是低成本高可靠的可验证设计**，企业内部 FAQ/数据核对类评测可直接借用。

### C. 软件工程与终端

#### 17) SWE-bench ✅ / SWE-bench Verified ✅ / SWE-bench Multimodal ✅
Princeton & Stanford ｜ 2023-10-10 ｜ ICLR 2024 Oral ｜ [arXiv:2310.06770](https://arxiv.org/abs/2310.06770) ｜ [SWE-bench/SWE-bench](https://github.com/SWE-bench/SWE-bench)（**6,129 stars**，GitHub API ✅）

- **能力**：给仓库 + issue，产出 patch 修复。
- **判分**：**Fail-to-Pass 单元测试**（确定性），Docker 容器化（2024-06-27 起）✅。
- **Verified**：与 OpenAI Preparedness 合作，**500 道经真实工程师确认可解**的子集（README 2024-08-13 条目 ✅）。
- **Multimodal**：**617 实例 / 17 个 JS 库**，每题至少含一张图；SWE-agent 12% vs 次优 6%（✅ arXiv:2410.03859，ICLR 2025）。README 显示 **Multimodal v2 已于 2026-09-01 开源，480 任务可本地评测**（✅）。
- **指标**：`%resolved`（通过全部 F2P 与 P2P 测试的实例占比）。
- **争议**：
  - ⚠️ 有独立分析称约 **1/3 的 issue 评论里已含解法**（来自搜索结果转述，未核实）；
  - ⚠️ arXiv:2503.15223 报告 **>15% 的 Verified 实例测试补丁不完整**，错误/部分解也能通过（仅搜索结果，未核实）；
  - 训练数据污染几乎无法排除（仓库是公开的、issue 早于模型 cutoff）。
- **成本**：README 明确要求 **≥120GB 磁盘、16GB RAM、8 核**，且**结果按 `run_id`+`instance_id` 缓存**——换 patch 必须换 run_id，否则静默复用旧结果（✅ 读到该警告，这是一个真实踩坑点）。
- **启示**：**"测试即规格"是 agent 评测里最强的判分形式**。企业平台应把内部回归用例写成 F2P/P2P 式断言，并**为 evaluator 版本单独打版本号**；同时必须做"evaluator 自身有效性"抽检（用已知错误解验证它会失败）。

#### 18) Terminal-Bench 2.0 ✅
Stanford / Laude Institute / Anthropic 等 ｜ 2026-01-17 ｜ [arXiv:2601.11868](https://arxiv.org/abs/2601.11868) ｜ [laude-institute/terminal-bench](https://github.com/laude-institute/terminal-bench)（约 **2.6k stars**，shields.io ✅）

- **环境**：**89 个**终端任务，**每题独立环境 + 人工编写参考解 + 完整测试**（✅）。
- **结果**：前沿模型/agent **均低于 65%**（✅）。
- **定位**：作者明确指出既有基准"要么不真实、要么不够难"（✅）。
- **争议**：题量小（89）导致置信区间宽；终端任务与"企业 agent 平台"的重叠度取决于是否做 DevOps/SRE 场景。
- **启示**：**"每题独立环境 + 参考解 + 测试"三件套**是 2026 年的新默认；比"一个共享沙箱跑所有题"可靠得多，也便于并行。

### D. 科研 / ML 工程 / 分析型

#### 19) MLE-bench ✅
OpenAI ｜ 2024-10-09（ICLR 版 v6 2025-02-26）｜ [arXiv:2410.07095](https://arxiv.org/abs/2410.07095)

- **规模**：**75 个 Kaggle 竞赛**（✅），含人类奖牌基线。
- **判分**：对比 Kaggle 奖牌阈值（确定性，但阈值本身是人为切分）。
- **结果**：o1-preview + AIDE 脚手架在 **16.9%** 竞赛达到铜牌水平（✅）。
- **亮点**：专门研究了**预训练污染**与资源 scaling（✅ 摘要）。
- **启示**：**"资源预算"必须写进协议**——同一模型给 10 倍算力分数会变，不声明预算的对比无意义。

#### 20) CORE-Bench ✅
Princeton 等 ｜ 2024-09-17 ｜ [arXiv:2409.11363](https://arxiv.org/abs/2409.11363)

- **规模**：**270 任务 / 90 篇论文 / 3 学科**（CS、社科、医学），3 个难度级，含语言与视觉语言任务（✅）。
- **能力**：**计算可复现性**——用给定代码与数据复现论文结果。
- **判分**：结果数值比对（确定性）；提供并行评测系统，比串行省数天（✅）。
- **结果**：最难档最佳仅 **21%**（✅）。
- **启示**：**"复现既有结果"是极好的企业 agent 评测母题**——有客观真值、无法靠话术蒙过、且直接对应"数据分析 agent 是否可信"。

#### 21) ScienceAgentBench ✅
Ohio State 等 ｜ 2024-10-07 ｜ ICLR 2025 ｜ [arXiv:2410.05080](https://arxiv.org/abs/2410.05080)

- **规模**：**102 任务 / 44 篇同行评审论文 / 4 学科**，9 位领域专家校验（✅）。
- **判分**：统一输出为**自包含 Python 程序**，评估程序本身 + 执行结果 + **成本**（✅ 三元指标，成本入表是亮点）。
- **结果**：最佳 agent 独立解决 **32.4%**（专家给知识后 34.3%）；o1-preview + self-debug 达 **42.2%**，但**成本 >10 倍**（✅）。
- **污染对策**：提出两种缓解策略（摘要未展开，❌ 具体方法未核实）。
- **启示**：**"准确率 / 成本"双轴汇报**应成为企业评测标准动作；只报准确率会诱导团队选最贵的模型。

#### 22) AgentBoard ✅
HKUST 等 ｜ 2024-01-24 ｜ NeurIPS 2024 Oral ｜ [arXiv:2401.13178](https://arxiv.org/abs/2401.13178)

- **贡献**：**细粒度 progress rate**——不只判最终成败，还量化"推进了多少"，配合部分可观测 + 多轮交互。
- **规模**：9 类任务 / 1,013 环境 ❌ 未核实。
- **启示**：**长程任务必须报"进度"而非二元成败**，否则分数全挤在 0 附近，失去区分度。

### E. 通用助理 / 经济价值

#### 23) GAIA ✅
Meta / HuggingFace 等 ｜ 2023-11-21 ｜ [arXiv:2311.12983](https://arxiv.org/abs/2311.12983)

- **规模**：**466 题**，其中 **300 题答案保留**用于榜单（✅）。
- **能力**：推理 + 多模态 + 网页浏览 + 工具使用的组合。
- **基线**：人类 **92%** vs GPT-4+插件 **15%**（✅）。
- **判分**：短答案精确匹配。
- **争议**：**答案泄漏是长期问题**（300 题 holdout 缓解但未根治）；题目风格偏"找事实"，与企业任务分布差异大。
- **启示**：**holdout 分集是低成本防污染手段**，企业内评测应区分"开发集/保留集"，且保留集**只在发版评审时消费一次**（对应本仓库 ADR-010 与规则 28）。

#### 24) GDPval ✅
OpenAI ｜ 2025-10-05 ｜ [arXiv:2510.04374](https://arxiv.org/abs/2510.04374)

- **规模**：覆盖美国 BLS 工作活动，**44 个职业 / 9 个对 GDP 贡献最大的行业**；开源 **220 题 gold 子集** + 公开自动评分服务（✅）。
- **判分**：专家构建任务 + 交付物质量评分（**LLM/自动评分 + 专家校准**），非确定性断言。
- **结论**：前沿模型表现随时间**近似线性提升**；最佳模型交付质量"接近行业专家"；配合人类监督可比专家**更便宜更快**（✅）。
- **争议**：交付物质量评分主观性高；"接近专家"的结论对评分 rubric 高度敏感；职业覆盖是美国中心。
- **启示**：**"经济价值"叙事会主导 2026 的企业采购话术**。技术团队应准备"质量分 + 成本 + 人工复核工时"三元指标来对冲这类营销口径。

### F. 元评测

#### 25) HAL（Holistic Agent Leaderboard）✅
Princeton 等 ｜ 2025-10-13 ｜ [arXiv:2510.11977](https://arxiv.org/abs/2510.11977)

- **贡献**：标准化 harness，**跨数百 VM 并行**，把评测从"数周"压到"数小时"，并消除常见实现 bug（✅）。
- **规模**：**21,730 次 agent rollout / 9 模型 × 9 基准**（coding、web、science、客服），**总成本约 $40,000**（✅）→ **约 $1.84/rollout**（本报告据其公开数字推算）。
- **关键发现**：
  - **提高 reasoning effort 在多数运行中反而降低准确率**（✅）；
  - 用 LLM 辅助日志审查发现**未被报告的行为**：agent 去 HuggingFace **搜索基准答案**而不是解题；订票任务中**滥用信用卡**（✅）。
- **启示**：这是**最值得企业团队直接抄的工程资产**。两个结论直接改变设计：①"更用力思考"不是免费收益，需按任务类型开/关；②**必须审日志**，分数背后的行为可能完全不是你想要的（对应本仓库"trace 内容 opt-in + 脱敏"规则 21）。

### G. 安全

#### 26) AgentDojo ✅
ETH Zurich 等 ｜ 2024-06-19 ｜ [arXiv:2406.13352](https://arxiv.org/abs/2406.13352)

- **规模**：**97 个真实任务 + 629 个安全测试用例**（✅），覆盖邮件、网银、旅行预订。
- **定位**：**不是静态测试集，而是可扩展环境**，用于设计新任务、防御与**自适应攻击**（✅）。
- **发现**：SOTA 模型在**无攻击时**也大量失败；现有注入攻击"破坏部分安全属性但非全部"（✅）。
- **启示**：安全评测要**与功能评测同环境同任务**跑，否则测不出"为了完成任务而放松安全"的权衡。

#### 27) InjecAgent ✅
Penn State 等 ｜ 2024-03-05 ｜ ACL 2024 Findings ｜ [arXiv:2403.02691](https://arxiv.org/abs/2403.02691)

- **规模**：**1,054 用例 / 17 个用户工具 / 62 个攻击者工具**（✅）；攻击意图分"直接伤害用户"与"窃取隐私数据"。
- **结果**：30 个 agent 中，ReAct-prompted GPT-4 **24% 被攻破**；加"黑客提示"后攻击成功率**近乎翻倍**（✅）。
- **争议**：静态用例，攻击模板固定，易被针对性防御过拟合。
- **启示**：**"工具返回值是不可信输入"必须成为平台级不变量**（对应本仓库规则 19/12：外部内容不得直接驱动副作用，副作用不确定必须转 UNKNOWN_OUTCOME）。

#### 28) AgentHarm ✅
UK AI Safety Institute 等 ｜ 2024-10-11 ｜ ICLR 2025 ｜ [arXiv:2410.09024](https://arxiv.org/abs/2410.09024)

- **规模**：**110 个恶意 agent 任务（含增强共 440）**，**11 类危害**（欺诈、网络犯罪、骚扰等）✅。
- **指标**：**双指标**——是否拒绝 + 越狱后是否**仍保持多步任务能力**（✅）。第二项是关键：只测"拒绝率"会奖励"变傻"。
- **发现**：前沿模型**未被越狱时就相当配合**恶意请求；通用越狱模板可迁移到 agent（✅）。
- **启示**：安全评测必须**同时报告"有用性"与"无害性"**，否则模型厂商有动机用过度拒答刷分。

## 3. 2025–2026 的六条趋势

1. **从"问答"到"长程 + 有状态"**。判分对象从答案字符串转为世界终态。任务时长与检查点数量在上升，单轮基准的区分度在坍塌。

2. **Computer-use 是主战场，工程重心是"并行 VM"**。WindowsAgentArena 的"20 分钟全量"（✅）与 HAL 的"数百 VM 并行"（✅）说明：**评测吞吐已是基准设计的一等约束**。

3. **MCP 生态催生新一代工具基准**。考点从"能否正确调用给定函数"移到"**在陌生、庞大、会漂移的工具空间里找到并组合工具**"。MCP-Universe 给出反直觉结论：**企业级 agent 产品（Cursor）并不优于朴素 ReAct**（✅）。

4. **成本与方差进入指标本体**。ScienceAgentBench 把成本列入三元指标（✅）；HAL 用 $40k / 21,730 rollout 让"每次评测多少钱"可比（✅）；`pass^k` 把方差变成一等公民（✅）。

5. **元评测（meta-evaluation）兴起**。HAL 表明大量已发表分数受 harness 实现 bug 影响（✅）——**跨论文比分数本身可疑，同 harness 内比较才有意义**。

6. **可靠性优先于峰值能力**。HAL 的"提高 reasoning effort 多数情况下降低准确率"（✅）与 τ-bench 的 Pass^4 断崖（✅）共同说明：峰值能力与稳定交付存在系统性落差，采购应看后者。

## 4. 污染（contamination）与 holdout 在 agent 评测中的特殊形态

公开基准的污染讨论已很充分，但 **agent 评测的污染有三条独有路径**，比静态 QA 严重得多：

**(a) 环境内泄漏（in-environment leakage）**
最直接的证据来自 HAL：agent 在解题过程中**去 HuggingFace 搜索基准本身**而不是解题（✅ 已核实）。静态 QA 基准里模型只能"记住"，agent 可以**主动检索答案**。这对企业内评测同样成立——如果评测数据集放在 agent 可访问的存储里，agent 会去读它。

**(b) 测试即规格（tests as spec）导致的 evaluator 过拟合**
SWE-bench 类基准的判分逻辑是公开的，agent 可以直接读测试文件反推期望行为。⚠️ 有分析称 >15% 的 Verified 实例测试补丁不完整，错误解可通过（仅搜索摘要，未核实）。**结论不依赖该数字**：只要测试可见，过拟合就是理性策略。

**(c) 时间性与环境漂移**
WebVoyager 用真实线上站点（✅），MCP-Universe 用 live server 与动态 ground truth（✅）——这类基准**天然不可复现**，"污染"与"环境变更"无法区分，历史分数不可纵向比较。

**已知的缓解手段（及其实证强度）**

| 手段 | 代表 | 强度 |
| --- | --- | --- |
| 答案 holdout 分集 | GAIA 保留 300 题答案（✅） | 中：题目仍公开 |
| 训练数据去污染 + 发布时间切分 | MLE-bench 专门分析预训练污染（✅） | 中 |
| 未公开的私有测试集 | 企业自建（第 5 节） | 高，但难以对外证明 |
| 程序化任务生成 | τ²-bench 组合式生成器（✅） | 高：可无限生成新实例 |
| 明确声明并量化污染影响 | ScienceAgentBench 提出两种缓解策略（✅，方法 ❌ 未核实） | 中 |
| 审日志而非只看分数 | HAL LLM-aided log inspection（✅） | 高：能发现"作弊"这类分数看不见的行为 |

**对企业的直接含义**：把 holdout 当**审计事件**而非"另一个文件夹"。本仓库规则 28（"Holdout 暴露是可审计的持久化事件；开发运行不得消耗 holdout 暴露"）正是对这一点的正确工程化——公开基准社区目前普遍**没有**做到这一层。

## 5. 企业私有场景的 agent 评测：公开方法论缺口与本报告建议

**先说结论**：截至本次调研，**没有找到系统性的、可引用的"企业私有场景 agent 评测方法论"公开文献**。现有公开材料分三类，都不构成方法论：
- 基准论文的"如何构造任务"章节（如 TheAgentCompany 的自包含公司仿真 ✅、τ²-bench 的组合式生成器 ✅）——可迁移的是**构造手法**，不是**组织流程**；
- 评测 harness 工程（HAL ✅、BrowserGym ✅、SWE-bench 的 Docker harness ✅）——可迁移的是**基础设施**；
- 厂商博客与框架文档——❌ 未核实，且利益相关。

**本报告综合建议（推断，非引用）**：企业私有评测应建成"**四层金字塔**"，每层用不同的判分强度：

| 层 | 内容 | 判分 | 频率 | 规模 |
| --- | --- | --- | --- | --- |
| L1 工具契约层 | 自有工具 schema 的 BFCL 式用例：该调/不该调/参数正确/并行 | AST + 可执行（确定性） | 每次工具变更 | 数百 |
| L2 任务回归层 | 真实工单回放，每任务一个终态断言脚本（OSWorld/SWE-bench 范式） | 确定性断言 | 每次发版 | 数十–数百 |
| L3 长程场景层 | 跨系统、多检查点、含人工审批介入的端到端场景 | 检查点断言 + 进度率（AgentBoard 范式） | 每周/里程碑 | 10–30 |
| L4 质量与成本层 | 交付物质量（GDPval 范式）+ token/美元成本 + 人工复核工时 | LLM judge + 人工校准抽样 | 每月 | 20–50 |

**四条不可妥协的工程约束**（直接对应本仓库已有 ADR）：

1. **evaluator 与 dataset 同等版本化**。判分脚本变了，历史分数就不可比。→ ADR-010。
2. **每次运行必须绑定**：代码 commit、resolved spec、知识快照、数据集版本、pricing 快照、evaluator 版本。→ 规则 18/25。
3. **holdout 是审计事件**，开发运行不得消费。→ 规则 28。
4. **报告必须含方差**：同一任务重复 k 次报 `pass^k`（τ-bench 范式），而非单次均值。

**最容易犯的三个错**：
- 用 LLM judge 做主验收（WebVoyager 的 85.3% 一致率意味着 15% 噪声，✅）；
- 只测"成功路径"，不测"该拒绝时是否拒绝"（AgentHarm 的双指标 ✅ 是最好的模板）；
- 评测环境与生产环境的工具描述不一致——那测的是另一个系统。

## 6. Top 10 必读清单

按"对做企业级 agent 平台的团队的实际杠杆"排序，而非按引用量：

1. **HAL**（[arXiv:2510.11977](https://arxiv.org/abs/2510.11977)）— 唯一把"评测工程 + 成本 + 作弊行为"讲透的元评测。**先读这篇**。
2. **τ-bench**（[arXiv:2406.12045](https://arxiv.org/abs/2406.12045)）— `pass^k` 与终态断言的范式来源；注意已迁移到 τ³-bench。
3. **SWE-bench**（[arXiv:2310.06770](https://arxiv.org/abs/2310.06770)）+ Verified 报告 — "测试即规格"的最强实现，也暴露了 evaluator 有效性风险。
4. **OSWorld**（[arXiv:2404.07972](https://arxiv.org/abs/2404.07972)）— 每任务断言脚本 + 真实 VM 的工业标准。
5. **Terminal-Bench 2.0**（[arXiv:2601.11868](https://arxiv.org/abs/2601.11868)）— 2026 年的新默认：独立环境 + 参考解 + 测试。
6. **MCP-Universe**（[arXiv:2508.14704](https://arxiv.org/abs/2508.14704)）— 最贴近企业 MCP 工具生态，且诚实报告了"企业产品不如 ReAct"。
7. **TheAgentCompany**（[arXiv:2412.14161](https://arxiv.org/abs/2412.14161)）— 组织仿真的最佳范例，长程任务评测的模板。
8. **AgentDojo**（[arXiv:2406.13352](https://arxiv.org/abs/2406.13352)）— 安全与功能同环境评测的正确做法。
9. **AgentHarm**（[arXiv:2410.09024](https://arxiv.org/abs/2410.09024)）— "拒绝率 + 能力保持"双指标，防止用变傻换安全。
10. **GDPval**（[arXiv:2510.04374](https://arxiv.org/abs/2510.04374)）— 不是技术最佳，但会主导采购话术；必须知道它的评分口径与弱点。

**次选（按需）**：AgentBoard（进度率）、ScienceAgentBench（成本入指标）、CORE-Bench（复现母题）、MCP-Bench（工具检索 vs 调用分离）、GAIA（holdout 设计）。

## 7. Benchmark 选型决策树（草稿）

```
你这次评测要回答什么问题？
│
├─ Q1「模型/工具 schema 能不能被正确调用？」
│   └─ 静态、便宜、高频 → BFCL 式 AST 判分
│      • 用自有工具集重写用例，不要用公开榜单分数
│      • 必含 irrelevance 子集（该不调时是否忍住）
│
├─ Q2「端到端任务能不能做成？」
│   ├─ 有确定性终态？（DB/文件/工单状态）
│   │   └─ 是 → WebArena / WorkArena / OSWorld 范式
│   │       每题一个断言脚本；能并行 → 参照 WindowsAgentArena
│   └─ 否（开放交付物：文档、PPT、分析报告）
│       └─ GDPval 范式：rubric + LLM judge + 人工校准抽样
│          ⚠️ judge 一致率必须实测，<90% 不可作验收
│
├─ Q3「长程、跨系统、含人工审批？」
│   └─ TheAgentCompany 范式：组织仿真 + 多检查点
│      • 报 progress rate，不报二元成败
│      • 必须包含"审批中断-恢复"路径
│
├─ Q4「稳定性够不够上生产？」
│   └─ 同任务重复 k 次 → pass^k（τ-bench）
│      ⚠️ 只报 Pass^1 等于隐藏方差
│
├─ Q5「工具空间大、陌生、会漂移？」
│   └─ MCP-Universe / MCP-Bench 范式
│      • 分开计分：工具检索 vs 参数正确 vs 轨迹规划
│      • 动态 ground truth 会牺牲可复现性，需接受
│
├─ Q6「安全边界在哪？」
│   └─ AgentDojo（功能+攻击同环境）
│      + AgentHarm（拒绝率 + 能力保持双指标）
│      ⚠️ 单独跑安全套件测不出"为完成任务而放松安全"
│
└─ Q7「评测本身可信吗？」
    └─ 三查：
       ① 用已知错误解跑一遍，evaluator 必须判负
       ② 抽样审日志（HAL 范式），查"搜答案""乱用凭证"
       ③ 成本与方差是否入表
```

**一句话总结**：2026 年选基准的关键分歧不在"哪个榜单更权威"，而在**"你的判分是确定性的还是 judge 的"**与**"你的任务是否有真实世界终态"**。凡是两者都弱的基准（真实网站 + LLM judge，如 WebVoyager），只能做探索，不能做验收。

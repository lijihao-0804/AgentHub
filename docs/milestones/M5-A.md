## State model

Approval decision and action execution are persisted as independent dimensions:

| Decision | Execution |
| --- | --- |
| `PENDING`, `APPROVED`, `DENIED`, `EXPIRED`, `CANCELLED` | `NOT_STARTED`, `CLAIMED`, `SUCCEEDED`, `FAILED`, `UNKNOWN_OUTCOME` |

`logical_action_id` is deterministic over the tenant, Run, published tool revision, canonical
argument hash, and proposal ordinal. It never uses a provider-generated `tool_call_id`.

Before an Approval is created, arguments are JSON-Schema validated, recursively checked for
server-owned fields, canonicalized, and hashed. Resume executes the persisted canonical
arguments; it does not trust arguments regenerated by a replayed model call.

## Action execution and safety semantics

M5-A implements only the internal transactional `create_ticket` WRITE action. Its idempotency key
is the persisted logical action identity and the database has a tenant-scoped uniqueness
constraint. Concurrent claims have one winner, and a committed result is reused on replay.

`UNKNOWN_OUTCOME` means the external side effect cannot be confirmed. It preserves
`decision_status=APPROVED`, sets the Run to `NEEDS_ATTENTION`, and is never automatically retried.
Approval decisions and action execution emit safe AuditLog/RunStep projections; raw arguments,
credentials, provider exceptions, and action payloads are excluded.

The runtime emits provider-neutral `approval.wait` and `approval.execute` spans with only safe
workspace/Run/Approval/action identity, status, latency, and failure-code attributes.

`DENIED` and `EXPIRED` remain Approval decision-only outcomes; they are not AgentRun statuses.
The Run may complete according to the graph after a denied/expired action observation, while
`UNKNOWN_OUTCOME` continues to map to `NEEDS_ATTENTION`.

## Checkpoint ownership and durability boundary

AgentHub business tables are owned by Alembic migration `0012_m5_approval_runtime`. LangGraph
PostgreSQL checkpoint tables are framework-owned in the `langgraph_checkpoint` schema and are
created only by the explicit bootstrap command:

```powershell
uv run --locked python -m scripts.bootstrap_langgraph_checkpoint --database-url <database-url>
```

The stable checkpoint identity is tenant-safe and binds `workspace_id` to `run_id`. The accepted
durability guarantee is **durable approval resume**: a Run in `WAITING_APPROVAL` can survive page
refresh, browser close, API/runtime restart, and a later decision, then resume the same Run.
This does not claim token-level durable streaming, SSE replay, or exactly-once semantics for
arbitrary external actions.

## Crash-window recovery evidence

The M5-A PostgreSQL integration suite covers the required windows:

1. Action commit before graph resume: a persisted `SUCCEEDED` execution is consumed after
   recovery and the action executor is not called again; the ticket count remains one.
2. Approval exists without a checkpoint: reconciliation is explicit and fail-closed as
   `NEEDS_ATTENTION / APPROVAL_CHECKPOINT_MISSING`; repeating reconciliation is idempotent and
   does not create another Approval.
3. Checkpoint exists while the Run is still `RUNNING`: reconciliation restores
   `WAITING_APPROVAL`; repeating reconciliation leaves the durable state unchanged.

Additional integration coverage includes concurrent claim, effectively-once ticket creation,
double/resume replay, unknown outcome, waiting cancellation, expiry, and developer approval
authorization. The main approved flow creates one ticket, resumes the original `AgentRun.id`,
and completes after a newly instantiated runtime service.

## Evaluation

The independent deterministic M5 dataset is
`benchmarks/approval_runtime/dataset.json` (`m5-approval-runtime-v1`, 20 cases: 14 dev and
6 holdout). It covers approval required/denied/approved, duplicate approval, multi-step action,
self-approval-denial fixtures, restart/resume, idempotent action, unknown outcome, cancel race,
and crash recovery. The fixture covers the denial branch; production authorization blocks
self-approval except for organization OWNER/ADMIN roles. The dataset uses no public LLM and
records its canonical dataset hash and metrics in
`benchmarks/approval_runtime/results/m5-approval-runtime-v1.json`.

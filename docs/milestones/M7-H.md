## Deterministic conformance chain

The formal run uses real PostgreSQL and the existing persisted services:

`Dataset → Experiment → ExperimentRunner → Metrics → Comparison → Ablation → Release Gate`

The deterministic driver emits typed observations for all seven formal categories. It is an
offline conformance fixture, not an LLM quality score and not a claim of 100% model accuracy.

The acceptance artifact is generated by:

```powershell
python -m benchmarks.evaluation.dataset_builder --check
python -m benchmarks.evaluation.runner --database-url $env:AGENTHUB_TEST_DATABASE_URL --output benchmarks/evaluation/results/m7-unified-conformance-<sha>.json
```

The exact-head GitHub Actions backend job generates and uploads the conformance artifact from
its real PostgreSQL service. The artifact name is `m7-unified-conformance-<commit-sha>`; the
workflow does not hard-code an Actions run number.

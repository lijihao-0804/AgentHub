# AgentHub 生成侧优化执行计划（R-09/R-10 落地：gold 天花板拆解与定向修复）

- 背景：交付链修复后，全链路最大剩余损失在生成侧——gold 证据对照臂 F1 62.8% vs 当前真实路径 41.4%（最新抽样口径 43.3%），约 21pp 差距发生在"证据完美送达之后"。本计划三步：**第 0 步零调用拆解 37 分损失 → 第 1 步打最大桶 → 第 2 步复测收口**。
- 依据：[实验全面归因](AgentHub-RAG实验全面归因-失败层定位-0730a94.md)（剩余空间排序）、[负结果法证复核](AgentHub-RAG负结果法证复核-0730a94.md)（GLM 词面差 83% 来自 2 道极性题格式不服从）、[修改进度与收益复核](AgentHub-RAG修改进度与收益复核-42215c8.md)（gold 臂数字）、answer-path 三条件诊断（充分材料拒答 1/8、删材料不拒答 4/8）。
- 纪律：沿用[总执行计划](AgentHub-RAG召回立项执行计划-96587c3.md) §0/§1（预注册协议先行、门槛模板、提交需批准、四件套、环境事实）；**抽样纪律（用户指示）：一切模型调用默认 100 题≈200 次调用，可降至 50 题≈100 次，禁全量 400**；唯一升级路径（结果边缘时加抽至 200 题≈400）须预登记并先报用户。
- 基线：`72a34a8`（分支 `codex/rag-root-cause-20261024`）。自包含，执行进程无需对话上下文。

## 0. 五桶假设（第 0 步要验证的对象）

gold 臂丢掉的 ~37 分，按既有诊断证据假设由五桶构成（ proportions 未知，第 0 步定案）：

| 桶 | 定义 | 既有证据 |
| --- | --- | --- |
| R 拒答校准 | 证据充分却拒答 | answer-path：充分材料拒答 1/8 |
| F 格式不服从 | 极性/事实正确但带解释、措辞膨胀 | GLM 差 83% 来自 2 极性题 |
| G 粒度失配 | 事实正确、多了规模/单位细节被词面扣分 | SQuAD 题附带规模 F1 下降案例 |
| E 真实阅读错误 | 关系读反、实体混淆 | MAML 案例（引用合法但关系不被支持） |
| S 评分口径 | 答案语义正确但未命中参考别名/措辞 | 上游 SQuAD 口径已知损耗 |

**诚实边界（写死在协议里）**：S 桶不可回收也不应回收；F/G 桶的"修复"只在**事实型短答案任务**（citation QA、MuSiQue 型）中是改进，在需要解释的生产场景可能是退步——因此所有干预先落在 benchmark/实验臂，生产接入提案必须带"适用任务类型"边界，禁止全局压词。

## 1. 第 0 步：拆解审计（0 次 API，第 1-2 天）

### GEN-0 协议

`results/generation-audit-<日期>/protocol.json` 预注册：数据=已冻结的 gold_budgeted 200 题答案（`benchmarks/public_rag/results/consumer-rag-20261023/confirmation-answers-1/`，含逐题预测与参考答案；可加 development-answers-1 的 gold 臂 160 题做复核集）；分类规则（下述五桶的确定性判据）；输出=逐题标签+桶占比+双侧示例；0 调用。

### GEN-0 实现

- 扩展现有 `benchmarks/public_rag/reader_value_audit.py` 框架（勿新造口径）：
  - **R 桶**：预测为拒答标记（unanswerable/拒答话术）且参考答案非空；
  - **F 桶**：极性题（参考为 yes/no 类）预测以正确极性开头但含多余论述；或预测长度 >> 参考且核心词面本可全中——判据必须**确定性**（如：正确答案 token 全部命中预测、但预测 token 数 ≥ 参考 3 倍）；
  - **G 桶**：参考答案 token 是预测的子集（预测包含正确答案+额外细节）且 F1 < 1；
  - **S 桶**：人工/规则可判的别名未命中（预测与参考同义但 token 交集低）——此桶判据允许标 UNKNOWN 并单列，**不得强行归桶**；
  - **E 桶**：其余（默认桶，报告中须给出双侧示例佐证，不得让 E 成为垃圾场——若 E 占比 >40% 须抽 20 题人工复核再定案）。
- 判据优先级：R > F > G > S > E（一题只进一个桶，判据冲突取先匹配）。
- 单测：每桶至少 2 个构造样例的分类断言。

### GEN-0 停止条件（写进协议，触发即收口）

- **S+UNKNOWN 合计 ≥ 50%**：损失大头是评分口径，生成侧真实可回收空间 <10pp → 本计划降级为"拒答校准单项"（仍按 GEN-1 走 R 桶路径）或直接关闭，写负结果/测量报告；
- 所有桶占比 <10%（无主桶）：关闭"打最大桶"策略，报告留档，交用户重排。

### GEN-0 产出

`generation-audit-report.json` + 五桶占比表 + 每桶 3 个双侧示例；**报告需同时给出"可回收上界估计"**（= R+F+G+E 中可机械修复部分的粗上界，如 F/G 全收、R 半收、E 不计）。

## 2. 第 1 步：打最大桶（≤200 次调用，第 3-4 天）

按 GEN-0 的最大桶走对应路径（**只走一条**，不并行多桶）：

### 路径 A：F+G 最大（结构化输出约束）

- benchmark 臂实现：答案提示改造为结构化输出——极性题锁枚举（yes/no/not_found）、事实题锁 `{"value":…,"unit":…}` 字段、"evidence_sufficient" 独立布尔（后判答）；沿用仓库 `response_schema` 通道语义，但**在实验臂的提示/schema 层实现**，不动生产 citation_qa（生产提案留到收口）。
- 预注册门槛：目标桶指标（F/G 占比折算的 F1 损失）回收 ≥50% 且 MuSiQue F1 ≥ +4pp 且 CI 下界 >0；R/E 桶不恶化；调用 ≤200。

### 路径 B：R 最大（拒答校准）

- 干预："evidence_sufficient" 前置判断字段 + 提示显式规则；**考卷**用已冻结的删证据条件（`results/rag-root-cause-20261024/reader-models-1/` 的 removed 条件 8 题 + 从确认集再抽 20 题做删证据变体，纯本地构造删法：移除 gold 段落之一后重新组消息，不需要检索）。
- 门槛：删证据条件正确拒答率 ≥75%（当前 50%）且充分条件拒答率 ≤5%（当前 ~12.5%）；F1 不降；调用 ≤200（考卷复用冻结消息，仅新增判断调用的 A/B）。

### 路径 C：E 最大（阅读能力）

- 仅在此桶 >40% 时启动：单次派发、身份校验、无 fallback 的模型路由对照（沿用 reader-isolation 纪律：身份不符/用量未知立即停）；门槛：gold 臂 F1 ≥ +5pp 且 CI 下界 >0。**成本最高，GEN-0 不过 40% 线不得启动。**
- A/B 用 gold 臂消息（已冻结）+ 候选模型，100 题≈200 调用。

### 通用停止条件

任一路径门槛未达 → 该路径负结果收口，**不换参数重试、不顺延到下一桶**（要换桶须新协议并报用户）。

## 3. 第 2 步：复测收口（≤200 次调用，第 5 天）

- 路径成功后：合并干预跑 100 题 A/B（before=当前生产默认消息，after=干预臂消息；抽样纪律同前）；门槛：F1 ≥ +3pp 且 CI 下界 >0、桶指标回收保持、无其他桶恶化。
- 产出：实施报告（含**生产接入提案**：干预落在哪些任务类型、citation_qa/schema 改动点、版本 opt-in 方案、"不适用解释型场景"边界声明）+ 索引更新 + 四件套。
- 未达 → 负结果收口，生产不接。

## 4. 排期与汇报

```
第 1-2 天  GEN-0 协议+实现+单测 → 五桶拆解报告（0 调用）→ 停止条件判定
第 3-4 天  GEN-1 对应路径实现+预注册 A/B（≤200 调用）→ 门槛判定
第 5 天    GEN-2 合并复测（≤200 调用）→ 报告/提案/四件套 → 请求提交批准
```

- 每天一行进度（完成/停止/花费）；总调用预算 ≤400（两步各 200），超限即停报用户。
- 预算内 0 调用也可走完第 0 步并产出决策依据——**第 0 步单独就有交付价值**。

## 6. 明确不做

不动检索/交付/预算层（刚修复完，四件套与重放基线不得回归）；不动生产 citation_qa/schema（收口后提案另批）；不优化 S 桶（评分口径不改）；不在生产全局压答案长度（F/G 修复限事实型短答案任务）。

# AgentHub RAG 场景优化验收（2026-10-23）

本轮把已下载的 QASPER 和 MuSiQue 真正用于检索实验，两个冻结方法都通过独立开发划分上的确认及预先声明的整体质量目标。收益主要来自减少上下文输出截断，不是换模型、堆 Agent 循环或反复扫参数。生产代码增加可选的证据字节预算；下面的公开数据成绩仍属于离线场景检索，不冒充业务接口或最终回答成绩。

## 结果与评分口径

| 确认任务 | 有效评分题数 | 证据段落召回：基线 → 优化 | 完整证据集：基线 → 优化 | 主指标成对增益及 95% 区间 |
|---|---:|---:|---:|---|
| QASPER，指定论文内找证据 | 854 / 全部采集 1005 | 62.24% → **84.39%** | 55.27% → **78.69%** | 召回 +22.16 个百分点，[+19.79, +24.64] |
| MuSiQue-Ans，给定候选含干扰段落 | 300 / 300 | 73.97% → **91.11%** | 45.00% → **76.33%** | 完整支持集 +31.33 个百分点，[+25.44, +37.72] |

QASPER 确认用官方 dev 全部 281 篇论文，275 个有效论文组；60 个不可回答问题、91 个无法完整对齐证据的问题均保留，分别披露但不塞入可评分证据分母。指标取多个合法标注证据集合中的最佳召回，完整集为至少一个集合的所有段落 ID 命中。它不证明段落的全部支持文字都进入上下文。更严格的“原段落 ≥90% 字符覆盖”代理从 54.21% 到 77.97%，仍不是精确 support span。

MuSiQue 确认是预先确定种子的官方 dev 300 题样本，不是全部 2417 题，不测未提供答案的 test。保留每题全部干扰候选；同一支持原文复用的题目合并成 173 个重采样组。这里只测支持段落齐备，不测分解或生成推理是否正确。

两个确认均按原组做 5000 次成对 bootstrap，确认前冻结方法，确认后不重选。预先暂定的工程目标为 QASPER 召回 ≥80%、完整集 ≥65%；MuSiQue 召回 ≥85%、完整集 ≥70%，本轮整体通过。它们不是通用行业标准，也不是每个子场景的保障。机器记录见 [acceptance.json](../../benchmarks/public_rag/results/scenario-rag-20261023/acceptance.json)。

## 机制选择及优秀项目的启示

延续前两份分析，参考的是实际项目的阶段划分和代码机制，源码依据及固定引用见[项目对照](AgentHub-RAG优秀项目对照与下一轮方案-20261022.md)和[场景分析](AgentHub-RAG场景化评估与改进方向-20261023.md)：

- RAGFlow 的候选、重排、输出预算分离，以及 Haystack 的融合与来源多样性用于定位阶段损失；之前预算/配额实验的负结果继续保留，不宣布所有场景都应启用配额。
- LangChain ParentDocumentRetriever 区分检索粒度和回答上下文粒度。本轮 QASPER 测了标题路径、同章节邻段扩展与按 BGE 排名填充；**邻段扩展弱于填充**，没有把“先进项目使用过”当作自动采用理由。
- Onyx 的来源选择单独作为有成本的候选机制。本轮额外做了 QASPER train-only 来源选择，增益不确定，**未采用**，也没有追加确认追调。

QASPER 开发集为 train 中预定 80 篇的全部 235 题，202 题可评分，74 个论文组。四个有限机制而非参数网格：

| 开发机制 | QASPER 证据召回 | QASPER 完整集 |
|---|---:|---:|
| 原文块，固定前 5 锚块 | 54.38% | 45.54% |
| 标题/章节路径，固定前 5 锚块 | 57.84% | 50.50% |
| 标题/章节路径，在预算内继续填充已重排块 | **77.04%** | **69.31%** |
| 标题/章节路径，锚块加同章节邻段 | 63.84% | 56.44% |

三次开发比较使用 98.333% 聚类区间；填充相对基线 +22.66 个百分点，区间 [+15.78, +30.02]。标题路径单独增益区间跨零，不能拆出一个确定的独立标题收益。

MuSiQue 开发为 train 160 题 / 3200 候选段落，2/3/4 跳各 112/35/13；不对互不相邻的文档做邻段扩展。固定前 5、标题前 5、标题预算填充的完整集依次为 54.38%、61.88%、80.63%。两次开发比较用 97.5% 区间，填充增益区间 [+18.24, +34.59] 个百分点；随后冻结同名 profile。不同数据集的协议、作用域、主指标和参数记录分别保存，即使当前最优数值相同也不合并为全局默认。

额外 QASPER API 探索在读取原确认聚合成绩前登记：固定 `deepseek-v4.1-flash-1017`、235 次请求全部有效，观测 645,420 tokens；增量请求均值约 921ms。相对填充仅 +2.47 个百分点，99% 区间 [-1.51,+6.70] 跨零。额外成本门槛在调用后、聚合评分前明确，故视为探索而非预注册确认；这不改变原冻结方法，也不宣称 API 成本已值得。无价格快照，不换算金额。

## 为什么有效，剩余损失在哪里

以下是已暴露确认结果上的描述诊断，不再用来选择本次方法。只看段落 ID 能否齐备，不把它当作严格文字覆盖上限。

| 场景与方法 | 完整支持在候选池中已缺失 | 候选池齐备但输出选择后缺失 | 最终齐备 |
|---|---:|---:|---:|
| QASPER 基线 | 149 | 233 | 472 |
| QASPER 填充 | 135 | **47** | 672 |
| MuSiQue 基线 | 21 | 144 | 135 |
| MuSiQue 填充 | 21 | **50** | 229 |

这说明本轮主要修复“已经召回，却在输出时丢掉”的损失。QASPER 优化后余下 182 个不齐备问题中，135 个在候选池阶段就不齐备；继续调输出预算无法补回不存在的证据。

MuSiQue 分层后并不均衡：

| 跳数 | 题数 | 支持召回：基线 → 填充 | 完整支持集：基线 → 填充 |
|---|---:|---:|---:|
| 2 | 140 | 80.00% → 96.07% | 62.86% → 92.14% |
| 3 | 110 | 74.24% → 92.12% | 39.09% → 77.27% |
| 4 | 50 | 56.50% → 75.00% | 8.00% → **30.00%** |

分层只做描述，不新增显著性或重新定门槛。四跳仍弱，不能声称已解决复杂多跳。下一质量里程碑应在新的开发实验中比较桥接证据选择/有界迭代检索，并先测完整链与最终答案；不拿已暴露的这 300 题继续扫参数。

## 成本、实现与应用边界

两臂上限均 8000 bytes，但实际输入不相等：QASPER 平均 3509 → 7874 bytes、段落 4.81 → 11.83；MuSiQue 3396 → 7854 bytes、段落 4.86 → 11.77。标注 precision 分别从 18.57% → 12.40%、40.03% → 21.75%。标注可能不穷尽所有相关段落，但更多输入和潜在噪声是实际代价。未评生成答案、faithfulness、P95 或价格，不宣称整体加速或等 token 成本收益。

新增可选 `context_budget_bytes` 已贯通 RetrievalQuery、知识 API、Agent 配置/发布、search_knowledge 和观测。严格整数 2..64000，`None` 保留旧路径且不向旧冻结规格添加新键。租户/快照水合、BGE 排序与相关性下限之后，按完整 RetrievedEvidence JSON 记录算字节，跳过超大记录并尝试后续候选，`final_top_k` 仍为数量上限。原有 `selection` trace 仍是重排输入阶段，新预算统计仅包含数字。

实际可试的 playground 覆盖值见[分场景预设](../../benchmarks/public_rag/scenario-presets-20261023.json)：`candidate_top_k=20`、`rerank_top_k=20`、`final_top_k=20`、`context_budget_bytes=8000`，还需真实授权知识库/快照 ID。这是预算填充入口，**不会自动建立指定论文范围或标题结构**，也不覆盖生产 relevance floor。完整 prompt 仍须通过 ContextBudgetPolicy。

工具默认 5、最大 10、snippet 最大 1000 字符不变，因此不能把本轮平均约 12 段的公开结果直接套给日常 Agent 回答。生产完整 DTO 的元数据开销也不同于 benchmark 的小记录。本轮未改业务索引、数据库快照、已发布版本或全局默认；Onyx 生产选择器仍未接入。

评测复用生产 BGE-M3 / BGE-reranker-v2-m3 与 ContextBudgetPolicy；在指定 paper/case 内用精确向量分数排除 ANN 变量，没有声称复刻 SQL/Qdrant 的整条业务路径。共享生产选择函数回放 QASPER 2010、MuSiQue 600 个已记录上下文，ID 与字节数全部一致；它是兼容性回放，不是新独立确认。

集成审查修正了预算选择前的旧数量截断，以及观测中指向不存在字段的来源映射。最终 19 项定向行为测试通过（1.12s、exit0），覆盖超大记录后续补位、非重排路径、UTF-8 实际字节、权限与 floor 顺序、显式 None 和旧配置；先前相关既有测试 56 项通过，共享选择器 26 项通过。主代理最终源码 Ruff 与差异检查通过。没有运行 GPU/API/数据库单元测试，也没有增加字段位置之类只复述实现的检查或哈希测试。记录见[integration-validation.json](../../benchmarks/public_rag/results/scenario-rag-20261023/integration-validation.json)。

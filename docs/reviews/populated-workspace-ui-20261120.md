## 真实操作发现的缺陷

- 多个标签共享同一个轮换 Cookie。并发刷新会触发服务端的重复使用检测，导致正常打开的页面被送回登录。前端现在串行化支持 Web Locks 的同源标签刷新，并合并同页并发请求。用一个登录连续两轮同时打开三个页面，六次刷新全部返回 200。没有 Web Locks 时仅合并同页请求。
- 已发布的检索配置含有 `retrieval_strategy`，应用派生草稿的 API 曾拒绝该字段。现有三种策略均通过发布配置到 PATCH 的往返验证。
- 工具固定修订后可以重新选择最新。MCP 导入会使用表单当前显示的默认值。文档上传缺文件时有直接反馈，修订上传后可看到新摘要。
- 待审批运行可以从调试台取消。客户端按实际权限显示知识、工具、模型和成员的写操作。权限加载失败时依然可以阅读有权查看的数据。创建工作区按目标组织的成员角色判断。
- 智能体和数据集的版本详情曾生成两个没有页面的中间路径，触发预取 404。面包屑现只链接到可达的父页面。浏览器分别验证版本对比返回智能体、数据集版本返回数据集、评测运行返回所属实验；另验证数据尚在加载时返回实验列表。

## 复测与范围

前端回归入口为 `node scripts/test_web_regressions.cjs`。跨标签测试使用 `node scripts/test_web_review.cjs --auth-tabs <web-origin> <local-account-file>`，需要真实测试账号、Edge 和 Playwright。历史导航通过只读账号检查。批准、删除、发布、创建正式实验等操作使用独立工作区的一次性对象，并核对真实 API 或数据库结果。

会话生成使用本机固定应答，评测使用确定性驱动。MCP 默认配置的浏览器测试拦截了 MCP 请求，服务端导入另用进程内 MCP 服务和 PostgreSQL 验证。付费模型调用为零。本次覆盖可达页面与记录所呈现的操作，未穷举第三方故障、浏览器版本和所有参数组合。

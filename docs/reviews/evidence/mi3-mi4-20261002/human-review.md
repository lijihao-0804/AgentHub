# 真实模型输出人工抽检表

样本：DEV 草稿 v1 的基线与候选各 10 条。这里只审核答案与用户目标是否一致，业务表状态另看报告。

请为每项填写 `人工判定：通过 / 不通过 / 无法判断`，并填写审阅者。保持空白意味着未知，助手不得代填为真人审阅。

## live-pilot.json / refund-multi_hop

用户轮次：退款申请在办理前有什么要求？能否直接说已办好？

参考答案：先人工审核，只能登记处理工单，不能声称已完成办理。

模型输出：

退款申请的处理要求如下（依据虚构测试政策）：

1. **处理窗口**：30 天。
2. **办理前必须人工审核**。
3. **客服权限**：客服只能登记处理工单，不能承诺已经完成办理。
4. **创建工单前置条件**：必须先查询客户，并取得人工审批；审批被拒绝则不得创建工单。
5. **费用**：该政策未说明是否收费，因此不能推测，也不能借用其他政策的费用规则。

关于“能否直接说已办好”：**不能**。客服只能登记待处理工单，登记不代表完成办理，也不能声称或承诺已经办好。

如果您需要登记退款工单，请提供客户编号，我会先查询客户，再按流程申请创建工单。


人工判定：________；理由：________

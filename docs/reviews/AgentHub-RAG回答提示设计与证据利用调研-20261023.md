# RAG 回答提示设计与证据利用调研

2026-10-23。范围：核对优秀项目的实际实现及相关原始研究，判断提示设计能否改善“检索到材料之后的回答”。本轮为调研；没有新答案 API 请求、提示替换、依赖安装或默认策略变更。

> 后续用户已授权并完成[单次回答提示实验](AgentHub-RAG单次回答提示实验-20261023.md)：固定160题/143组，F1仅+0.60pp、区间跨零，EM不变，缺据对照出现退步；未采用候选。原运行中断和补充未发请求分别留档，不能把这份调研建议或补充合并结果称为一次成功的原注册验收。

结论：值得做一次受控的回答提示实验，但目前没有证据承诺 AgentHub 能提高多少。优先研究单次回答中的问题目标、证据关系和答案取值约束；保留已有来源限制与缺据拒答。不要从一个明确错例推导出所有剩余错误都来自阅读，也不要把别人的微调、常识补答或选择性回答分数当成我们的提示收益。

## 1. 召回提升已经带来答案收益

[互补证据选择确认](AgentHub-RAG互补证据选择与阅读组织-20261023.md)采用来源隔离的 MuSiQue dev 200 题、134 个共享原文组；相同问题、答案提示、模型、原文格式和预算：

| 指标 | 基线 | 互补选材后 |
|---|---:|---:|
| 支持段落召回 | 82.58% | 90.67% |
| 完整支持段落集 | 63.50% | 80.00% |
| 答案 token F1 | 36.34% | 52.49% |
| 答案完全匹配 EM | 29.00% | 45.00% |

F1 增加 16.15 个百分点，分组配对 95% 区间为 [+10.16, +22.82]。这支持已验收的选材组合有效；不能单独归因于选择提示的某一句话。F1 是词面重合指标，不能直接称为事实正确率。完整段落集达到 80% 而 EM 为 45%，也不能据此认定两者相减就是可由提示修复的错误比例。

这里存在三个不同条件：标注段落命中；实际送进模型的文本足以回答；模型按题目要求正确使用文本。段落 ID、答案字面出现，都不能替代第二、第三项。

设 S 为“最终可见文本在语义上充分”、A 为“答案正确”，则：

`P(A) = P(S) × P(A|S) + P(非S) × P(A|非S)`。

这是概率分解，不是拟合结果。召回主要影响可用证据，提示主要可能影响条件下的回答行为；多送干扰材料、裁剪关键句或误解关系，也可能使后者变差。无充分证据仍答对，可能依赖模型记忆，不能自动算有来源支持的成功。

这一划分有直接研究依据：[Sufficient Context 的原始研究](https://research.google/pubs/sufficient-context-a-new-lens-on-retrieval-augmented-generation-systems/)区分材料不足与未利用充分材料，并研究受控拒答。其“已回答问题中正确比例”的提升，不等于固定全体问题的准确率提升。[Lost in the Middle](https://arxiv.org/abs/2307.03172)还表明相关信息的位置会影响受测模型表现；它支持关注可见上下文组织，不能证明当前 DeepSeek 有同样幅度的问题。

## 2. 实际项目有哪些可借鉴的机制

### InstructRAG：展示证据如何导向答案

实际检查：[inference.py](https://github.com/weizhepei/InstructRAG/blob/main/src/inference.py)、[data_utils.py](https://github.com/weizhepei/InstructRAG/blob/main/src/data_utils.py)、[rag.json](https://github.com/weizhepei/InstructRAG/blob/main/src/rag.json)。

项目分别提供 ICL 示例提示和 FT 微调路径。理由生成使用训练问题、材料和训练答案；ICL 将问题与理由示例加入提示，不等于每个线上问题追加一次定位调用。值得借鉴的是示范材料与结论的关联，帮助模型排除无关材料。训练答案只能用于开发示例，不能把待测题的答案或官方分解塞入推理输入。

重要差异：源码明确允许材料无帮助时依据模型常识回答，也会生成说明文字。AgentHub 的来源约束与短答接口不同，不能直接复制该提示或借用其综合提升幅度。本项目里“任务关系约束＋原接口短答”的组合仍是待验证假设。

### Context-faithful Prompting：提示确实能改变材料依从性

[原始论文](https://arxiv.org/abs/2303.11315)研究知识冲突和拒答；[knowledge_conflict.py](https://github.com/wzhouad/context-faithful-llm/blob/main/knowledge_conflict.py)实际切换普通提示、归因/叙述者提示及不同示例条件。[abstention.py](https://github.com/wzhouad/context-faithful-llm/blob/main/abstention.py)另评估缺据情形。

这是无需微调的提示干预证据。可借鉴“回答材料所支持的事实，而不是默认调用记忆”，并用缺据与冲突对照衡量。但研究模型、任务及拒答评分与当前接口不同；材料依从性提高也不能直接等同于开放问答准确率提高。我们不需要把企业材料改写成某个虚构叙述者的意见，也不照搬其跳过过长或失败样本的评测做法。

### DSPy：用明确任务和评分管理示例

检查 [BootstrapFewShot 源码](https://github.com/stanfordnlp/dspy/blob/main/dspy/teleprompt/bootstrap.py)：在训练样本上生成轨迹，配置 metric 时按评分筛选示例，再形成预测器提示。它说明示例应有来源、目标和验收依据。

这不是正确性的自动保证：未配置 metric 的代码路径可以直接接受轨迹；只用答案 F1 也不能保证证据支持。借鉴的是优化纪律，不要求引入框架或开始大规模搜索。示例的输入 tokens、离线筛选成本、训练与确认隔离都应计入。

### ALCE：任务、材料身份、示例和引用一起设计

检查 [run.py](https://github.com/princeton-nlp/ALCE/blob/main/run.py)：提示数据显式区分 instruction、document template、demonstration 和当前测试输入；文档保留标题、编号和正文。

可借鉴稳定的任务与证据接口，并分别评价答案和引用。其长回答与交互检索设置不同于我们的固定短答；材料编号合法不证明具体陈述被原文支持。无需为了模仿项目而增加交互轮次。

## 3. AgentHub 当前缺什么，已经有什么

[benchmark 回答提示](../../benchmarks/public_rag/evidence_plan_replay.py)已经明确来源限定、材料不可信、短答、缺据拒答、引用 ID 和 JSON。它有契约设计，但主要负责行为边界，没有经过提示本身的独立效果验证。它对“当前所问属性、时间和对象范围、桥接事实与最终答案的区别”缺少明确指导。

[生产 Citation QA](../../packages/knowledge/citation_qa.py)是另一套提示和结构化输出接口，要求逐项引用并使用问题语言。benchmark 的收益不能直接认定为生产长回答收益。输出不写解释也不证明模型没有推理；thinking disabled 是模型配置，不能靠文字指令等同于开启推理。

现有错误证据仍有限：[关系诊断](AgentHub-RAG问题约束与证据关系评测-20261023.md)复核了初审的 5 个关系错误，只保留一个清楚的充分材料误读；其余涉及缺事实或范围歧义，原先启动门槛未满足。[后续删除对照](AgentHub-RAG证据关系诊断集与删除对照-20261023.md)的 4 对案例中，完整材料答对 3 对，删除关键材料后均拒答；普查题把执行时期与发布年份混淆。它说明关系区分值得研究，不能估计总体可改善空间。

[两阶段定位实验](AgentHub-RAG原文定位与答案生成评测-20261023.md)的 F1 点估计增加 2.28pp，区间跨零，总输入 2.216 倍、模型流程 P95 2.983 倍，未通过验收。这个结果不支持增加通用定位调用，也不排除单次提示改善的可能。

## 4. 建议的一个有界实验

主线保持为：找齐互补材料 → 按题目要求读取原文 → 生成有来源支持的答案；提示是阅读环节的任务定义。

先比较原提示与一个任务指导候选。候选在原来的单次回答中明确：识别所问对象、关系与限定条件；区分中间事实和最终所求属性；仅用材料中支持这些条件的取值作答；缺少必要连接时保留拒答。沿用原 JSON、来源安全边界和短答案，不要求输出长推理或新增关系图。

若需要示例，再作为独立候选加入少量经核验的训练示例，最多形成两个有依据的候选；不能把“换指令”和“加示例”混成同一个不可归因改动。示例不使用已曝光确认题及其共享来源，不为普查单题写特例。此前归档的关系 reader 不因本次调研自动恢复上线。

评测建议：

1. 冻结同一批已准入的证据、顺序、问题、模型、temperature、thinking 和输出上限；检查新增指令/示例没有挤掉证据。若发生裁剪，单独记录，不能继续声称是固定材料的提示比较。
2. 当前 4 对仅用于接口与已知错误诊断；扩充来源独立、关系明确的充分/缺据样本，保留歧义和未裁决标签。它们不是已经具备总体代表性的金标。
3. 开发比较同时报告全体问题 F1、EM、充分材料下误拒答、缺据时无依据回答、有效输出率和引用支持。引用语义评分若依赖辅助模型，说明未做人类校准；ID 合法率单列。服务失败保留分母，不能算拒答成功。
4. 记录输入/输出 tokens 和模型流程延迟，示例与离线开发成本计入。选择前写明最小有用收益、风险和成本门槛，再按共享支持来源分组做配对统计；不在结果出来后改变主指标。
5. 只有开发达标，才对新来源隔离样本做一次冻结确认；历史确认题已曝光，不能重新称作盲测。无稳定收益则保留原提示，结束这一实验，不开展无上限改写。

本轮完成的是研究与下一实验设计依据。未产生新的质量分数，没有把文献结果或 4 对诊断分数写成 AgentHub 整体性能。

## 2. 目标及业务边界

目标是构建可解释、可恢复、有成本账本的上下文工程链路：识别模型实际能力 → 控制业务工作集 → 区分必须原样保留与可摘要材料 → 冻结最终请求 → 验证任务质量与成本。

长期记忆仍限定 Workspace+Agent 共享事实；Thread 历史摘要仍归属原Thread。不能因为公开数据里存在个人画像，就自动把实现改为跨用户、跨Agent的个人记忆。

固定首轮候选：

- 通用输入工作集上限64K，客服/常规分析32K，长文专用128K；K=1024。实际值必须受主备模型共同限制，不预设模型都有1M。
- 共享事实4K为首个64K候选的软份额，不改变当前条目数量、正文长度、提取策略，不强行填满、不自动扩到20%。必须权限和动作状态不受这4K示意份额约束。
- 70%软触发、85%派发前处理、55%期望目标，均以实际业务工作集为分母；这些数值是待验证候选。
- 所有新策略只对显式选择的新版本启用；旧版本解析与原快照恢复兼容。

### M2.2 预算计算与解释

对每个冻结的可执行主备模型：

```text
O_i >= max(该模型请求的max_tokens, 策略输出预留)，遵循其推理token口径
R_i = min(已确认适用的 I_i、T_i-O_i、P_i)
S_i = max(1024, ceil(0.05 * R_i))     # 候选余量，不是精确计数保证
B_i = R_i - S_i
B = min(所有可执行主备模型的 B_i)
B_work = min(B, 业务工作集上限L)
soft = (70 * B_work + 99) // 100
hard = (85 * B_work + 99) // 100
target = (55 * B_work) // 100
```

仅有运营限额P不足以证明模型能力。仅有独立输入I时，要有提供者独立输入/输出语义证据；缺少总窗口并非一概拒绝，也不能一概忽略。

输出预留不能超过已知输出上限，不重复扣推理开销。所有有效预算必须为正；bool不作为整数通过。最终输入包含系统提示、工具/schema、各角色内容及必要协议包装；计数器无法精确覆盖时明确APPROXIMATE及其适用范围。

解释结果至少包括：业务预设L、各模型有效上限及来源、输出扣除、余量、fallback限制、最终B_work、阈值、计数器状态和限制原因。使用现有版本/运行配置读路径展示必要信息；不新造管理大屏。不要只暴露孤立的“64K”掩盖实际更小值。

M2只冻结阈值并提供解释，触发扫描/分级、软配额借用和调度在M3实现，摘要调用在M4实现。

## 6. M4：可恢复摘要与有界质量实验

分成同一阶段内的先后准入工作包：先契约与离线实现，再持久化/失败注入，最后在实验准入条件齐备后执行单候选质量验证。

- 摘要含source IDs/范围/hash、parent revision、模型/prompt版本、事实/决定/冲突/未决事项/动作引用与省略原因；原文保留。摘要永远不替代数据库权威审批和外部动作状态。
- 明确job状态、唯一键、claim/ownership、源水位和CAS发布。先落盘响应后校验发布；过时结果保留实际费用，不能覆盖新revision。
- 每次请求冻结具体摘要revision及原文范围，checkpoint恢复不读“最新”。同一来源不循环压缩，失效产物不悄悄替换。
- 70%允许异步整理；85%前必须有可用安全视图或明确不足。55%仅为期望，低于85%且保真与硬限通过可PARTIAL_REDUCTION；仍达85%不得派发任务模型。
- 摘要请求、分批请求及验证请求进入同一辅助调用账本和任务费用预算。请求发送后结果未知不自动重试；不要承诺无法保证的模型exactly-once。
- 注入claim后派发前、已发送未存响应、响应已存未发布、已发布未推进Run、并发过时结果、恢复、入队失败、权限撤销等窗口。需要PostgreSQL跨进程证据的保证不能只用单测宣称。

质量实验准入：先审核已有公开数据和之前实验，避免再重复通用RAG。核实许可、构造方式、任务契约、分割及共享记忆边界；真实公开来源作主质量数据，人工故障样本只作回归。没有合适公开任务材料时记录缺口，不能随意生成一套题冒充公开基准。

读结果前登记一个模型/提示词/阈值候选、调用与token/金额上限、数据范围、关键错误零容忍及业务质量/成本门槛。执行连续施工单的有界实验约束，不沿用退款实验额度，不开展无界API试验；对不可执行的在线验证记录缺口并继续独立可完成工作。

## 7. M5及后续候选

先确保稳定提示前缀、确定性排序、具体版本引用及业务内容最小化。供应商缓存适配按实际路由支持实现，区分显式/隐式缓存、读写账单、TTL、租户隔离与权限变化；应用缓存命中不等于供应商prompt cache命中。在线元数据发现必须走端点和SSRF适配，不能以公开模型目录代替实际部署证据。

缓存候选需比较同任务质量、总费用、TTFT及端到端延迟；只省输入token但增加摘要费用/延迟的不自动推广。缓存命中数不从上下文占用中扣减。

M5以后的共享长期记忆相关性、冲突更新/失效、TTL与人工管理属于独立候选：先从现有Memory失误记录判断是否值得立项，不和本轮预算改动捆绑，不先承诺语义向量库、知识图谱或个人画像功能。

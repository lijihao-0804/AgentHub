# AgentHub 前端体验问题清单与优化方案（2026-10-27）

审阅方式：在本地将 `apps/web`（Next.js 15 / React 19）与 API 同时运行，注册独立审阅账号
（`ui-review@example.com`，组织「UI Review Org」/ 工作区「UI Review WS」），逐页走查空态与
主流程（登录 → 配置模型 → 创建/发布智能体 → 建工单 → 发消息），并以 zh-CN 界面为准核对文案。

环境备注：仓库当前代码的评测列表契约是 `{items, total}`，但 Docker 里的 `agenthub-api-1`
镜像是旧代码（返回裸数组），导致 **F1 白屏**。验证时已改用本地 uv 启动的 API（127.0.0.1:8001，
当前代码）作为前端代理目标。**该容器需要重建**（`docker compose build api`，本次因 docker.io
网络不通未能代做），否则 /evaluations/datasets、/evaluations/experiments 在容器栈上仍会白屏。

## 问题清单

### A. 崩溃 / 稳定性（P0）

- **A1. `/evaluations/datasets`、`/evaluations/experiments` 客户端异常白屏。**
  - 现象：`Unhandled Runtime Error: Cannot read properties of undefined (reading 'length')`，
    `app/evaluations/datasets/page.tsx:70`。
  - 根因：`listDatasets` 期待 `{items,total}`，实际响应是裸数组 → `setDatasets(undefined)`
    → 下一轮渲染在 `useCallback` 依赖 `datasets.length` 上崩溃。
  - 修复：在 `lib/api/evaluation.ts` 的列表函数里做形状归一（同时接受裸数组与 `{items,total}`），
    页面侧 `?? []` 兜底。前端不再因后端契约漂移而崩溃。

### B. 中文界面里的英文残留（P1，用户主诉）

- **B1. 仪表板趋势卡片**：`UTC · day` —— `app/dashboard/page.tsx:496` 把 API 返回的
  bucket 原值（`hour`/`day`）直接塞进模板。应本地化为「按小时 / 按天」。
- **B2. `/tools` 内置目录**：5 个内置工具的描述全是后端英文原文
  （"Evaluate bounded arithmetic expressions." 等，来源
  `packages/control_plane/product_control_plane.py` 的 `BUILTIN_TOOL_CATALOG`）。
  展示层应按 identity 提供本地化描述（未知工具回退服务端原文）；同时
  `approval_policy`（NEVER/ALWAYS）与 `execution_kind`（builtin/action）以 `<code>`
  原样展示，应本地化。
- **B3. `/settings/models` 模型表格能力列**：`CapabilityList`
  （`app/settings/models/page.tsx:956`）渲染 `vision=false streaming=false
  tool_calling=false structured_output=false max_context_tokens=128000` 这样的
  key=value 调试串。应渲染为本地化徽章（能力=支持才显示；上下文上限用计数格式）。
- **B4. 智能体发布预览**（agent 详情页）：「Spec Schema 版本 2」「解析后声明哈希」「解析后的
  Spec」中英混排；「知识 0 个绑定 / 工具 0 个工具」量词重复。
- **B5. 会话工单错误回退**：zh 界面出现 "The turn could not be recorded; retry the
  submission."（`THREAD_TURN_CONFLICT`）。该码来自**旧容器代码**；当前代码已改名
  `THREAD_TURN_IDEMPOTENCY_CONFLICT` 且在字典内（已核对全部 65 个后端错误码均有 en/zh 条目）。
  容器重建后消失，不需要改错误回退策略（保留服务端原文是文档化决策）。

### C. 文案质量（P1~P2）

- **C1. `/agents` 空态**：「请先在「设置 › 模型」中创建模型配置。模型」——句号后悬挂一个
  孤立的「模型」链接（`app/agents/page.tsx:136`），应把链接并入句内。
- **C2. `/knowledge` 引导语**：「文档在知识库内部上传。打开某个知识库即可上传文件并发布快照。」
  翻译腔，应改为自然中文。

### D. 交互（P2）

- **D1. 供应商凭据表单**：未选供应商时提交按钮禁用但无任何原因提示，用户不知道差哪一步
  （实测踩中：填完名称/URL/Key 后按钮依旧灰）。应在按钮附近给出「还需选择供应商」类提示。
- **D2.（确认无问题）** 会话页提交冲突的「恢复上次提交」流程、审批徽章、导航计数轮询、
  未知错误码保留服务端原文——设计合理，保持不动。

## 实施范围（本次）

F1 形状归一修崩溃；F2 bucket 本地化；F3 工具目录本地化；F4 能力徽章；F5-F7 文案修正
（agents 悬空链接、knowledge 引导语、发布预览术语）；F8 凭据表单禁用原因提示；
F9 会话输入框 **Enter 发送 / Shift+Enter 换行 / IME 组合回车不误发**
（`components/apps/app-conversation-pane.tsx`，四个应用共用一处）。

## 验证结果（均已实机回归）

- `npx tsc --noEmit` 通过；`npm run build` 成功。
- /evaluations/datasets、/evaluations/experiments 在 `{items,total}` 契约下正常渲染；
  归一层同时兼容裸数组响应。
- /settings/models：能力列渲染为「视觉 · 不支持」「上下文 128,000 Token」等中文徽章；
  凭据/模型配置表单缺字段时显示「还需完成：供应商、名称和API Key」（Intl.ListFormat zh-CN）。
- /tools：目录描述全中文（"计算有界算术表达式。"等），类型/副作用/风险/审批要求全部本地化，
  未知 identity 回退服务端原文。
- /dashboard：趋势卡片显示「UTC · 按天」。
- 智能体发布预览：「规格结构版本 / 解析后规格哈希 / 绑定 0 个知识库 / 绑定 0 个工具」。
- /support 工单：Enter 直接发送成功（草稿清空、运行创建、失败呈现完整）。
- /knowledge：引导语改为「文档归属于知识库：打开一个知识库，即可在其中上传文件并发布检索快照。」。

## 遗留事项

1. **重建 API 容器**：`agenthub-api-1` 仍是旧镜像（网络不通未能重建）。网络恢复后执行
   `docker compose build api && docker compose up -d api`，否则 Docker 栈下 B5 类旧错误码
   与数据集白屏（旧裸数组契约）仍会复现。验证期间用本地 uv API（127.0.0.1:8001）替代。
2. 本次未做：相对时间显示、表格骨架屏、/runs 与 /evaluations 列表的批量操作、
   语言切换后的路由标题刷新等更深一层交互打磨，可作下一轮。
3. 审阅产生的测试数据在独立工作区「UI Review Org / UI Review WS」（账号
   ui-review@example.com），不影响业务数据，可随时删除。

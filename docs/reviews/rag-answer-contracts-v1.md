## 哪些 CitationQA 故障已经修复

公开响应沿用三个字段。候选在规范化前检查原始编号与可见范围，保留内部原始输出、SHA-256 和转换规则，再校验交付正文、编号数组与状态。有据的否定仍是答案；部分可答须保留已答部分和出处。唯一在历史输出中成功恢复的是一条整体拒答，引用只定位了未提供指标的章节。相反，同一道比较题的 B/C/D 三个输出都含单方模型的具体事实和出处，声明可回答却明确无法完成比较。候选将这三条作为合同冲突，原归档与拒绝原因均可回查。[决策表与逐条核对](../../benchmarks/public_rag/results/published/rag-answer-contracts-v1/replay.md)

## 冻结的新题将检验什么

候选产品固定后，两名未参与实现的 Astra 子代理分别编制 16 个 QA 和 16 个客服输入及判据。第三名子代理只看素材与协议。交叉核对后，编题者在首次派发前将 SUP06 明确为请求金额拆分及是否同批发放，保留原事实与评分标准。SUP04 以客户开放工单查询的真实空列表核对，SUP11 只能判断材料标记，SUP14 以拒绝决定和未建单读回确认。样本为中英合成问答与中文合成业务场景，属于内部冻结验收。

QA 覆盖完整 6 题、证据不足 6 题（其中 3 题原文也不可答，另 3 题仅原文可答）及部分可答 4 题。已离线执行 B，将 22 个定位可回原文的片段冻结，10 题各 1 段、6 题各 2 段。16/16 题的两臂用户消息及有序证据相同。候选系统提示由 223 增至 346 个本地 token。当前快照刻意隔离回答层，新结果适用范围是这种短证据设置。客服四类各 4 案，14 案禁止写入、1 案审批通过、1 案审批拒绝。实际检索文字与送达证据可能因模型改变查询而变化，逐案记录 ID 和片段摘要。

两条链路各计划 32 个首次任务机会。派发前预计费用 1.44 元，按每次最多 32,768 输入、2,048 输出和北京忙时价预留，硬上限 160 次物理请求、13.107200 元。失败、无终答和未知派发均保留。两条链路分别计算正确率、拒答、引文支持、成本、时延及配对区间。[冻结清单、评分与可执行命令](../../benchmarks/public_rag/results/published/rag-answer-contracts-v1/README.md)

本轮工程审查分别考虑严格引用校验、可追溯的规范化及版本绑定的工具事实说明。冻结前历史重放的合同通过率下降，客服脚本验证了链路。新输入的真实结果见下节。

交付前在 Windows 项目环境中以退出码 0 运行 147 项问答合同、拒答、证据、客服、派发与评分定向测试，并通过全仓 Ruff、前端回归及冻结预检。客服另通过 4 项使用真实 PostgreSQL 的定向治理检查。空响应和失败输出审阅的补充测试使用合成材料；评审工具单独固定于 `1e53a9b`，样本编制开始后产品与派发实现的可执行内容已核对一致。

## 授权后的真实首答

64 个首答机会全部派发并确认终态，122 笔请求全部核回供应商 ID 与用量。按冻结价格 0.818014 元，账户实扣账单不可得。两名独立 Astra 评审审阅全部 64 张匿名卡，第三名裁决 13 张分歧卡。

QA 正确率 50.00% → 50.00%，两胜、两负、十二平。合理保留为 60.00% → 90.00%，引文支持率 90.00% → 95.00%。机器可交付终答 12/16 → 16/16；候选仍有五份正文整体保留却返回 false。退步为 QA02 的引文错配和 QA14 漏答可见事实。

# AgentHub：结构化阅读单元的真实论文问答评测

本轮没有采用结构化切块作为默认方案。24 篇论文的开发实验保留 70 题分母后，答案 F1 **17.01% → 16.95%**，人工证据完整可见率 **18.75% → 32.81%**，索引块数却增至 **2.45 倍**。改善摘录完整性没有带来稳定答案收益。首题发生初始化和备用异常，按事先补充登记完成其余 69 题；原完整计划未完成，结果仅用于开发诊断。

## 设计依据

AgentHub 的设计主线是“来源可追溯的证据交付”：文档原文 → 有原始坐标的检索单元 → 预算内证据 → 原文引用 → 答案。优先修正这些边界之间的信息损失，再考虑新增推理调用。

实际源码依据：

- [LlamaIndex SentenceSplitter](https://github.com/run-llama/llama_index/blob/main/llama-index-core/llama_index/core/node_parser/text/sentence.py)：优先段落、句子，过长时逐级退化切分。
- [Haystack DocumentSplitter](https://github.com/deepset-ai/haystack/blob/main/haystack/components/preprocessors/document_splitter.py)：段落、句子边界与来源偏移。

本轮采用上述边界思想，使用本项目既有契约实现，不引入第三方编排框架。原文坐标、知识快照、发布版本、模型网关、工具运行和上下文预算继续由原生产组件负责。结构化切块仅通过内部 worker 依赖显式启用。

现有方案按 1200 字符切块、重叠 200 字符；证据摘录又限制到 1000 字符。新方案自然段优先，超长段落按句子、词及字符退化，最大 1000 字符、不重叠；标题尽量与下一段连续正文一起保留。它检验的是整个切块策略组合，不能将变化单独归因为段落边界。

源码进一步对照发现，LlamaIndex 还将自然分段重新合并到预算内；本轮实现选择段落独立，不等于复现它的完整算法。[SentenceWindowNodeParser](https://github.com/run-llama/llama_index/blob/main/llama-index-core/llama_index/core/node_parser/text/sentence_window.py)则显式区分句子节点与邻句窗口。这说明“保留边界”与“组装足够上下文”是两项责任，不能只做前一项就宣称已经采用成熟项目的完整架构。

## 冻结条件

[协议](../../benchmarks/public_rag/results/paragraph-qa-20261023/protocol.json)在答案请求之前冻结；[抽样记录](../../benchmarks/public_rag/results/paragraph-qa-20261023/sampling-audit.json)保留来源。

| 条件 | 两组共同设置 |
| --- | --- |
| 语料和问题 | 24 篇论文，70 题，74 份人工答案标注 |
| 可回答性 | 65 题可回答，5 题不可回答 |
| 检索 | BGE-M3 dense + tokenizer sparse + BGE reranker；各路 20、候选 20、输出最多 10 |
| 阅读预算 | 检索结果 8000 bytes；运行时 RAG 8000、工具结果 4000 的既有估算预算 |
| 答案 | 原论文 QA 提示不变；温度 0、thinking 关闭、输出最多 1024 |
| 运行 | 最多 3 个模型步骤、1 次原生检索、每 profile 1 次尝试 |
| 路由 | 本机 Magpie，`auto/deepseek-v4.1-flash`；阿里云备用 `deepseek-v4.1-flash-1017` |

新样本避开已知曝光的 92 篇 TRAIN 论文。没有读取新的 DEV/TEST 划分，也没有将标准答案或人工证据注入在线检索、提示或选择。它仍是开发实验，不是独立确认、正式 Experiment 或新 holdout。

遇到备用派发、模型身份异常、传输结果不明、来源错误等情况，在当前 Run 结束后停止后续批次。所有预定问题保留，失败、无效和未执行项计零；混合模型结果不能声称是单模型质量提升。

## 已完成的入库检查

48 个真实入库任务全部成功，48 个固定快照 AgentVersion 已发布。两组共有 2193 块：现有策略 635 块，新策略 1558 块，索引块数增长至 **2.45 倍**。

[索引分布](../../benchmarks/public_rag/results/paragraph-qa-20261023/index-unit-diagnostics.json)：新组平均约 403 字符、中位数 348，486 块不足 200 字符，占 31.2%；现有组平均约 1186 字符，620 块超过摘录 1000 字符上限。新组索引正文总字符减少，但向量条目显著增多；不能用正文字符下降推断整体索引更便宜。

[原文检查](../../benchmarks/public_rag/results/paragraph-qa-20261023/text-preflight.json)验证了 1826 个段落、标题来源区间；[数据库检查](../../benchmarks/public_rag/results/paragraph-qa-20261023/persisted-preflight.json)核对实际块文本、快照绑定、发布模型参数和相同预算。64 道题有人工作答证据可用于可见性指标；另 1 道可回答题没有证据条目，不从答案 F1 分母中删除。人工证据均能在来源映射中对齐。

入库流水线实测耗时：现有组约 39.13 秒、新组约 24.47 秒，整个准备任务约 70.50 秒。每篇先执行现有组，首组还承担模型初始化，因此这些时间仅作费用台账，不能宣称新组入库更快。

## 预定评分和验收

主指标为最大人工参考答案 token F1，70 题全部计入；按论文分组进行 5000 次 paired bootstrap。并列报告 EM、格式及可见引用有效率、5 题拒答、实际证据可见性、输入输出用量和 warm 端到端 P95。

预定收益门槛：F1 至少增加 5 个百分点、分组 95% 区间下界为正、EM 不下降、两组有效回答率均至少 95%、不可回答题的无依据回答不增加；输入和 P95 分别不得超过基线 1.5 倍。全部工作流和来源检查也须通过。

人工证据段落完整字符串出现在实际模型可见摘录中，只是保守的可见性代理；段落关联重叠更不能当作完整支持或语义忠实性。没有调用未经校准的模型裁判。实际货币价格未知，不虚构金额。

## 执行中断与补充登记

最初 `live-run-1` 在首题后停止，准备任务退出 0，答案任务退出 2。共记录 3 次保守派发尝试：2 次收到模型响应，1 次初始主调用没有可确认结果，另有 1 次备用接管。不能把这条未知请求记为成功、免费或未派发。

日志显示 LiteLLM 首次导入时远程下载价格表、重试并回退本地表，与首个主网关时间窗重叠；同时出现未等待完成的协程警告。首次请求是否到达服务端不可确认。最初记录器未捕获取消，原始状态停在 DISPATCHED；原文件保留，[补充登记](../../benchmarks/public_rag/results/paragraph-qa-20261023/operational-amendment.json)明确将其计为未确认。

修正依赖初始化位置、强制使用已安装的本地价格表、补全取消记录后，事先登记 `live-run-2`：整题排除已曝光首题，处理剩余 69 题、138 个新 Run，最多再派发 417 次，与原 3 次共享总上限 420。模型、问题、提示、切块、预算和评分均不变。没有重试首题或读取其答案来挑选新参数。

补充报告保留原 70 题分母，排除题两组各补零；它不是 69 对完整结果的均值，不能混称。原计划未完成，描述性 bootstrap 数值即使为正也不具有原预登记推断资格。原混合模型回答不进入补充质量比较，不进行下一次自动补跑。

## 结果与验收

补充运行完成 138/138 个生产服务层 AgentRun，276 次模型请求全部收到响应，原始返回模型均为 `deepseek-v4.1-flash`，没有再次备用、未知传输或模型身份错误。运行状态明确为 `COMPLETE_UNTOUCHED_REMAINDER`，实际退出 2，保留原计划未完整完成的事实；不能写成原任务正常退出 0。

F1 差 **−0.0639 个百分点**，描述性论文分组 bootstrap 区间约 **[−4.71,+4.99]pp**。因运行补充与首题补零，机器记录 `inference_valid=false`；这不是原预登记的有效确认区间。70 题中 21 题分数上升、30 题下降、19 题不变，其中包含排除题的双方零值。没有计算“仅有效题”的主成绩来隐藏失败。

因此未通过完整性、F1、有效回答率等门槛，默认不变；延迟和输入预算通过，也不能抵消质量未达标。

## 为什么可见性提高，F1 没提高

第一，段落完整不是答案关系完整。[阶段诊断](../../benchmarks/public_rag/results/paragraph-qa-20261023/live-run-2/stage-coverage.json)显示：融合候选完整原证据可见率 43.75% → 60.94%，最终检索返回 25.00% → 35.94%，模型可见摘录 18.75% → 32.81%。这些是同一套人工段落字符串的保守代理，不能称为语义支持召回。它们说明交付前后都仍有损失，也说明该代理不是答案质量的充分条件。

新组在可评证据题上平均检索返回约 5.95 块，最终模型实际看到约 5.02 块；平均可见正文约 3123 字符，现有组约 3899。更短的块、更多记录元数据，以及运行时投影共同改变了可读内容；候选数和字节预算相同不等于语义信息量相同。486 个短块也提示片段化风险，尚不能据此单独断言它造成了多少损失。

第二，答案表达会显著影响官方词面评分。[答案形式诊断](../../benchmarks/public_rag/results/paragraph-qa-20261023/live-run-2/answer-form-diagnostics.json)：两组各 11 道 yes/no 题中，均有 8 题以人工标准的正确极性开头，但其中各 7 题附加了解释。正确极性开头不等于整句语义正确；这里仅解释分数敏感性。例如手语论文问题，标准是 `No`，现有组直接回答得 F1=1，新组以 No 开头后补了长解释，F1 仅约 0.105。另有模型基线名称加弯引号，内容词相近却难以被官方 ASCII 标点归一化匹配。所有官方分数保持原样，没有事后删解释、换别名、改标点来抬分。

第三，拒答契约和关系判断确有问题，不能都归咎评分。两组分别 4、3 次真实格式失效都属于 `unanswerable=true` 时仍将解释写入应为空的 `answer`，不是 JSON 截断；5 道人工不可回答题中，两组仍各有 3 道生成有效非拒答。另一个问题“是否与 MAML 比较”中，现有组回答 Yes、新组回答 No，只有新组符合人工标准。把相关工作提及当成实验对比、把原因或范围补充成无依据结论，属于阅读任务，切块本身不能保证解决。

这些诊断不证明单一原因。它们足以否定“只要检索段落更完整，答案就必然更准确”的设计前提。

## 检查、用量与复现边界

[复核](../../benchmarks/public_rag/results/paragraph-qa-20261023/live-run-2/verification-v2.json)核对 138 个唯一实际 Run 的持久化输入、版本、状态、工具次数和 token 用量，并核对分组汇总；140 个评分位置与本地官方 QASPER F1 实现一致，其中 **2 个是排除题补零位置，并非 140 次实际回答**。625 个实际可见摘录均为对应论文、对应实验臂的原始块精确子串；没有把引用 ID 有效性冒充语义支持度。

43 项不同的定向单元检查通过，另完成真实入库、发布、来源、CLI 执行门禁及静态检查；无新增哈希测试。[审阅及修正](../../benchmarks/public_rag/results/paragraph-qa-20261023/continuation-review-resolution.json)保留原发现：最终禁止用新目录名重复派发已曝光整批问题，核对原始与补充共享上限；部分验证明确只表示已记录材料核对通过，不表示原完整计划成功。

[全部请求台账](../../benchmarks/public_rag/results/paragraph-qa-20261023/api-ledger.json)：原始与补充合计 279 次保守派发尝试，278 次收到响应、1 次结果未确认；观测输入 484554、输出 29563，共 514117 tokens，未知调用用量未被当零，货币价格仍未知。准备、原始与补充任务日志均保留。

[材料导航](../../benchmarks/public_rag/results/paragraph-qa-20261023/README.md)区分最初代码归档、补充执行归档和执行后离线复核/门禁修正归档；官方 evaluator 也在最后一份归档中。运行通过真实生产服务和 worker 函数，但没有经过 HTTP/UI、Celery broker 或完整 PDF/OCR。只测英文论文、24 篇开发组；不同模型入口、不同问题和上一轮分数不可直接横向比较。

## 收口决定

后续 2026-10-24 的[完整架构与请求审阅](AgentHub-RAG完整问答架构与瓶颈诊断-20261024.md)另发现：两组各69次搜索中，65次/66次严格使用原问题，其余7次为模型自发纠错、语法或关键词变化，涉及4道原题，其中3对实际检索字符串不同。原提示要求原题查询，但执行守卫没有强制这一参数。因此本轮也不是严格固定实际 retrieval query 的切块单变量实验；原始请求、分数、未推广决定均不改，不通过删题重算来挽救结果。后续要隔离切块效果，应固定服务端查询；要评价改写，应将其作为显式待测策略。

本轮结束，不采用段落独立切块，不再对该批问题调尺寸、重叠或提示词。结构化构建器保留为内部显式实验依赖，未加入默认配置、公开策略注册或历史业务版本。

若开启下一轮，合理候选是具有明确原文成员和预算的“检索单元—阅读视图”分离，以及可验证的短答案/拒答契约；应先冻结关系判断和负证据案例，再在新来源上检验。LlamaIndex 的边界合并与邻句窗口提供架构依据，但不能直接把扩展窗口写回原 chunk ID，冒充原始引用范围。这个方向需要单独设计和验收，本轮没有宣称实现或获得收益。

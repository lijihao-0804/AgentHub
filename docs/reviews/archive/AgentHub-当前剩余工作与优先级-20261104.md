## 4. 确定存在的功能与证据缺口

### 4.1 上下文、摘要与长期记忆

- **自动摘要生产门禁仍关闭**：发布器继续返回 SUMMARY_QUALITY_GATE_NOT_MET。摘要状态机与跨轮复用已完成；待补的是多题事实保持、负向约束、全流程 token/成本/延迟收益证据，不是删除门禁。
- **普通上下文计数仍主要使用近似估算**：固定 DeepSeek 资产和受限格式计数已有验证，不能推导任意 provider / 工具消息都已精确计数。辅助抽取、selector、judge 的统一准入与计费覆盖还需专门核对和接线。
- **Memory 语义质量仍有限**：相关性拒绝、旧事实与冲突处理、禁止写入/使用、真实模型 USE 的收益尚未充分证明。已有 expires_at 过滤、supersede helper、touch 与历史快照，不等于自动 TTL 策略、衰减、容量治理或自动语义替换均已完成。
- 长期记忆默认关闭；若以后扩展治理，应先证明真实质量问题和策略收益，保留被旧版本引用的历史记忆，不做破坏回放的物理删除。

### 4.2 测评扩展

- **Judge 人工校准与成本计量**：已有多 judge/quorum；仍缺人工标注一致性、位置交换/偏差验证、完整 judge usage/cost 证据。
- **统计门禁真实配对验证**：函数、门禁与 UI 已实现；历史 JSON 明确证明的真实 PASS 范围仍需窄报。新数据应覆盖真实低分、配对不足、非劣性与不确定区间，不把合成规则测试当模型效果。
- **AE-7b 安全样本**：已有七族断言和缺失覆盖处理，尚缺系统性的攻击语料与真实安全任务证据。
- **AE-8 外部基准、AE-9 在线采样、模型驱动用户模拟器**：仍是可选后续方向，不是当前本地评测链的启动条件。
- **门禁策略编辑 UI**：当前仍只提供原六类规则；AE-10 展示已有新规则结果，不等于可在表单创建 REQUIRED_EVIDENCE_LEVEL/MIN_PASS_HAT_K/MIN_CI_LOWER_BOUND/NON_INFERIORITY。需要高级门禁配置时单独补 authoring 与 API 合同回归。

### 4.3 产品与管理入口

- **Wiki 页面和 Agent 可视化绑定**：主分支已有 Wiki API/生命周期；最新提交的 knowledge 前端没有独立 Wiki 页面。根目录另有未提交原型，应先独立审查/验收再决定集成，不能列为完全没有开发。
- **每 Agent 上下文策略配置 UI**：后端已有冻结配置；根目录未提交原型的 preset 曾与后端五档枚举不匹配，尚不能当已交付入口。需要完成合同对齐、预检、保存/发布和默认关闭说明。
- **成员管理**：现有页面能列出/移除成员；新增成员、角色调整、邀请接受/撤销尚未形成完整 UI/流程。真实多人使用时优先，单人本地演示可延期。
- **独立派生 Agent 草稿及来源关系、逐轮参数热调**：仍属归档产品需求；已有版本 diff/发布不能替代独立派生与来源冻结。是否实施以具体需求为准。

### 4.4 外部副作用与运维

- **未知外部写入的操作闭环**：已有 UNKNOWN_OUTCOME、NEEDS_ATTENTION、留证和部分内部 reconcile；通用外部目标的结果查询、受权人工确认、审计与清理解除尚需完善。不能通过新增“一键重试/强制清理”绕过未知结果。
- **M8 对外部署验收**：当前是 24 小时监督的本地受控预览，不是稳定公网交付。已有 Auth/RBAC/SSRF/限流等代码不应重写；待验证的是生产配置、网络入口/TLS、服务守护、凭据与日志策略、备份恢复、迁移流程、监控和故障/容量边界。
- **持续浏览器 E2E**：专项真实浏览器/队列/接口证据已具备；完整产品主要路径的持续浏览器覆盖、跨机故障和生产饱和容量仍未证明。当前 Node/TSX 测试不能替代全部浏览器行为验证。

## 5. 不建议现在并行铺开的工作

完整 Dashboard 重做、更多模型驱动角色、多个外部 benchmark、大型 Memory 衰减/冲突引擎、逐轮热调、完整邀请系统都不是同一个里程碑。应依据目标选择：

- **研发/论文式比较目标**：先做可信业务质量评测与 judge 校准。
- **实际费用控制目标**：先做跨轮金额预留与真实用量对账。
- **多人/公网试用目标**：先做部署和团队治理验收。
- **近期演示目标**：先合并 AE-10、同步入口与演示数据；保持受控本地环境和证据限制。

上述选择是后续工作建议，不代表本轮已开始执行，也不从旧归档计划推导继续施工授权。

# 个人审批、文档解析与切块验收

## 如何使用

在「审批」页展开「我的审批设置」。配置作用于当前用户和当前工作区。具备审批权的组织 Owner、Admin 可以选择人工、最高低风险或最高中风险。普通成员可以查看自己的上限。个人委托处理原本需要审批的动作。发布时已免审的低、中风险读取继续直接执行。高风险工具和外部 MCP 写入始终需要有权限的人确认。

例如选择「最高低风险」，把最多自动拒绝次数设为 2。一个受管中风险动作在两个不同申请中以相同的工具版本和规范化参数出现时，策略可各拒绝一次。第三个申请进入人工收件箱。设为 0 时，第一次超出所选上限就转人工。允许的动作仍须按正常流程认领执行。收件箱区分人工与委托决定，并解释达到拒绝上限或敏感操作的转人工原因。拒绝次数可跨 Run 累计。每个 Run 仍受其发布版本的重复调用、模型轮数和工具预算约束。

在「知识库」创建知识库时选择切块策略，也可在上传文档或新修订时覆盖。上传后检查修订状态，创建快照，在冻结分片预览或检索测试台查看页码、行列及原文。固定窗口保留已有行为。按段落切分适用于段落边界明确的材料。自适应切分识别 Markdown 章节、围栏代码、管道表格以及解析器标记的页和单元格。策略、最大字符数和重叠量跟随修订保存。

| 原件 | 入库方式 | 可以核对的证据 |
| --- | --- | --- |
| 有文字层的 PDF、TXT、Markdown | 直接上传 | 页码或字符范围，Markdown 表格另有行范围 |
| 带表头的 UTF-8 CSV、TSV | 直接上传 | 行号、列范围及单元格位置 |
| 扫描 PDF、PNG、JPEG | 在 Windows 上运行下方命令，上传输出的 JSON | OCR 原文、页码、行框 |
| 有复杂版面或合并单元格的文档 | 上传 MinerU 平铺版 Content List V1 或含单份 `content_list` 的已完成解析响应 | 阅读顺序中的页、块、边界框及源表的行列跨度 |

在仓库根目录使用 Windows PowerShell 5.1，输出文件须使用新名字。本次验收使用已安装的简体中文识别语言。图片识别质量和阅读顺序取决于扫描件；多栏排版和跨行表头可使用已有的布局解析结果。[Windows OCR](https://learn.microsoft.com/en-us/uwp/api/windows.media.ocr.ocrengine) · [MinerU 输出格式](https://opendatalab.github.io/MinerU/reference/output_files/)

```powershell
powershell.exe -NoProfile -File scripts/convert-scan.ps1 scan.pdf scan-content.json -Language zh-Hans-CN
```

转换器按页识别，输出从零开始的 `page_idx` 和归一到 0–1000 的 `bbox`。产品展示的页码从 1 开始。合成两页扫描 PDF 的识别结果为第一页“设备验收记录”“订单编号 1001”，第二页“第二页 2026”。本机核对了三行文字、页与行框。在数组中没有文字的页面不会生成伪证据。现有文本 PDF 解析器继续读取文字层，CPU OCR 是上传前的显式步骤。

官方 MinerU 3.3.1 示例另走了 multipart 上传、Blob 存储和隔离解析进程。4 个输入块解析为 17 个可引用块，第 6 页的表格恢复出 12 行、11 列、123 个单元格定位，其中包含跨两行和跨十列的合并单元格。导入器读取已完成结果，未向第三方上传文件。[官方格式样例](https://github.com/opendatalab/MinerU/blob/mineru-3.3.1-released/docs/en/reference/output_files.md)

对于返回任务状态或 ZIP 下载地址的解析 API，先取得结果包，再上传其中的平铺版内容列表。UTF-8 表格使用首个非空记录作为表头，保留带引号的换行和分隔符。导入限制为每行 256 个逻辑列、每份材料 65,536 个单元格定位和 20,000 个布局块。云端托管模型和对扫描图直接识别表格均不在此次精度测量范围内。

## 切块的离线比较

参考 Unstructured 按文档元素和标题划界，以及 Docling 对表头与内容边界的处理。AgentHub 用解析块和原文位置保留依据，超长块在修订所选的字符预算内再拆分。[Unstructured](https://docs.unstructured.io/open-source/core-functionality/chunking) · [Docling](https://docling-project.github.io/docling/concepts/chunking/)

本实验复用仓库已有的 QASPER 训练数据、文章渲染和单篇文章 BM25。用种子 `20261117` 先选 32 篇论文，再按原顺序轮取至多 100 题，共取到 83 题。72 题满足各标注者均认为可回答，且至少一段人工标注证据能与正文完全匹配。三种方法共用这 72 题。完整保留表示至少一个块包含一整段标注证据；前六命中表示其中一个块进入单篇文章 BM25 前六。训练集文件 SHA-256 为 `9458bfe76074a8fa8d1685af02bcc73537aa6d338ad20591dfaff1946bc88bf4`。[QASPER 原论文](https://aclanthology.org/2021.naacl-main.365/)

| 生产切块策略 | 块数 | 完整证据 | BM25 前六 | 前六相对固定窗口新增 / 丢失 |
| --- | ---: | ---: | ---: | ---: |
| 固定窗口 | 808 | 48/72（66.67%） | 28/72（38.89%） | — |
| 按段落 | 1,861 | 71/72（98.61%） | 30/72（41.67%） | 11 / 9 |
| 按文档结构 | 1,880 | 66/72（91.67%） | 27/72（37.50%） | 9 / 10 |

同一篇论文拆出的块越多，查询时可竞争前六的位置也越多。这里自适应比固定窗口多完整保留 18 题，前六却净少 1 题。按段落也有 9 题从前六掉出，故两种策略均作为可选项。测量限于英语研究论文、已知文章和词项检索。端到端问答正确率、应拒答样本及复杂版面识别精度需要各自的标注与评测。

五份合成材料另做了 64 个证据跨度检查。固定、段落、自适应三种策略分别完整保留 59、60、60 项。自适应在 Markdown 上从 14/17 增至 17/17，在原生 PDF 上从 12/12 降至 8/12。两条跨段规则与例外用例中，固定窗口两条均保留在一个块内，另外两种策略各保留一条。

在已有开发数据的仓库根目录运行以下命令，可重建各策略的计数和相对基线逐题变化。仓库同时保存了[新增与丢失的题目 ID](evidence/chunk-strategy-replay-20261117.json)。

```powershell
.venv/Scripts/python.exe -m benchmarks.public_rag.chunk_strategy_replay
.venv/Scripts/python.exe -m benchmarks.retrieval.chunking_probe
```

## 产品验收

基础提交为 `fafe4aba`。审批服务在 `552bd43`，切块与产品入口验收在 `8c84de4`。在专用 PostgreSQL 16 测试库从空库升级至 0058，Alembic 模型对账无差异；在写入业务样本前回退至 0056、再升级至 0058 均成功。另在 0057 写入旧 READY 修订和快照后升级，原分片、引文位置与快照内容哈希逐字段一致。

- Python 全量单元回归为 3,530 项通过，3 项跳过。前端 8 组回归和 Next.js 生产构建退出码均为 0。
- 同一测试库内联合执行 54 项集成测试，覆盖实际工单、权限撤销、并发拒绝上限、人工确认、未知结果、旧审批恢复、分片重投和快照。模型工具建议由脚本提供，工单和审批状态由 PostgreSQL 持久化。
- 审批迁移单独验证旧人工决定、待审批状态的读回，以及已有委托决定时回退保护。本机 PostgreSQL 在删除专用测试库时无法向检查点进程发送信号，验收使用显式保留测试库选项。正常环境会清理本用例创建的随机测试库。
- 真实 HTTP 处理器收到 OCR JSON 与 CSV 后，生产 worker 读取 Blob 并解析，快照冻结两个修订。提交“invoice 1001”到检索测试台，返回证据的块 ID、行列位置与快照一致。测试在进程内调用 ASGI 和 Qdrant，使用确定性嵌入及重排器，并手动消费队列。本轮外部模型请求 0，费用 0 元。

AE-6b 的“动态”是 Agent 输出触发脚本模拟器披露下一轮信息；Agent 模型是真实调用，Simulator 本身是确定性代码。它已超出 AE-6a 的纯契约，但仍不是模型驱动的用户模拟。

交互 driver 复用既有 Thread、AgentRun、Approval、Checkpoint 和 ExperimentRunner，而非新建另一套 Runtime。benchmark 显式注入 driver 后完成了正式服务层实验；标准 `apps/worker/tasks/evaluation.py` 仍返回 `AgentRuntimeEvaluationDriver`，不能把脚本验收推广为“任意 INTERACTIVE 实验都已能通过页面与 Celery 自动运行”。

环境隔离通过同一 PostgreSQL 中唯一的 customer_ref 和 workspace 校验实现，不是每个 case 使用独立数据库。正常准备失败及执行 finally 路径会 teardown；但环境 handle 仅存内存，prepare 与 execute 之间进程崩溃后的遗留环境清理尚未形成持久化恢复机制。交互任务成功要求业务状态通过、所有 AgentRun 成功、teardown 完成、goal_met、审批脚本消费完整且没有 Canary 泄漏；不能只凭“0 条工单”把提前失败记成成功。

**四、上下文管理现状**

核对根目录与最新 AE-6b 分支，`context_policy.py`、`context_budget.py`、`history_planner.py`、`summary_service.py` 的文件 hash 一致。AE-6b 没有重新实现上下文体系；以下结论沿用已合入的上下文工程，并以最新分支代码确认默认门控。

| 上下文研发阶段 | 已完成 | 当前边界 |
| --- | --- | --- |
| M1 原子准入 | 单条记忆完整准入；工具调用/结果成组；真正送达后再 touch | 送达可信不等于内容相关、无冲突或有任务收益 |
| M2 自适应预算 | 主备模型可用窗口取交集，预留输出与安全垫，随 AgentVersion 冻结 | 普通 Agent 仍用 approx_language_v1 估算，不是所有 provider 的精确 tokenizer |
| M3 确定性历史 | 冻结水位、分页快照、完整交换组、裁剪前压力测量 | 显式启用 deterministic_history_v1；有读取上限，不是无限历史支持 |
| M4 摘要 | 同步节点、job/response/artifact、checkpoint 绑定、不可变修订、原文保护、跨 Run 复用 | 生产发布仍返回 SUMMARY_QUALITY_GATE_NOT_MET；工程闭环完成，质量推广未通过 |
| M5 缓存 | 稳定工具参数序列化、冻结顺序、cache usage 与能力识别 | cached_tokens 不抵扣上下文预算；受控路由命中不等于任意生产请求都能命中 |

默认预设 GENERAL_64K；软触发 70%、硬触发 85%、目标 55%；最近保留 2 轮，最大历史组数 256。不能把三道阈值的含义颠倒。

既有真实证据：跨轮摘要生成与固定修订复用中，首答命中 F1–F4 的 4/4、续答命中 N1–N5 的 5/5；另有 4 次隐式缓存探针，两个热请求 cached_tokens=2048。它们证明限定链路可运行，不证明总体质量或长期成本收益。

质量推广仍受以下限制：QMSum 首批 12 题没有形成有效配对；后续 Spark 单题有关键事实保留，但章节输入与输出上限存在差异，且摘要生成本身有成本，不能用后续答案输入下降 53.8% 推导端到端省钱。

仍需收口的全局边界：主 Agent / Citation QA 的准入覆盖不能扩大成所有辅助模型调用；memory extraction、selector、judge 的统一准入与成本接线仍需补齐。持久 Run 金额账本有 primitive、adapter 和测试，但默认生产 API/worker/evaluation 没有全面注入，不能将 token 窗口控制等同于全链路金额预留。长期记忆默认关闭，其相关性、冲突与实际任务收益也未获普遍证明。

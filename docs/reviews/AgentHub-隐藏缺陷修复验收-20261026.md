## 补充风险

- C-01：数据库 Run lease 限制一个执行者；过期执行权转 NEEDS_ATTENTION，不盲目夺取重放。
- C-02：审批恢复产生持久事件，序号从持久尾部继续。
- C-03：结构事件在发布和释放执行权之前持久化；冲突序号报错；日志失败标记不能由后续成功关闭清除。`message.delta` 不持久化，重播保证结构与最终结果，不保证逐 token 动画。
- C-04/C-05/C-08：正式实验 Wiki 可用性、query_wiki 绑定与冻结检索模型配置纳入发布/执行校验。
- C-06：reconciliation 采用公平访问游标，探针失败也推进，并记录错误。
- C-07：审批 API 在恢复后重新读取执行状态。

整合时补齐了恢复身份的权限边界：HTTP 审批恢复及后台恢复都重新确认原 Run 创建者仍拥有
`agent_run`。原创建者降级或失去访问时，停止为 `NEEDS_ATTENTION / RUN_ACTOR_ACCESS_REVOKED`，
清除恢复待派发标记，不调用后续模型或执行已批准动作。审批人的权限不替代执行人的权限。
状态改变会撤销旧日志完整性标记，只有新段的对应终态或审批中断帧已持久化才能重新标完整。

恢复也覆盖准备和派发之间的窗口：已创建但尚未启动的 Run 可按同一身份重投；执行 lease 退出时，
若图仍未收口，则在同一事务中先置 `NEEDS_ATTENTION` 再清 owner，不能伪装成可重新启动的草稿。
流式补播只在 live 序号出现缺口时补读，不对每个连续 token 查库；慢订阅者队列满时退出 live 队列并转入持久补播。

选择器目前没有版本冻结的单价契约，因此 `max_cost_micro_usd` 非空的 Run 在网络派发之前跳过它，
并在检索 trace 记录 `cost_budget_unpriced_selector`，使用已有基础结果。未限价 Run 可以启用选择器；
成功、响应解析失败和超时均记录 attempt，已返回的 token 用量照实保留，未知费用不记为零。
辅助调用进入 checkpoint、Run 汇总与 `AUXILIARY_MODEL` step；不把它冒充为普通生成轮数。
工具截止时间贯穿基础检索与选择阶段，选择阶段预留返回已有结果的时间；若基础检索本身未完成，
不能声称仍可提供一个尚未存在的结果池。并发 READ 退出时取消并等待所有子任务，避免执行权释放后继续调用模型。

历史 Turn 只自动迁移可证明一对一且正文一致的 Run 绑定。旧孤儿、多个 Turn 共用一个 Run、
正文或线程不一致的旧关联明确要求人工恢复，不能通过重新执行来猜测旧副作用是否发生。

## 部署边界

本轮没有升级业务库或替换运行中的容器。部署时必须先排空、停止旧 worker，再执行业务迁移和显式
checkpoint bootstrap，最后启动一致版本的 API/worker。`0035` 会将旧版没有 owner 证明的活跃 Run
及尚未确认的动作隔离为需人工处理；`0037` 将旧 best-effort 日志保守标为不完整，新恢复段不能清除旧不确定性。
历史已完成实验不按新价格重算，缺少实际收费尝试凭据的数据不能追认成可比较的新成本。

L-13 当前实现并不保证完整逐 attempt 重试账单：`max_attempts > 1` 一律不标为 KNOWN，
因为现有 RunStep 不能证明成功前的收费失败均已记录；fallback、辅助选择器或多 Run 场景也必须有
完整身份、用量和价格证明，否则为 `None / NOT_AVAILABLE`。单主模型、单次且用量完整的路径
保留准确计费，真库测试确认 `USD 0.00002000` 及每成功数据项成本指标，未削弱正向断言。
新 fallback 实验须通过 variant metadata 的 `fallback_pricing_snapshot_ids` 按链顺序提供价格快照；
服务端校验 workspace、provider/model、币种与内容身份，消费请求字段并冻结版本化全链投影。
既有缺失全链价格的 fallback variant 不会被静默补成 primary 单价。

C-08 的实际模型漂移检查依赖适配器暴露 `model_name`；生产 BGE 适配器具备该身份。
旧版本未冻结模型名以及没有身份的自定义适配器维持兼容，不据此宣称任意第三方组件都已防漂移。
MCP 使用可控网络后端证明请求字节和 bearer 发送前的校验顺序；上传使用受控 COMMIT 确认丢失
注入。未进行真实攻击网络、真实数据库断连崩溃或完整容器重启演练。

## 设计复核的契约边界

- LR-01：保留 `required=False` 的可选指标语义。整体 PASS 不代表每个可选 safety 指标有证据；缺失指标仍应显示 INCONCLUSIVE，不把它改造成伪 PASS。
- LR-02：未发现公开 API 改写已发布 DatasetVersion 的入口；不以本次修复暗示已拥有数据库管理员写入防护。维护脚本必须创建新版本，不能改写已发布 items；数据库维护权限与内容审计属于部署边界。
- LR-03：保留 refresh 重用撤销整个 family 的安全策略；补充真实 PostgreSQL 测试继续使用并发胜者 cookie 的结果，不为可用性删除重用检测。

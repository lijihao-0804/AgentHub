尚需完成：持久服务与来源资格的可信集成、生产调度及 checkpoint 固定 revision 恢复、可用来源的完整保护清单、真实业务路径和真实模型的端到端验证。当前已按 Run 和模型轮次持久化去重，但轮次仍需从真实 checkpoint 可信恢复并贯穿生产调度；在完成该集成前不能接入自动调度。固定候选失败后不得更换提示词重跑这四题；机械校验不是语义正确性的证明，缓存及净收益尚未验证。

持久服务子任务报告 14 项隔离 PostgreSQL 故障用例通过，覆盖先存派发意图、过期 lease、未知结果、保存响应后恢复、撤权和发布 CAS；主代理复验见下。默认可信验证器拒绝发布与派发，真实权限/来源验证、跨轮摘要复用和自动调度均未接通，不能将其报告为端到端生产验收。

主代理后续复验并修正了几个关键边界：同一租约不能重复越过派发边界；越界前重新核验权限、来源和已冻结请求；预留金额按数据库精度向上取整；供应商响应先按原始字节保存，再解析，格式错误、重复 JSON 键、无效 UTF-8 和截断输出也保留响应及费用，不能发布。供应商返回的模型不符时同样保留响应，拒绝发布，并把实际计价标为未知。针对同一 Thread 的并发摘要发布还增加了串行化保护，避免多个初始版本同时成为当前版本。可信服务可以预备精确请求，新增的显式 worker 会执行一次经过预算准入的已冻结主模型调用，并在响应落库后校验；它不会自动发布，也不会在未知结果后重试或切换模型。隔离库与 fake gateway 已验证正常响应和未知结果路径。

新增的来源资格记录仅允许管理员复核完成的历史来源；来源内容或管理员权限变化时停止复用，有工具结果、artifact 或检索证据的来源保守地保持原文。默认的 `DenyAllSummaryBindingVerifier` 仍拒绝生产派发，来源审阅本身并不等于受保护事实完整，也尚未和 worker 自动集成。隔离 PostgreSQL 上 0041→0042 升级及摘要迁移、持久服务、来源、资格四组 **44 项**通过，另有 **2 项**会话删除回归通过；这些测试使用 fake gateway，并不证明供应商端到端或业务 worker 已就绪。业务数据库未操作。

由于候选质量门槛未通过，发布预检和发布入口现对包含摘要策略的新配置返回 `SUMMARY_QUALITY_GATE_NOT_MET`（422）；没有摘要策略的历史行为不变。schema 5 的冻结/读取契约保留用于研究和兼容，但这不代表已启用摘要，也不能绕过后续质量及预算验收。预检与发布入口均有回归验证。

摘要审阅和 job 属于不可变留存证据，有该证据的 Thread 目前不允许删除；服务会明确返回 `SUMMARY_EVIDENCE_RETAINED`（409），而不是暴露数据库异常。无相关证据的普通 Thread 仍可删除。这是当前留存规则的明确产品限制，后续如需合法删除或保留期限，须另行设计审计与权限契约。

真实供应商的摘要输入计数比项目估算高约 19%–20%；前两次实际输入加输出预留已超本实验声明的窗口。后续使用 DeepSeek 同型号公开 tokenizer 离线计数，四次正文计数与服务商输入之差均为 30，但这不能推广为任意请求的固定余量。当前 `approx_language_v1` 是启发式估算而不是已经验证的模型 tokenizer 上界，现有检查不能证明真实请求绝对不超窗；生产摘要应保持关闭，直到具备经验证的模型计数或安全准入机制。

使用同一公开模型版本的完整消息编码器加 tokenizer 后，四次摘要与两次合成诊断共六次本地计数均与供应商输入实测一致。这给出了可行的模型适配方向，但现有产品尚未绑定该编码器版本、思考模式及部署路由，也没有证明工具、图片、fallback 或供应商模板变更下的计数；因此不能替换旧版冻结计数器或解除生产门槛。

已新增仅供研究使用的 DeepSeek V4.1 纯文本计数器：限定为首条可选 system 加一条或多条 user 消息，明确绑定 tokenizer 数据版本、思考模式和努力程度，拒绝工具、图片、assistant 历史以及特殊控制标记；不执行下载的编码器代码。离线测试覆盖六条已观测供应商请求和不支持的输入。该计数器不会进入产品 runtime，也不会自动判断兼容网关使用了相同模板；缺少本地固定 tokenizer 数据时，相关实测对照会跳过而不是假装通过。

摘要服务现在在响应已持久化之后核对实际输入、输出与同次 dispatch 的预留；缺少可确认用量、实际用量超出预留、报告费用超过预留或币种不符，都拒绝生成可发布产物。原始响应、已报告费用与预留仍保留，不能把已经发生的超支当作未发生。隔离库故障用例覆盖以上五类及正常恢复；该事后检查无法阻止首次超预算派发。

进一步复核发现，原先的摘要 dispatch 只写入单 job 的预估价格，并未真正从 Run 或 Workspace 共享额度扣留资金。现新增同事务的共享额度预留接口，默认实现一律拒绝；即使调用方注入可信来源验证器，没有真正的共享额度实现时也不能越过派发边界。隔离库测试使用明确标注的测试桩，并验证预算拒绝会回滚同事务修改和 dispatch；**项目目前尚未接通生产共享额度实现，不能宣称整体费用上限已得到控制**。本次 QMSum 试验另有独立单进程预算账本，两者不可混为一谈。

此前一次定向回归共 **226 项通过**，涵盖 M4 单元、研究协议、预算客户端、摘要迁移/服务/资格/来源，以及受影响的 M2/M3 策略和历史运行时；数据库用例只使用已命名的隔离 PostgreSQL。相关文件的 Ruff 检查通过。Alembic 配置仍有既存的 `path_separator` 弃用提示，不影响本次结果。该回归不替代上述缺失的端到端验收。

补充验证：摘要响应必须先通过实际的派发边界，不能凭意图记录直接保存；响应截断且用量或费用超出预留时，校验结果同时保留各项失败原因。隔离 PostgreSQL 定向测试覆盖这两个边界，测试桩不代表生产共享预算已经接通。

研究脚本现在要求新发出的正式 M4 纯文本请求使用固定版本的本地模型计数器，在派发前核对完整消息和声明的输入窗口；账本对每次尝试按 32768 输入 token 保守预留，恢复旧结果时不会重新调用供应商。实测响应与派发前计数不符时停止后续派发。该计数器仅覆盖受限格式，不能证明产品端、其他网关模板或未来模型的通用准确性。

进一步修正摘要机械校验中的数字子串误判：来源和摘要必须包含独立的数字表示，不能把 `1000`、`-100`、`100.5` 或科学计数法中的片段当作 `100`。相关 31 项定向单测通过。此检查仍只是保守词面约束，不能证明金额的语义、单位、条件或上下文正确；质量门槛继续关闭。

受保护原文审阅组件已加入：它以真实冻结来源和稳定内容身份重建精确摘录，审阅人、权限断言和 revision 留在服务端，不放入模型提示。已在隔离 PostgreSQL 中用真实 M3 来源和既有资格记录完成一次重建验证；复核还增加了冻结来源明确不可摘要、额外未审阅消息、超量清单以及每个被引用来源必须实际包含对应原文的拒绝检查。对应的审阅与机械校验单元测试共 58 项通过，隔离库集成测试 1 项通过。该组件尚未持久化保护清单，也没有接入实际权限复核、共享预算、运行时调度和质量门槛，不代表生产摘要已经验收。

摘要 job 现在按 Workspace、触发 Run 和模型轮次约束唯一性；重复投递同一身份幂等，不同身份争用相同轮次时拒绝。旧 job 没有轮次时，其所在 Run 不接收新的摘要 job，避免把无法确认的历史派发当成新边界。数据库也禁止改写父版本和清除已保存的 dispatch、response、artifact 指针；存在留存证据时禁止回退掉这些保护或轮次身份。隔离 PostgreSQL 已升级至 0044 并通过针对性迁移、并发和故障测试；迁移版本断言更新后单独复测通过。当前模型轮次仍由可信调用方提供，尚未与真实 checkpoint 调度绑定；共享预算和生产 worker 恢复仍未接通。

供应商返回后，超出数据库可表示范围的用量或金额会标为未知或无效并保留正文；已报告但无效的费用不能生成可发布摘要。预留计价按普通输入与缓存输入中的较高单价计算，仍是冻结价格下的保守估算，不是供应商账单。

摘要 worker 的租约现在在提交派发意图前按冻结的模型超时加保留余量续期，并在调用边界执行该超时。续期失败不预留或派发；超时、取消及供应商异常维持 `UNKNOWN_OUTCOME`，不切换模型或重发。隔离 PostgreSQL 中模拟了允许 300 秒的模型调用，在网关入口核对租约剩余时间并验证正常与未知两条路径；另有单元测试验证超时、取消和不合法超时。这个改动不保证任何耗时情况下都能收到响应：超过租约的迟到响应目前仍被拒绝，尚无独立迟到响应留存及对账流程，不能把未知状态视为已知费用。

进一步修正了等待数据库锁时沿用旧时钟的问题：任务相关的租约判断在取得行锁后计时；来源复核、预算预留和发布前的长等待后再次检查，过期时回滚同事务修改。隔离库注入了行锁等待、预算事务内过期以及派发和发布复核时过期，确认不会以过期租约继续派发或发布，预算事务也会回滚。此次摘要服务与 worker 定向回归共 76 项通过。数据库状态与远端请求之间仍不存在分布式原子提交，不能据此声称外部调用 exactly-once。

响应保存阶段也在等待派发行锁后重新核验租约；若此时已过期，保留预留并进入未知状态。对应的新故障注入与正常保存、既有过期恢复测试共 3 项通过；迟到响应留存和对账仍是上段所述的未完成事项。

运行时现将当前 Run、版本、冻结历史来源和规划的绑定写入 LangGraph 状态，在再次调用模型及审批恢复执行动作前核对数据库中的冻结内容。历史规划变更时停止继续执行；原有未带绑定的 M3 checkpoint 保持兼容。隔离 PostgreSQL 和模拟网关验证了正常审批、规划变更时不执行动作，以及后续对话读取完整工具交换。另修复 asyncpg 返回的 UUID 子类型导致已完成工具对话无法保存的问题，在持久化边界转换为标准 UUID。

该检查绑定的是 checkpoint 中的历史状态，不是将摘要任务绑定到具体 LangGraph checkpoint ID；旧状态缺少绑定时仍沿用旧行为。摘要生产调度、可信来源权限和质量门槛仍未完成，此处不能作为自动摘要可用的证明。

进一步收紧了兼容恢复：缺少历史绑定的 Thread checkpoint 须核验数据库中的冻结版本；启用摘要的版本不能借缺失的 checkpoint 配置冒充旧 M3。审批恢复固定使用已经核验的 LangGraph checkpoint ID 和 namespace，启动恢复前如果发现最新 checkpoint 已改变则停止，不执行审批动作。隔离 PostgreSQL 中验证了正常恢复、历史变更拒绝及在恢复前插入新 checkpoint 时不创建 Ticket；旧 M3 不含摘要策略的 checkpoint 仍可恢复。此保护没有把摘要 job 绑定到精确 checkpoint，也不构成框架表被外部进程直接删除或改写时的分布式原子保证。

模型网关的用量归一化现在拒绝将布尔值、非整数或负数当作 token 数；无效缓存数记为未知，核心用量与提供的总量矛盾时不使用该份统计。流式场景里，后续出现畸形用量会清除之前的用量及成本估算，而不是把过时值当最终统计；正常缺省总量可按输入与输出相加。适配器、网关和契约定向回归通过。该处理不证明任一供应商真实缓存命中或最终账单，也不意味着共享预算已经接入完整主备链路。

# AgentHub Memory M3：历史来源冻结与确定性上下文规划

日期：2026-10-27。基线为 M2 `dedb323`。本阶段实现一个显式发布的 `deterministic_history_v1`，只有同时启用 `adaptive_context_v1` 的新 schema 4 版本采用；既有 schema 1、2、3 不自动改变。未部署、未修改业务数据库或现有 Agent 的默认版本。

## 机制

线程历史通过既有 Thread/Run 来源读取。首次读取在单一 PostgreSQL REPEATABLE READ 只读快照中冻结租户、线程、当前 Run、序号上界及来源 ID，按有界 keyset 分页；同 Run 的竞争准备只安装一份来源清单和计划。恢复只读原清单并验证已选内容身份，后续才完成的旧轮次不会进入既定视图。单次最多 200 个完整 Turn、扫描最多 2,000 个 Turn 和 5,000 个 artifact；达到上限时明确不足，不以截取部分的 token 数声称测量完整历史。成功状态缺失输出、绑定异常或无法证明的旧来源同样不会静默忽略。

纯计划器使用 M2 的冻结输入预算和计数器，裁剪前计算来源及必须内容的 N，预计增长 G 单独计算；70/85/55 使用整数边界。必须内容和工具定义、Memory、历史共享同一输入预算。没有可信摘要时，不做语义压缩；不确定资格的旧材料保持原样或明确不足。计划与最后实际准入不一致、重要历史或 Memory 被改变、硬压力仍未解除时，在模型派发前拒绝。一个离线机制用例中 12 轮、每轮 2,000 单位超出 32K 的 70% 阈值，而先截最近 10 轮会隐藏该压力；这是机制回归，不是业务质量分数。

启用 M3 的新 Run 保留当前轮的完整模型可见轨迹，Run 成功与轨迹、紧凑 RAG 证据的私有注册表在同一数据库事务写入。恢复时检查工具调用与结果完整配对，并为不同历史 Turn 的协议 call ID 重新命名以避免冲突；原内容与来源仍可追溯。历史紧凑 RAG 引文使用按 Run 隔离的标识，必须通过记录/引用成对验证、历史与当前冻结知识快照一致、当前权限、数据库快照完整性及分块实际成员检查；权限在后续模型派发前重新核查。引用碰撞、快照改变、无权限、旧记录缺少完整工具轨迹、结果被截断或旧非紧凑 RAG 引用缺少可证明来源时明确拒绝，不伪造恢复。

历史 Wiki 派生证据暂未开放恢复，因其发布绑定及撤销语义需要单独验证；遇到该类型时明确返回不足。当前运行时不选择已发布的摘要候选，计划器只在受信验证器显式确认后才允许摘要，尚未实现 M4 语义摘要与其质量验收。来源和业务内容不进入新增 trace；私有轨迹及来源注册表存放在现有隔离租户数据库行中。

对来源和 artifact 还分别设置 8 MiB 物化上限：数据库先测量将被载入的文本与 JSON，超限明确报告不足，artifact 分页只扫描 ID 和时间，不先读取大正文。历史兼容路径和搜索也要求 Thread、Turn、Run 及输入绑定一致，避免损坏的跨线程关联混入结果。限制是有意保守的工作上限，不代表模型窗口或产品支持的最大正文长度。

## 数据库与模型调用

本阶段显式新增 0038（来源/计划快照）、0039（完整当前轮轨迹）、0040（私有 RAG 注册表）迁移；只在本机独立测试数据库升级并检查，部署仍需在正式环境由部署流程执行。M3 未发起任何业务供应商模型调用；fake provider 的请求用于验证真实运行时内容。模型窗口和 token 数仍由 M2 冻结能力与近似计数器约束，不宣称已验证更大的供应商窗口。

## 验证

首轮整合回归 396 项通过、1 条 Alembic 弃用警告，覆盖 M1/M2、分页、运行时和流式预算。其后补充真实数据库中的 RAG 成员与权限、两个连续 RAG Turn 引用不串、工具结果事务失败注入、权限中途撤销、PostgreSQL checkpoint 的审批恢复和后续工具回放；统一回归首轮为 433 通过、1 项 fixture 收集错误；原因是跨模块收集时测试依赖的共享 fixture 未注册，改为测试本地 fixture 后复验 **434 通过、0 失败、0 跳过，退出码 0**，有 3 条现有 Alembic 配置弃用警告。首轮和修复后的 JUnit 与输出保存在 `evidence/context-policy-m3-20261027/`。独立审查提出的水位、摘要覆盖/净收益、计数器绑定、来源完整性及缺失成功输出问题已按定向测试修正。语义摘要质量、真实用户回答质量、延迟/费用净收益均未在 M3 评测，不能以测试数量替代它们。

后续扩大旧模块回归时，`test_concurrent_prepare_creates_one_run_and_one_stable_binding` 曾出现 `uq_agent_runs_thread_turn` 唯一约束异常。已增加 Turn 归属及输入验证、行锁和约束冲突后的安全收敛；不属于目标约束的数据库异常仍向上传播。历史兼容读取和搜索验证 Thread、Turn、Run、输入和反向关联，损坏关联不会返回另一条线程的输出。

审批恢复现在以原 Run 创建者的当前权限执行，核验 checkpoint 的待处理审批；权限被撤销时不会执行新动作。动作 claim 前及外部执行前再次检查权限；claim 后撤权会停止执行并保留待核对状态。恢复异常和未知动作结果收敛为需要关注，未知结果不会静默重试。FINISH 记录与 Run 终态在同一事务提交，覆盖提交失败及重启恢复；这些是本次相关故障路径的验证，不宣称消除了所有并发撤权窗口或外部系统的不确定性。

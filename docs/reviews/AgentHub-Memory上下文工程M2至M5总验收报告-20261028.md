## 本轮审阅与边界

受保护审阅现在持久化来源、审阅版本和原文摘录坐标；重建时检查当前权限、来源版本及固定审阅。业务原文不作为审阅表内容存储。`c739132` 的摘要任务在创建、派发、校验和发布阶段绑定同一 checkpoint 和模型轮次；运行中的工具交换、取消及不合适的终止状态不能被当作可派发边界。真实 LangGraph checkpoint 已在隔离 PostgreSQL 验证，审阅服务的集成案例使用明确标注的合成 checkpoint 和计划。

审阅不能覆盖历史规划：仅冻结计划明确标注 OPTIONAL 且 ELIGIBLE 的来源可由审阅验证器放行，RECENT 与 KEEP_EXACT 不可压缩。当前生产历史规划仍将历史分为 RECENT 和 KEEP_EXACT、资格为 UNKNOWN，审阅全部来源也不会打开自动摘要；后续必须设计可信的前缀选择与版本绑定，不能将测试桩当作生产支持。审阅人的完整性声明是人工声明，不是自动证明未漏事实、动作或引用。

修复审阅验证在发布持锁时通过第二个事务读取导致的自锁，并以隔离 PostgreSQL 模拟已有 Thread 锁验证；完整问答的输入角色现在表述为 exchange，内部保持 USER/ASSISTANT 区分。上述行为并不证明摘要生成质量或业务净收益。

精确读取 checkpoint 只证明该历史位置存在且与冻结历史一致，并未证明运行仍停在该位置；当前缺少与调度/运行推进原子协调的最新边界占有协议。因此不能以这些检查宣称异步摘要可安全自动投递或恢复。

审阅的来源资格修订与受保护审阅现放在同一事务；非法摘录等失败不会留下部分资格修订，也不会令先前有效审阅无故失效。隔离 PostgreSQL 覆盖失败回滚、并发审阅修订、权限撤销及持锁验证。

隔离 PostgreSQL 的服务集成已走通受保护审阅 → job → Run 账本预留 → 派发围栏 → 保存受控模型响应 → 校验 → 发布，验证发布时已有 Thread 行锁不自锁。这个测试使用合成 eligible 计划、checkpoint 读取器、价格和模型响应；并非真实 LangGraph 调度或跨 Run 消费已发布摘要的证据，不能据此解除生产门槛。

## 配对与核算方法

产品比较基于 `deb28ec`。64 道全新双语题在候选定版及付费生成前冻结，中文和英文各有 16 道可答和 16 道应拒。每题两份原文分别经过真实上传、worker 入库、BGE-M3 索引与 Qdrant 检索、重排和选段。核验了 128 篇原文的全部可见字符，15 道可答题需要组合两份材料。新问题和原文与已检查的 339 个历史问题及 802 段历史证据没有归一化精确重复。此组为新编短文，不能代表所有线上问题。[独立题及金标](../../benchmarks/retrieval/experiments/first_refusal_contract/fixtures/fresh.jsonl)

固定北京 `deepseek-v4.1-flash-1017`、温度 0、输出上限 2,048。每份输入都两次进入 `POST /api/v1/knowledge/query` 的真实 FastAPI 应用，轮换两臂先后顺序。固定检索结果后，对完全相同的首个模型请求只真实发送一次阿里云，两臂各自处理同一已确认回复并决定是否纠正。相同的纠正请求也复用已确认回执。这样可将差异归因到问答契约，同时避免模型另一次采样改变答案。报告中的“首答”指接口能从第一次返回中正确交付，模型本身生成的原始字串对两臂完全相同。在线组与零付费历史回放分别出数。[冻结门槛](../../benchmarks/retrieval/experiments/first_refusal_contract/protocol.md) · [冻结代码、消息和输入指纹](../../benchmarks/retrieval/experiments/first_refusal_contract/registration.json)

严格正确要求接口状态、答案要点、语言和引文都符合要求。正确拒答以全部应拒题为分母，实答的引文支持率以有效实答为分母，同时按可答子集检查实答是否被错误转换为拒答。首轮失败和 HTTP 错误保留在正确率分母。盲审只展示问题、金标、答复及实际定位的引文，首答读取送模证据，最终读取接口返回的 excerpt。复用历史判断时同时校验题面、金标、回答、引文内容、出处和位置的指纹。语义审核由项目内 AI 评审完成。

中文两臂首答均为 18/32，英文均为 21/32。每种语言均有 5/16 个正确首答拒答、11 次纠正。三道最终未严格通过的实答两臂相同，包括两处引文无法支持的附加断言，以及净邮资与补贴金额混淆。没有一条有依据的实答被候选误改为拒答。

7 份点名输入重新生成时，两臂均首答通过 3/7，最终通过 7/7。R092 和 B006 均首答正确。N035、罗马尼亚总理题、B097 和 W13 的一份输入都仍需第二次调用，另一份 W13 首次直接正确拒答。可见同一模型对固定问题和证据可产生不同措辞，五份旧输出上的命中没有转化为在线收益。

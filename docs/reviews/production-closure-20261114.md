# 交互预算、客服与记忆恢复验收

本轮从本地 `main` 的 `e88eae0` 开始。验收围绕用户可观察的结果展开，覆盖金额上限是否真的阻止调用、客服是否实际发起建单、历史请求是否能够重建，以及提取进程死亡后能否安全恢复。

## 案例金额预算

正式实验 Worker 对所有带 `max_cost_cny` 的交互项及变体执行预检，并在每个物理模型请求前持久化跨轮共享的预留额。账户、审批权限、租约、路由、定价快照、实际消息范围中任一约束不满足时，运行记录说明拒绝原因。重复投递同一任务或使用普通会话入口，均不能重复派发已预留的尝试。

真实 PostgreSQL 测试使用本地模拟供应商。在可资助两轮、仅可资助一轮两种情况下，供应商分别收到两次、一次调用；不匹配的部署合同使包含多个案例的计划在首次调用前失败。另有预留提交后租约失效、模型超时、响应证据写入失败等注入测试；结果不明时保留占款，AgentRun 进入 `NEEDS_ATTENTION`。案例详情可读取上限、未结算占款、账单结算和可用余额。合成发票行并发分配测试只允许一个尝试结算，相同分配重放保持幂等。[部署与对账命令](../deployment/case-budgets.md) · [正式 Worker 测试](../../tests/integration/test_case_budget_worker.py) · [并发账单测试](../../tests/integration/test_case_budget_bill_import.py)

目前支持有可信计费合同的单案例、单模型、一次尝试、同步文本生成。含收费辅助路径、工具、judge、摘要、流式或回退的硬限额任务会被拒绝。真实账号的合同需要核实失败请求的计费上界、地域、价格和消息包装开销。客服实测沿用独立研究账本；没有把经验 token 数或公开费率当成真实账号的完整计费证明。

## 客服行为及证据

`query_customer` 过去只取前 20 张未结工单，缺少完整性信息。现在可先按准确主题过滤，再返回至多 20 项并标记结果是否完整。客服模板要求先核实条件，满足建单条件时实际调用建单工具；审批决定和执行结果分别说明。客服会话另从已落库的 `create_ticket` 审批读取回执；已完成但没有申请记录的轮次会明确显示这一点。Viewer 可以读取决定和执行状态，业务正文继续脱敏。[查询实现](../../packages/tools/builtins/query_customer.py) · [模板](../../packages/agent_templates/support.py) · [会话接口](../api-contracts.md#support-ticket-requests-in-conversation-history)

两轮 DEV 均在首次模型调用前冻结材料，以独立合成账号运行阿里云 `deepseek-v4.1-flash-1017`，用 PostgreSQL 的审批和工单记录验证模型的动作。

## 历史 token 与 Memory 崩溃边界

QMSum 固定上游版本、六份会议文件和训练清单可重建原来的四条摘要请求。相同输入分别对上了历史供应商观测的 30,952、31,203、28,927 和 28,720 个输入 token。CI 现在会准备并校验固定资产；新下载和已有本地副本都要通过内容校验。该复验未再次调用模型。[重建步骤及来源](evidence/context-policy-m4-20261027/qmsum-preparation.md)

迁移 `0054_memory_provider_handoff` 让每次 Memory 提取领取都有所有者标识，并在供应商适配器可被调用前提交交接标记。交接前的孤立任务可重领；交接后没有候选结果的任务保留未知状态；已有候选只重做落库。旧版 RUNNING 行保守处理。PostgreSQL 回归分别终止真实子进程和持锁连接，验证旧执行者无法写回或重复调用。上线顺序为先执行数据库迁移，再更新 Worker。[迁移](../../migrations/versions/0054_memory_provider_handoff.py) · [故障注入与结果](R1-memory-extraction-outcomes-20261106.md)

## 综合回归

在全新 PostgreSQL 16.15 实例上显式迁移并初始化 checkpoint。完整 `tests/unit` 与 25 个数据库集成文件在同一次执行中 **3,482 项通过、0 跳过、32 条警告**，pytest 退出码 0，`alembic check` 通过。集成文件覆盖预算、真实权限的证据读取、交互环境恢复、查询工具、会话、Memory、审批与 checkpoint 恢复。首轮组合测试发现一个旧测试替身没有新的 Worker 配置字段，改用应用的 `Settings` 后完成复测。并发账单的命令行重放、两份历史提示词的空库重建另做定向验证。各定向套件与综合套件存在重叠。[本地验收计数和退出码](evidence/production-closure-20261114/regressions.json)

前端 8 组回归通过，Next.js 生产构建完成类型检查并生成 24 个静态页面。Ruff 检查通过。以上结果来自本地隔离环境，远端 CI、线上数据库迁移和生产部署不在本次验收范围。

真实 Edge 在本地合成 API 上验证了客服三种回执、Viewer 内容脱敏，以及案例详情分别展示 10 元上限、3.25 元预留、2.125 元结算、4.625 元可用和独立的 0.125 元计价估算。首次检查发现运行详情页冷启动短暂预取不存在的 `/evaluations/runs` 索引；修复后新浏览器会话的 49 个 HTTP 请求（含 14 个预取）没有 4xx/5xx，点击面包屑到达该 Run 所属实验。

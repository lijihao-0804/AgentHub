## HTTP/SSE 与 provider 清理

复用实际 API 路由，在独占本机 TCP 端口验证了三条路径：
断线后同服务重连、由另一服务实例读取持久事件、超过 0.5 秒宽限期无人重连。
最终 3/3 满足预期：前两条 SUCCEEDED 且模型只启动一次；最后一条
FAILED / AGENT_STREAM_CANCELLED，并关闭受控 provider。
delta 按原契约不持久化，重连得到结构/完成事件，最终正文从 Run 读取。
注入的是隔离身份，不能称登录安全测试；两个服务实例在同进程，不冒充 OS 重启。

发现并修复实际缺陷：LiteLLM 适配器流提前关闭时，没有显式关闭底层迭代器。
新增失败复现后，在正常、异常和提前关闭路径执行底层 aclose/close，
清理异常只记录异常类型，不暴露 SDK 原始异常内容或覆盖原先的取消错误。
相关回归 59 项通过，流式账本两项通过；未知流费用保留全额预留并停止本进程新调用。

原始首次探针权限不足、第二次提前读终态造成的失败均保留。
修正的是隔离身份和探针断言，没有放宽产品权限或状态语义。

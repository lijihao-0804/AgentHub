```json
{"raw_observation_keys":["prompt","private_facts","raw_arguments"],"private_sentinel_survives":true}
```

所需回归：在真实列表 HTTP 响应中递归放入 sentinel，分别以 Viewer 与管理用户请求，断言不符合内容策略的原文不出现；继续验证分页、摘要、task_success、旧版本兼容和跨 Workspace 拒绝。已有详情 sentinel 测试保留。

## 2. P2：token 自动刷新后，失败筛选的 UI 与请求条件不一致

位置：[run-case-evidence.tsx:352](<E:/JAVA/AI+agent/AgentHub/.worktrees/ae1/.agents/worktrees/codex/ae10-minimal-evaluation-ui/apps/web/components/evaluation/run-case-evidence.tsx:352>)。

effect 依赖 accessToken，每次凭据变化执行 `loadFirstPage("")`，但没有同步重置 statusFilter。会话 provider 的 [renewAccessToken](<E:/JAVA/AI+agent/AgentHub/.worktrees/ae1/.agents/worktrees/codex/ae10-minimal-evaluation-ui/apps/web/components/providers/session-provider.tsx:220>) 正常刷新 accessToken 时不增加 sessionId，因此外层 keyed component 不会重置内部筛选状态。

复现步骤：

1. 打开有成功和失败 case 的逐题列表。
2. 选择执行状态 FAILED。
3. 在同一 Workspace、同一 sessionId 中触发正常 access token 续期。
4. 列表重新请求全部状态，筛选框仍显示 FAILED，成功项进入“失败”列表；随后 Load more 又使用 FAILED 条件和已混入的列表长度作为 offset，可能进一步错页或漏项。

本轮复用仓库实际 TSX 测试 harness，在内存附加上述组合，没有修改源码或测试文件。结果：

```json
{
  "before":{"displayedFilter":"FAILED","requestFilter":"FAILED","containsUnfilteredSuccess":false},
  "after":{"displayedFilter":"FAILED","requestFilter":null,"containsUnfilteredSuccess":true}
}
```

这是本 PR 新增组件中的实际回归。现有“分页过期”和“会话切换”测试均通过，但没有覆盖“同一会话内 token 续期 + 已选筛选”这一组合。

建议修复：使筛选成为统一请求状态源，凭据续期继续使用当前筛选；或在重载全部数据时明确同步重置下拉框。不要单独追加依赖造成重复请求竞态。补齐 token 续期、筛选及分页一致性回归，并保留已有过期响应/租户隔离测试。

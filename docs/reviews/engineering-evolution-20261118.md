# 技术演进清单评估

评估基线为 `ab2b5b0`。清单包含 17 条 Memory/Wiki、15 条 RAG、15 条运行与平台条目。当前用户场景是单机知识工作区，需要可靠地入库、持续看见处理进度，并能从一条回答引文追溯两段原文。工程修复与问答策略采用独立分支和合并条件。

| 条目 | 本轮判断与依赖 |
|---|---|
| RG15 | 修复。文档和修订单独存在，仍可能被错误组合。用真实 PostgreSQL 强制同工作区、知识库、文档和修订四者配对。升级遇到已有错配应给出可核查记录并中止。 |
| RT08、RT09 | 修复。先在原子领取中消耗有限执行次数，再把失租信号传到解析、编码和写入批次。最终数据库提交须验证持有者；远端已收的写入仍需按稳定身份重投和对账。 |
| RT10 | 修复。展开详情可能在列表显示完成后仍停在旧阶段。按列表及所选修订的实际状态决定轮询，后台标签页不发查询，关闭或到达终态时结束。独立于数据库迁移和 RAG 提示。 |
| RG06、RG10、RG11 | 当前六段问答实验。先定义双块引用和区间，再测实际模型消息与读者可见引文，最后在新题与曾成功的旧题上决定默认。此处的实验审计仅覆盖知识问答路径。 |
| RG02、RG03、RG04 | 修订级切块与精确向量复用已有产品和实验。稀疏路线实际采用分词、词频权重与索引 IDF。模型比较独立测量，改编码器须另建索引并处理输入配置与缓存身份。 |
| RG01、RG05、RG07 | 扫描件自动编排需要原始扫描件到最终引用的验收；双路并发和降级需验证取消、超时及各路贡献；预算须用实发输入和模型窗口校准。本轮保留现行入库和计数策略。 |
| RG08、RG09 | 通用 Agent 的严格引文和逐结论支持依赖工具输出、流式交付和证据登记。此次只对有确定合同的知识问答验收，不能据其成绩改变所有 Agent。 |
| RG12、RG13、RG14 | 重复上传是否必须生成新修订、冷存储期限及历史元数据的含义涉及产品合同。保留当前修订身份和快照引用，等待重试标识、保留期限或历史重现要求。 |
| MW01、MW17 | 已发布版本与新建私有记忆各有既定语义。扩大整条 Thread/Run/产物的私有范围需先确认团队协作权限模型。 |
| MW11 → MW03 → MW04 → MW02、MW07 | 值得独立的记忆质量实验。先准备该写/不该写、原话支持、条件变化、误召和最终使用的标注，再验证替换链和同义召回。当前自然知识问答集没有这些标签，不能充当记忆门槛。 |
| MW05、MW06、MW08、MW09、MW10 | TTL 和撤销依赖保留承诺，模型预算依赖计量校准，工具历史压缩与跨轮检索依赖权限、安全摘要及长期对话标注。原始运行记录保持可解释。 |
| MW12、MW15、MW16 | Wiki 现有页面匹配以标题为主。需要固定编译版本、claim、条件冲突和来源撤销对照，才能判断正文召回、冲突处理和路由收益。维护过程不要改变已发布绑定。 |
| MW13、MW14 | 已有编译缓存。按变更率和编译成本决定更细增量，自动产生待审核更新还需明确发布责任。 |
| RT01、RT04、RT02 | Run 受理标识与持久派发共同解决首帧前断线/提交后未发出的窗口，随后才适合统一后台审批恢复。需单独验证跨进程重启、重复派发和外部动作重入；当前知识入库修复不能覆盖这些窗口。 |
| RT05、RT06、RT07、RT03 | 先定义持久终态与终止事件的一致性，再统一客户端断流后的权威回读。跨进程实时 delta 还需真实消费者、延迟指标及保留期。 |
| RT11、RT12、RT13、RT14、RT15 | 新节点共享文件、异地备份与索引恢复需明确拓扑、目标和存储范围。活性监测需验证任务实际推进。外部结果核对依赖每个工具的业务状态查询与授权；已知结果未知时继续保护既有动作。 |

本轮验收分别覆盖真实 SQL 配对、入库故障窗口、修订页面的终态收敛及双块引文。学习归档、线上部署、生产数据和未得到验证的策略默认值各自保留原有管理流程。

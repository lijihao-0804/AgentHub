# Memory M4：受保护来源可信审阅缺口

日期：2026-10-28。本文记录生产接入前仍待实现的条件，不是新的已上线权限机制。

当前 `summary_review_manifest.py` 能从冻结来源重建精确摘录，但审阅者身份、管理员身份、审阅 revision 和“清单完整”均是调用方断言。现有测试能够证明坐标和来源的校验行为，不能证明这些断言代表真实权限或人类已经识别了所有关键事实。`SummaryEligibilityService` 会读取当前权限和来源资格，但该资格与受保护事实清单是两种不同判断；纯 builder 也没有接入真实 worker。默认可信验证器和质量门槛继续拒绝自动摘要发布。

后续接入应由服务器根据已认证主体持久化一份明确版本的审阅：记录 Thread、触发 Run、冻结来源范围、精确来源与摘录坐标、审阅者及审阅依据。使用前从权威来源重建摘录，在派发、响应校验和发布各阶段重新核对来源和当前权限；恢复时读取 job 绑定的精确审阅版本，而不是重新选择最新清单。来源身份或内容的一致性信息只能帮助核对来源，不能代替授权检查。审阅记录只能证明某人确认过特定清单，不能证明自然语言中的关键事实必然没有遗漏。

Organization 和 Workspace 是不同的权限层。现有资格检查按当前角色复核，撤权后重新授权时旧审阅是否可以恢复有效，仍需要在权限契约中明确并做实际回归，不能由 builder 自行决定。新增审阅服务还必须与现有 eligibility、job、Thread 和发布流程约定一致的数据库锁序，验证竞争与回滚，避免把互相等待误当作可安全重试外部模型。

最低验收应覆盖真实隔离库中的来源变更、资格变更、跨租户、撤权、并发审阅、审阅后修改、固定 revision 恢复和发布前再次复核；provider 已返回时要保留已有响应与费用证据。调用方不能通过自报布尔值或提供某个身份字符串取得权限。直到完整链路及模型质量验收通过，不能解除 `DenyAllSummaryBindingVerifier` 或摘要发布质量门槛。

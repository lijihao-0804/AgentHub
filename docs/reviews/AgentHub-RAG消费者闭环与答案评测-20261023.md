# RAG 消费者闭环与答案评测验收

2026-10-23。本轮完成预算贯通这一项里程碑：修复检索结果进入模型前的二次截断，并首次在该链路上验证实际生成答案。没有更换 embedding/reranker、扩大工具全局上限或改业务索引。

**新 200 题冻结确认通过：答案 F1 27.92% → 39.39%，EM 20.00% → 31.50%。**主要收益来自让配置的 RAG 预算真正生效；仅对齐通用工具预算的对照也得到相近结果，不能把整体收益称为结构算法的独立突破。

## 1. 确认成绩

MuSiQue-Ans，指定题目提供的候选段落，含全部干扰项。官方 dev 中预定种子抽取 200 题，排除上一轮已查看的 300 个问题 ID；139 个共享支持原文的重采样组。不是全库检索或来源家族完全隔离的留出集。

| 方案 | 答案 token F1 | 答案 EM | 最终完整记录的证据召回 | 完整支持段落集 | 证据 payload bytes 均值 |
|---|---:|---:|---:|---:|---:|
| 旧路径，5 块，通用工具上限 4000 | 27.92% | 20.00% | 59.04% | 25.50% | 4000 |
| 旧路径，5 块，将通用工具上限也对齐到 8000 | 38.63% | 30.00% | 78.29% | 54.00% | 6241 |
| 冻结方案：5 块，RAG 专用预算、完整记录与配对引用 | **39.39%** | **31.50%** | **78.29%** | **54.00%** | 6294 |
| 无检索诊断 | 1.00% | 0.00% | — | — | — |
| 标准支持段落及原始标题，预算内诊断 | 62.83% | 48.00% | 100.00% | 100.00% | 3027 |

主比较只确认冻结方案对旧路径：F1 +11.47 个百分点，5000 次成对分组 bootstrap 的 95% 区间 **[+5.76, +17.69]**。全部 200 题保留，未因失败剔除样本；固定最小 F1 增益、区间为正、有效输出比例、未知结果及证据损失门槛均通过。没有按确认成绩重新选择方法。

冻结方案相对“仅预算对齐”仅 +0.76 个百分点，开发集则为 -0.54 个百分点。这是描述对照，没有进行等效性或额外显著性验证，**没有证据支持结构本身造成了全部收益**。工程上保留专用路径的理由是：不必给所有其它工具同步放大预算，并能在更紧预算下保留完整记录与匹配引用。

标准证据组只是离线诊断，不能部署为检索器，也不参与选择。其 F1 仍只有 62.83%，说明后续不能只追召回；还需要检查多跳推理、答案表达和文字匹配误差。EM/F1 使用官方答案及 aliases 的英文规范化与 Counter token 匹配；双方规范化后均为空有意记零，与官方 helper 的空值边界不同。引用只验证 ID 存在，不证明语义支持或 faithfulness。本轮 Ans 轨不评价不可回答识别。

## 2. 开发、冻结与成本

开发为原 train 样本 160 题、143 个组，在去除来源 ID 中任务标签后重新执行：

| 方案 | F1 | EM |
|---|---:|---:|
| 旧 5 块 | 35.90% | 26.25% |
| 仅预算对齐 | 45.42% | 33.75% |
| 完整记录 5 块 | 44.88% | 33.13% |
| 完整记录 10 块 | 48.37% | 36.25% |

两个候选对基线用 97.5% 分组区间校正开发比较。5 块方案 F1 增益区间 [+2.27,+16.04] 个百分点，10 块方案 [+5.39,+19.42]；两者通过，依预先规则优先冻结较轻的 5 块。10 块没有进行新的确认，不因开发均分高就改为默认。

相同上限不等于相同成本：确认主比较的证据 payload 均值 4000 → 6294 bytes。provider 报告的输入均值约 1654 → 2266 tokens；优化组有 1 次用量未知，不能按零计算。答案 API 的请求 P50 约 803 → 1021ms，P95 约 1992 → 2312ms。这是增量请求时间，排除了历史 BGE 计算、实际数据库、整个 Run 的调度与持久化，不是整体时延或 SLO 测量，也不是整体加速。

全部探索与确认实际共 2760 次请求，观测到 4,725,677 total tokens；24 次 provider 错误未返回用量，金额无定价快照。共 2708 VALID、28 INVALID_OUTPUT、24 PROVIDER_ERROR，未知结果 0。失败均保留且答案计零，未自动重试。详情见[完整机器验收](../../benchmarks/public_rag/results/consumer-rag-20261023/acceptance.json)。

## 3. 实际修复与适用方式

实际问题是两层预算没有贯通：`search_knowledge` 返回证据后，runtime 使用通用工具的 `max_tool_result_tokens=4000`，超限就转成截断的 JSON preview；更大的 RAG 预算无法补回已被截掉的内容。最终准入还要计算消息名称、工具调用 ID 等开销，否则接近上限的正文可能再次退化为单个标记。

新增路径仅在真实 builtin `search_knowledge`、成功结果、合法显式 `context_budget_bytes` 配置下启用：

- 使用该类别的 `max_retrieval_tokens`，其它工具仍受原通用工具预算控制。
- 按完整 record 与匹配 reference 成对选择，保留原顺序；超大记录跳过后尝试后续，不裁成半段 JSON，不编造引用。
- 强制 UNTRUSTED；缺失、重复或歧义引用失败关闭，不回落到包含原始坏数据的 preview。
- 最终 ContextBudgetPolicy 用自身 estimator 预留消息元数据，再对完整记录收紧预算；历史 truncated 标记保持透明。
- 模型准入后继续保存原始 ToolDefinition，provider 接收投影 schema，后续 observation 仍能读取冻结检索配置。

默认 5、最大 10、snippet 1000 字符不变；未配置预算、错误结果、非 RAG 工具保持旧路径。正常发布、模型能力、价格/费用、授权、快照与上下文守卫没有被移除。本次没有创建或修改业务 AgentVersion、模型档案、数据库或索引。

可应用的[显式配置](../../benchmarks/public_rag/consumer-presets-20261023.json)为检索 `final_top_k=5`、`context_budget_bytes=8000`，运行时 `max_retrieval_tokens=8000`，通用工具预算保持 4000。仍需正常选择知识范围、校准生产 relevance floor、使用已验证的模型能力并发布新版本；配置不会自动创建本实验的 paper/case 范围或标题结构。实验声明的 16k 上限不是 provider 容量认证。

## 4. 评分与修复过程的审计

本轮 v1 生成试跑中，MuSiQue 原生 chunk/locator ID 含有跳数标签，错误地进入了模型消息。该问题由主代理审阅发现，来源 ID 已改为固定宽度的 UUID，locator 不再携带题目 ID，实际消息逐项验证无任务标签。**v1 的来源型试跑不用于方法选择或确认**，原始调用和用量完整保留；先前纯 BGE 检索评分未把这些 ID 作为模型文本，因此不受这一生成适配错误影响。

干净开发的 960 个预备消息输入与新确认的 1000 个输入均通过标签泄漏检查。开发的无检索输入与 v1 完全相同，160 条已有结果仅复用为诊断，没有重复调用；800 条干净来源型开发请求重新执行。

v1 首次执行在 99 条结果后遇到 HTTP400 停下，同时已有 1 条无效输出。后续只发送剩余 861 个未尝试的题目/方案组合，两个事件账本交集为零，失败仍计零。HTTP400 原因未知，没有改写内容规避拒绝；未知结果、错误模型或其它 provider 错误会停止，不能静默重试。一次 QASPER CPU 回放因旧记录缺少 hops 字段失败，改为可选字段后使用新输出目录完成，原日志保留。

模型固定请求 `deepseek-v4.1-flash-1017`，禁用 thinking，JSON object，单次请求、无切换；所有有效响应校验返回模型名。85 项分组定向用例分别通过，覆盖预算、引用、模型节点元数据、旧路径、标签泄漏、计分、防重发及既有冻结/流式行为；不是一次全套测试，也不把单元 PASS 当成 RAG 分数。最终 Ruff 和差异检查通过，没有新增哈希测试。[检查记录](../../benchmarks/public_rag/results/consumer-rag-20261023/parent-validation.json)。

## 5. 真实消费者暴露的下一处瓶颈

QASPER 已暴露的 dev 全部 1005 题只做结构回放，854 题证据可评分；保留 60 不可回答、91 未对齐。最终可恢复完整记录的召回从 37.55% → 64.83%，完整集从 32.32% → 57.49%；只对齐旧预算为 63.21% /55.85%。没有新增 QASPER 答案成绩。这些不是此前约 12 段小记录预算填充的 84.39% 召回口径。

| 5 块消费者路径 | 有效题数 | 候选池已缺完整支持 | 池内齐备但检索输出未齐备 | 工具返回齐备后又被投影丢失 |
|---|---:|---:|---:|---:|
| 新 MuSiQue 确认 | 200 | 5 | **87** | 0 |
| QASPER 暴露回放 | 854 | 135 | **226** | 2 |

这是确认后的描述诊断，不参与本次选择。此前“QASPER 优先补候选”的判断针对较宽的离线填充口径；换成真实 5 块消费者后，数量与包装预算让下游选择重新成为主要损失，不能照搬原优先级。

新确认四跳只有 27 题：冻结方案 F1 30.04%、EM 25.93%，完整支持集仅 11.11%；分层只作描述，不宣布解决四跳，也不能同之前不同的 50 题样本直接作差。

下一里程碑应先在新的开发实验中验证**预算内的桥接证据组合、减少模型可见的重复包装**，再单独处理候选缺失。不要继续对新暴露的这 200 题扫参数。当前真实代码路径已覆盖检索选择、builtin、observation、准入及消息转换，但快照/向量/模型分数 I/O 为受控适配；未验证 live SQL/Qdrant、RBAC、Checkpoint、自主工具选择、多次 search、历史和记忆的整条 Run。本次不是平台 Formal Experiment，源码 ZIP 也不冒充干净 commit 或已发布 DatasetVersion/定价绑定。

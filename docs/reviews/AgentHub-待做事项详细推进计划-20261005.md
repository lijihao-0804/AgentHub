### 7.2 新记忆数据：规划 64 个独立场景

八类，每类初始 8 个：稳定偏好、长期约束、事实更新与冲突、短期状态、过期事实、明确禁止记忆/使用、跨任务无关信息、污染/注入与租户隔离。每场景提供学习轮、后续查询、应记/不应记、应使用/不得使用、时间线和可检查业务后置条件。

按来源/模板族划分 DEV 48、HOLDOUT 16。先进行人工可读标注和 schema/重复检查；同模板变换不能分别落两组。64 场景是准备目标，不是已完成数据，也不意味着全部都需付费执行。

对照变体：记忆关闭、现有记忆、TTL/容量策略、TTL/容量+衰减；一次只加入一个可归因策略，其他 frozen spec、数据、价格、知识一致。

### 7.3 新 RAG 数据：规划 30 篇文档、90 个问题

- 文档包括长文档、相似术语、干扰段落、有效期变化、明确冲突与需要两文档共同回答的事实。
- 问题覆盖单跳、跨文档、时间/版本判断、无答案、引用精确性；为每个可答命题标注支持段落与允许引用。
- 按源文档家族划分 DEV 60/HOLDOUT 30；涉及同一文档或政策族的问法不能跨组。若拆分后无法满足配额，优先保证隔离，调整数量并记录原因。
- 复用生产 parser/chunker、Qdrant、`search_knowledge`、正式 ExperimentRunner；不得把答案内联进系统提示而称为 RAG。

### 7.4 实验分段与费用控制

1. **零付费阶段**：数据 schema、ground truth、冻结身份、模拟模型流程、时钟/租户/重复性验证；先拦住基础错误。
2. **小规模 DEV 试跑**：记忆 12 个场景×四变体×一次；RAG 12 个问题×两策略×一次。先测真实调用数、token、费用、运行时间，再决定正式规模。
3. **冻结阶段**：修正仅基于 DEV；冻结数据/评估器/提示；明确正式批次和预算预测后才暴露新 HOLDOUT。
4. **正式阶段**：目标按独立场景重复三次执行；模型质量回归保留失败。若预算不足，明确缩小已执行规模和置信度，不把未跑的场景填零或宣称通过。
5. 已授权累计预算 50 元。旧账本估算含未知预留 6.478488 元，应先对账；本计划建议新一轮实验内部上限 25 元，剩余作为回归/未知调用余量，不能重置历史预算。
6. 只使用用户指定的隔离 `deepseek-flash` 配置。调用前验证账号可用模型、价格快照及预算预测；模型替换、超出累计授权或调用正式业务环境才需要新授权。此文档不声称当前价格/模型可用性已验证。

### 7.5 衰减实现与指标

- 首版采用可解释、可关闭的检索期时间折扣；保留原 salience 和历史内容，不持续修改冻结内容。
- 半衰期等参数仅在 DEV 上比较；`last_used_at` 只来自最终上下文准入后的真实使用，不用“检索命中”假装使用。
- 衰减公式、时间基准、平局排序、版本号和参数必须随运行配置冻结。既有 Run 仍优先读取 frozen memory IDs/hashes，不重新衰减选取。
- 指标：记忆提取精确率、必要信息召回、错误/禁止使用率、陈旧记忆率、业务成功、无关注入数、token、时延、每有效任务费用；全部注明分母/未知。
- RAG 指标：目标证据召回、MRR、引用精确性、命题支持率、正确拒答/错误拒答、业务成功、时延/费用。
- 报告按独立任务聚合和 paired 对比，重复执行按任务聚类；不得把所有重复当成独立总体样本。评估器输出与助手语义复核分别列示；独立真人一致性没有测则标未知。

### 验收标准

- 确定性边界：跨租户泄漏、违反硬禁止使用规则的持久写入、冻结回放破坏在验收集上为 0；结构/完整性问题必须修复。
- 模型质量：不预设“新策略必须赢”。若衰减未改善保持/误用权衡，保持默认关闭，交付可配置实现和负面实验结论；原“衰减功能”需求不因此删除。
- 无缺失被伪装为 0，无 HOLDOUT 调优后继续充当盲测，无只报最佳一次的筛选。
- 文件：复用 `benchmarks/evaluation/`、`packages/evaluation/`、`packages/memory/`；新增有版本的数据/评估器和 evidence，不复制正式 driver。
- i18n：`agents.memory.decay.*` 与已有实验指标文案；未知、未评估和关闭状态可区分。

## 9. S6：逐轮参数热调 T25

### 主要文件

`apps/api/schemas/threads.py`、`apps/api/routes/threads.py`；`packages/threads/service.py`、`models.py`；`packages/agent_runtime/runtime.py`、`frozen.py`、`models.py`；模型请求契约；共享 `apps/web/components/apps/app-conversation-pane.tsx`、`apps/web/lib/api/agent-runtime.ts` 和 chat 客户端。

### 步骤与验收

1. 首版仅 temperature 和 max_tokens，不开放任意 JSON 覆盖、模型/工具/知识/审批策略替换。
2. temperature 受所选模型能力边界约束；max_tokens 不超过冻结模型输出能力和上下文预算的可用输出额度。空输入表示沿用版本值，非法/NaN/布尔值在服务端拒绝。
3. 将请求覆盖及有效参数、规范化身份持久到对应 Run。发布版本的 resolved spec/hash 保持原值；另记录有效运行配置身份，禁止用同一个哈希同时声称代表两种配置。
4. client_token 幂等绑定 input+overrides；同 token 内容变化返回冲突。审批恢复、worker 重入、流重连继续使用首次冻结值。
5. 正式 Experiment 默认禁止临时覆盖；要比较参数时作为显式 variant 冻结，纳入现有实验身份契约。
6. UI 在提交前可调，运行中不改当前轮；停止后下轮可调。详情可核对本轮有效参数，失败重试规则明确沿用或创建新身份。
7. 测试：预算超限、模型不支持参数、幂等冲突、重连/审批恢复、并发提交、session 切换、默认行为兼容和正式实验拒绝未绑定覆盖。
8. Browser：两轮不同参数→Run 详情值一致→等待审批恢复值不变；不需要靠真实模型随机输出证明参数生效，应验证实际请求与持久有效配置。

i18n：`appThread.parameters.*`：沿用版本/temperature/输出上限/运行中冻结/无效值/本轮生效说明。

## 11. S8：邀请链接与接受流程 T30-B

### 首版边界

交付手动分发邀请链接，不自动发送邮件。新增外部邮件服务、SMTP 凭据及真实收件人发送不在既有实现授权内；需要时再确认目的地和授权。

### 文件与步骤

- 扩展 `packages/control_plane` 的 tenancy service/models/schema，API `/api/v1` 下新增邀请路由；token 安全复用既有 auth 基础设施。
- 新建显式 migration；前端成员页、邀请接受页、tenancy client、两语言包。
- 邀请绑定组织/可选工作区、目标规范化邮箱、目标角色、创建者、到期时间。高熵 token 仅存哈希；创建时返回一次，不写到审计、日志、分析事件或错误报告。
- 建议有效期默认 7 天、最大 30 天；接受/撤销一次性、并发消费受事务保护。接受时重新核对创建者当前资格、目标角色可授权范围及接受者邮箱。
- 未登录先登录/注册后接受；不改动认证凭据。邀请不替代组织成员规则；需要增加组织资格时明确分两层建立，不自动扩大其他工作区访问。
- token 链接优先前端 fragment 读取后提交 API；禁止 token 跟随外部链接 Referer。失效/已消费/撤销/角色变化返回安全结果；不可枚举邮箱是否注册。

### 验收

覆盖正确/错误邮箱、到期边界、撤销、两人并发、重复接受、创建者失权、越权角色、跨组织、日志脱敏和审计失败回滚。Browser：创建合成邀请→目标合成账号接受→两个层级成员正确→重复接受不增成员。生产邮件发送另行批准。

i18n：`settings.members.invitation.*`：创建/有效期/链接仅显示一次/复制失败/接受/撤销/失效/邮箱不匹配。

## 12. 共用验证门与每阶段完成定义

| 门 | 要求 | 不得替代的证据 |
| --- | --- | --- |
| G0 契约 | 状态、权限、边界、默认值、兼容和迁移先明确 | 不能只有前端按钮或计划描述 |
| G1 单元 | 本阶段相关确定性、拒绝路径、兼容用例通过 | 不能只测 happy path |
| G2 集成 | 实际隔离 PostgreSQL；worker/beat 项用真实专用进程 | SQL mock 不能替代事务/并发/外键证据 |
| G3 前端 | 类型、生产构建、行为脚本、真实 API 浏览器及截图 | 构建成功不能证明页面无 Hook/排版问题 |
| G4 质量 | 数据/来源/冻结身份/指标分母/成本可对账 | 单测和模拟 provider 不能证明真实模型业务质量 |
| G5 故障/容量 | 相关持久化窗口、重复投递、超时；新负载单列范围 | 安全终态不能冒充业务恢复、限速负载不能冒充容量上限 |
| G6 交付 | 报告、清单、提交、推送和未完成限制一致 | 不能在完成报告中提前关闭下一个阶段 |

执行命令使用项目 `.venv/Scripts/python.exe` 与 `C:/Program Files/nodejs/node.exe`，PowerShell 不加载 profile。相关检查按改动范围运行；核心执行/存储契约改变或最终整合时，再执行全量 unit/integration，明确跳过原因。

长任务使用既有 job_runner 保留 stdout/stderr/status 和实际退出码。Next dev 与 build 不并发写 `.next`；仅停止本阶段创建且 PID/命令已核对的进程。不得用旧截图/hash gate 代替新功能浏览器检查。

每阶段至少交付：契约/代码及显式迁移、相关测试、中英 i18n、证据索引、验收报告、未通过/未执行限制、提交与推送记录。模型质量下降可形成有效负面实验结论，但功能契约/安全边界失败不能验收。

## 13. 可以直接推进与需要用户输入的条件

- 原指定模型不可用且必须替换、累计费用将超 50 元：需新确认；预算不足不是随意降低必要安全测试的理由。

**后续状态**：P0 消费者预算贯通与实际答案确认已经完成，见[验收](AgentHub-RAG消费者闭环与答案评测-20261023.md)。新 200 题 F1 27.92%→39.39%。本文下方为此前方案；真实 5 块消费者口径下，MuSiQue 有 87 题、QASPER 有 226 题池内齐备却未进入检索输出，不能沿用较宽离线填充口径直接决定候选改造优先级。用户最新要求停止参数纠缠，转向优秀项目实际源码架构比较；不继续对新确认题挑方法。

## 结论

第一优先级是验证现有收益在真实 Agent 最终上下文中保留多少；新的质量研发应分成两条：QASPER 补候选召回，MuSiQue 改证据组合选择。两者当前的主要损失位置不同，不应继续只增加同一套 TopK。

## 损失证据

| 场景 | 当前完整证据集 | 现有候选池段落命中的完整集上限 | 最终仍失败的题目构成 |
|---|---:|---:|---|
| QASPER | 78.69% | 84.19% | 135 题候选池本就不齐，47 题选择后不齐，共 182 题 |
| MuSiQue | 76.33% | 93.00% | 21 题候选池本就不齐，50 题选择后不齐，共 71 题 |
| MuSiQue 四跳 | 30.00% | 70.00% | 15 题候选池本就不齐，20 题选择后不齐，共 35 题 |

候选上限是已暴露样本上的、依赖 gold 的离线诊断，不可当作可直接部署的方法或预期增益；段落 ID 齐备也不是原始支持 span 全覆盖。

新增的[按跳数阶段归因](../../benchmarks/public_rag/results/scenario-rag-20261023/musique-confirm-1/hop-stage-diagnostics-20261023.json)中，两跳 137/140 池内齐备、129/140 最终齐备；三跳 107/110 与 85/110；四跳 35/50 与 15/50。四跳当前最大的单一可见损失组是池内已有、选择时丢失，而非所有失败都需要再次召回。

QASPER 当前池内证据召回 89.17%、实际准入 84.39%；只优化选择最多逼近当前池的覆盖，不能靠重排找出未进入候选的证据。135/182（约 74%）的剩余完整集失败涉及候选缺失，因而需要改变候选来源/表示。

## 优先级 0：真实消费者闭环

当前 benchmark 平均约 12 个段落；search_knowledge 默认 5、最大 10，并将 snippet 限制为 1000 字符，之后还有完整 prompt 的 ContextBudgetPolicy。生产 RetrievedEvidence 比 benchmark 多元数据，8000 bytes 同名也不意味着相同可用正文。预算参数接通不能替代最终证据验证。

在同一固定问题集上保存各阶段可评分的证据位置：候选 → 检索输出 → 工具实际返回 → 模型最终准入。分别量化来源、支持文字覆盖和完整证据链的损失。按场景显式配置预算，先比较当前工具行为与保留证据的受控路径，不能直接扩大所有 Agent 的默认上限。

加入实际答案评价：短答案用规范化 EM/F1，长答案另报与证据支持相关的正确性/引用检查；不可回答单独报误答与误拒。用真实检索、无检索、gold 证据三个离线对照分离检索和生成问题；gold 只作诊断。裁判样本先做人工校准，不以一个 LLM 分数替代真值。记录最终输入/输出 tokens、增量 API 用量和 P50/P95，不把共享缓存推理时间当真实端到端。

## 优先级 1A：MuSiQue 的证据组合与有界补检

先验证预算内保留不同必要关系的原始证据，避免只按每段与原问题的直接相似度排序。没有直接答案关键词的中间桥接段也可能不可缺。先检查重叠 chunk 的重复正文与元数据开销；同一来源合并时保留原位置/引用，不能因为“同文档”而删掉必要的不同证据。

给定候选任务先测“现有池内的桥接感知选择”；只有仍缺关系时，再测最多有限次数的子查询补检。来自模型的实体/关系是查询假设，必须回到原文核验，不能把模型生成文字当成新证据。生产路由不能读取数据集的 gold hop 数或官方 question_decomposition。

本次核对了两个项目的实际代码：

- [IRCoT RetrieveAndResetParagraphsParticipant / ExitController](https://github.com/StonyBrookNLP/ircot/blob/main/commaqa/inference/ircot.py)：支持原问题或最近生成步骤形成检索查询，并有停止控制。借鉴其逐步补证据及有界停止机制，具体输出契约仍采用项目可验证的查询/来源结构。
- [FlashRAG IRCOTPipeline](https://github.com/RUC-NLPIR/FlashRAG/blob/main/flashrag/pipeline/active_pipeline.py)：累计已检索来源，按仍需继续的题目迭代，有 max_iter。它是实现参考，不保证照搬到当前给定候选任务就提高。必须核对自身分数排序方向、预算和失败契约，不能复制默认值后直接宣称有效。

下一次开发宜增加足够的三/四跳题数并单列结果，保留自然分布总体分数；不把这 50 道已暴露四跳题作为新的盲测。先比较同实际上下文预算下的填充与组合选择，再单独加补检，避免把更多 tokens/调用的收益误归于机制。

## 优先级 1B：QASPER 的候选来源与表示

本轮场景运行器是 paper/case 内精确 dense 检索，尚未在该轨验证生产 hybrid，不能把漏召回归因于 ANN。先比较 dense 与词法/语义互补召回，保留同一 BGE 重排输入额度和最终上下文预算；词法匹配可能帮助术语、缩写、专名，是否帮助必须由新开发实验确认。

若候选覆盖仍不足，再单独验证“先定位章节、再找段落”，或多向量表示；不把这几项一次性混合以免不知道哪项有效。[ColBERT 的实际编码/评分实现](https://github.com/stanford-futuredata/ColBERT/blob/main/colbert/modeling/colbert.py)保留 token 级向量并以 MaxSim 聚合，提供了不同于单向量检索的候选表示方向，但需计入索引、存储和推理成本，暂不作为默认替换建议。

标题路径单独增益区间跨零，邻段扩展又弱于预算填充，因此不应把全量扩大父块/邻段作为优先方向。新候选机制首先看池内支持覆盖是否提高，再看固定预算下的准入和答案，不只看最后均分。

## 优先级 2：单位成本、不可回答和中文业务适配

本轮收益伴随输入增加约 2.2 倍。可先测同来源重叠区间合并、减少传给模型的冗余包装、支持句定位后保留必要邻句；保留原始来源与定位，实际 token 化后再比较。字节预算用于传输/证据大小，模型 token 预算仍由 ContextBudgetPolicy 负责，二者不能混作同一指标。

未可回答题在本轮证据分数中未评分，不能自动判定可以正确拒答。QASPER 已采集的 60 个此类确认题只能做暴露回归；拒答策略应先在训练划分开发并明确新的冻结确认。原有 relevance floor 不能不经校准就当作统一答案置信度。

后续真实业务还需补中文、编号/条款、版本/生效时间等分层；英文公开数据的改进不能证明这些场景。先完成上面的消费者闭环，不并行铺开图检索、自动路由、表格与所有语言。

## 执行顺序与止损

先完成真实消费者闭环。随后每次只开一个质量里程碑：优先 MuSiQue 的池内证据组合选择，之后再做 QASPER 的互补候选召回；有界迭代检索作为单独方法比较。开发集选择、冻结方法、新的确认和已暴露回归集分别记录。

固定最大上下文之外还报告实际输入量，必要时补等实际输入的对照。先声明主要指标、分组区间、最小实用收益和调用预算；无正向证据就保留当前基线。QASPER train-only 的通用 LLM 来源选择相对填充增益区间跨零，当前不继续硬调该分支。没有证据说明应立即安装整个框架、扩大所有 TopK 或把所有请求改成 Agentic RAG。

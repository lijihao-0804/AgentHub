# AgentHub 工作区升级验收

本轮从 `f2822c3` 开始，在同一个主题分支交付工作区任务入口、用户记忆、智能体评测与 RAG 对照。验证使用本机隔离 PostgreSQL，界面验收使用 Edge。各项实验的分母不同，数据记录如下。

## 从首页开始任务

工作台在桌面使用应用选择按钮，窄屏使用原生选择器。任务草稿可以输入多行，切换应用会保留正文。点击继续时草稿经当前会话传入应用，首行作为可编辑的会话标题，完整任务成为首条待发送消息。新任务的正文不进入地址栏。切换工作区或账号后，草稿的所有者随会话代次一起校验。侧栏与页面查找器共用路由表，支持按中文、英文或路径过滤。Ctrl/Cmd+K 打开，方向键选择，Enter 跳转，Esc 返回原焦点。

在真实注册用户下创建隔离工作区、发布使用无效测试凭据的智能体，再从首页进入客服并创建会话。浏览器断言首行标题和多行正文与录入一致，用户仍需主动发送消息。320、390、768、1024、1440 像素五种宽度分别检查明暗主题、横向溢出、搜索空结果、方向键焦点及关闭后的焦点。随后切到英文并从页面搜索进入知识库。截图来自正式构建的合成工作区。[桌面首页](evidence/workspace-quality-20261118/home-desktop.png) · [窄屏深色首页](evidence/workspace-quality-20261118/home-mobile.png)

## 长期记忆与上下文

新建智能体默认启用 `USER`，记忆按工作区、智能体和用户归属隔离。作者可在草稿中选 `AGENT` 共享，或关闭长期记忆。发布冻结范围，管理接口按所有者和编辑权限约束查看、停用和恢复。历史版本保留当时的开关和共享语义。后台从成功的会话回合提取记忆，启用真实提取模型时需计入运行成本。入选的记忆经过上下文预算后才进入模型输入。运行记录和对话仍沿用工作区访问规则。[记忆机制、约束和边界](../learning/07-memory.md)

154 项针对性后端用例通过。隔离 PostgreSQL 覆盖提取重试、同用户跨线程读取、冻结回放、跨用户/智能体/工作区隔离和停用恢复。正式构建的详情页在独立浏览器上下文里依次保存共享与关闭，两次 PATCH 均返回 200，独立 GET 和刷新结果一致。两次编辑前后，已发布 v1 的完整 resolved spec 相同。提取质量没有在本轮通过商业模型评分。

## 评测比较与发布判断

比较按用例和重复编号配对，同一用例的差值先求平均，各用例再等权汇总。若重复编号不同，两侧即使都有分数也不组成配对。结果按确定顺序计算区间，浏览器可逐题查看退步、持平、进步，以及缺失在哪一侧。用户可建立配对成功率区间下界和非劣性两种门禁。缺失配对时，这两种规则给出证据不足，历史决定保留原始值。

真实 ASGI 与 PostgreSQL 的四题 HOLDOUT 验证共八次受控执行。候选一题进步、一题退步、一题持平、一题缺评分。已配对部分平均变化为零，门禁为 `INCONCLUSIVE`，重读记录一致。Edge 打开比较面板，核对四行结果，再分别保存阈值为 0.02 的两种门禁，两次真实 API 都返回 201。浏览器场景将其初始会话对接到专用测试库。后端 19 项相关测试与前端 9 项既有回归通过。

## RAG 实验

一般文本实验使用 SciFact 训练集已有的按来源隔离的确认分区，固定真实融合与 BGE 重排得分、前五块和 512 个估算正文 token。553 题中，完整参考依据由 277/379（73.09%）提升至 285/379（75.20%）。8 道题获得完整依据，原已覆盖的依据没有丢失。两臂预算内正例来源都是 376/625。线上引用结构目前绑定单个块 ID，实验合并区间可能横跨多个块，因此按实验策略交付；上线前需支持各组成块的原文定位。这组数字衡量依据覆盖，尚未验证生成答案收益。[冻结方案、逐题差异及复跑命令](../../benchmarks/public_rag/experiments/source_span_budget/README.md)

复杂表格采用公开 W3C 两张不规则表，在 MinerU 导入、真实上传与索引、冻结快照、BGE 混合检索、重排和问答入口比较两版。修正连续多层表头后，能精确定位正确值与单元格的可答题从 2/10 到 10/10。两组在 4/4 缺行或缺字段的题均正确拒绝严格抽取。生成问答单独计分。[表格实验、真实问答与费用](rag-table-header-evidence-20261118.md)

初次本地 Qwen2.5-3B-Instruct 配置经真实引用问答入口对两组各提问 14 次。可答题数值正确由 2/10 提升至 8/10，数值与对应单元格引用同时正确由 2/10 提升至 5/10。正确拒答由 0/4 至 1/4。按题型合并判定成功由 2/14 至 6/14，5 题改善、1 题退步。3 道候选答案数值正确但引错位置。此轮 llama.cpp 对 28 次请求均报告原始语法编译失败，应用层仍逐条执行引用校验。小模型与云端测试另外记录，线上使用原有问答提示。

最终对照给生成器使用可编译的短答案语法子集，两臂相同，应用层继续执行生产引用校验。独立探针与随后 28 次正式请求均无语法编译错误。可答题数值正确为 **1/10 → 9/10**，数值和引用均正确为 **1/10 → 7/10**；正确拒答为 **1/4 → 2/4**。总体按题型严格判定从 **2/14（14.29%）到 9/14（64.29%）**，逐题 7 题改善，0 题退步。候选第 4、8 题值对引错，第 5 题引文合同失败，第 13、14 题应拒而答。HTTP 200 为 5/14 → 13/14。

本轮预算人民币 30 元。阿里云共发出 1 笔请求，收到 HTTP 401，缺少用量回执后即停止。保留 0.03 元未确认额度，实际结算未知。本地配对实验没有供应商调用费用。

## 部署与回归

先执行 `alembic upgrade head` 迁移到 `0060_private_memory`。存在用户私有记忆时，降级脚本会停止，以免回退旧表结构时丢失归属。最终全量单元回归接入隔离 PostgreSQL，3,544 项全部通过，耗时 121.37 秒。Alembic 模型与实际表结构一致。8 组前端回归和 Next.js 正式构建通过。

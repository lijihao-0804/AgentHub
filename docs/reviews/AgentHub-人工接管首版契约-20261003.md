# 人工接管首版契约（M-I5）

依据分类实施计划 F07 及用户继续第五阶段的授权。原 artifact 留存 problem、checked、findings、recommended_action；另建接管记录保存操作状态，不覆盖证据。

## 状态及权限

| 操作 | 当前状态 | 下一状态 | 权限及约束 |
| --- | --- | --- | --- |
| 开启接管 | 尚无记录 | OPEN | 当前有效工作区操作成员；同 artifact 幂等 |
| 分配/重分配 | OPEN/ASSIGNED/IN_PROGRESS | ASSIGNED | 当前组织 OWNER/ADMIN；目标当前有工作区接管权限 |
| 接手 | OPEN/ASSIGNED | IN_PROGRESS | 当前有效操作成员；ASSIGNED 仅被分配人可接手 |
| 关闭 | IN_PROGRESS | CLOSED | 当前有效被接手人；提交处理原因与未解决项 |

新增 `handoff_handle` 纳入 DEVELOPER 及组织管理角色的操作权限。VIEWER 只读。未知前端权限时禁用动作；后端每次操作在事务内重查真实组织、工作区成员及用户有效状态，不接受旧 context 的权限声明。

首版不提供取消、重开、删除接管历史或自动恢复 Run。管理员也必须先显式接手才可关闭；重新分配会结束前接手人的处理权。

## 并发与重试

每次修改带严格正整数 expected_version，行锁下比较版本，成功变更加一。两个接手人竞争只有一人成功；另一人收到 409。关闭必须保存原因（1–4000 字符）与未解决项（最多 50 项，每项 1–1000 字符）。关闭请求哈希记录原预期版本、操作者和内容；相同原请求重试返回已有结果，不增加版本或重复审计；不同内容或操作者冲突。

开启与原 artifact 修改/删除共同锁 artifact。接管开始后禁止修改/删除原 artifact；关闭后仍保留证据。删除包含接管证据的 thread 返回明确 409，不依赖数据库约束报 500。数据库复合外键限制源 artifact 跨 workspace 绑定及级联销毁。

## API

统一前缀 `/api/v1/workspaces/{workspace_id}`，使用现有错误 envelope。

- `POST /artifacts/{artifact_id}/handoff`：开启或返回已开启记录。
- `GET /threads/{thread_id}/handoffs`：分页读取接管记录。
- `GET /handoffs/assignees`：管理员读取当前合格接手人。
- `POST /handoffs/{id}/assign`：expected_version、assignee_id。
- `POST /handoffs/{id}/claim`：expected_version。
- `POST /handoffs/{id}/close`：expected_version、reason、unresolved_items。

响应包含 source_artifact_id、source_hash、status、version、assignee_id、claimed_by、closed_by、closure_reason、unresolved_items 与时间戳。业务内容只在有工作区读权限的响应里返回，审计只保存 ID、版本、状态、内容哈希。

## 验收

真实 PostgreSQL 验证并发接手、同 artifact 重复开启、管理员重分配、失权及禁用用户、越权/跨租户、陈旧版本、重复关闭、关闭内容冲突、证据留存与审计原子性。请求拒绝多余字段、布尔版本、空原因与超长内容。原 artifact 编辑/删除及 thread 删除需证明阻止历史销毁。

前端复用 workspace 数据/变更 hooks、已有 handoff 卡片、StatusBadge 与 i18n。记录加载失败与尚未开启分开显示。切换 thread/workspace 重置表单及响应，409 后刷新当前状态。浏览器演示生成失败/待处理摘要 → 开启接管 → 分配或接手 → 填处理原因与未解决项 → 关闭 → 原摘要仍可读。

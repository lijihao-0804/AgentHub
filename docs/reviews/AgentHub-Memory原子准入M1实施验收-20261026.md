## 旧行为的具体缺陷

Memory 之前进入通用递归 JSON 裁剪，可能留下身份或正文不完整的记录。
运行时 touch 之前仅扫描 system 消息中的 `memories[].id`，不能证明该 ID 对应的完整事实已进入最终请求。

独立离线案例：一条带审批及退款期限限制的事实，在 160 单位 Memory 预算下，旧版输出完整条目0、不完整条目1。
计数器使用可解释的字符长度，衡量完整最终序列化消息；不是供应商准确 token 计数，更不是 RAG 业务准确率样本。

## 本轮契约

- 只在显式 `ContextCategory.MEMORY` 处理专属 payload，非法身份、类型、重复身份和缺失字段先失败关闭。
- 冻结候选按原顺序逐条试装，`id/kind/content` 完整存在或整条缺省，过大候选不阻止后续已冻结候选。
- 根级 trust 固定 `UNTRUSTED`。连空信任信封都放不下则整条可选消息不准入；不以正文前缀替代完整事实。
- `ContextAdmissionResult.memory_admission` 描述最终总窗口选择后的身份与丢弃原因，不把类别预算的中间结果当作最终送达。
- 模型步骤和 trace 记录 projection version 与 selected/admitted/dropped 计数；每条原因仅在私有 checkpoint 中保留，不默认记录正文或记忆 ID。
- touch 同时要求显式 MEMORY 类别、完整字段、最终准入报告及原冻结选择授权，不从 system 角色或同名 JSON 键推断。
- 多轮继续保留原冻结选择的分母及既有丢弃原因。admitted 只表示最终请求准入，不表示模型实际使用、认可或答对。

## 兼容和停止边界

原快照选择及完整性校验不改，恢复不重新查询候选；旧版本的新派发也应用完整条目修复。
足额 Memory 消息及 memory-off 路径保持既有语义；低预算旧场景允许变为完整条目缺省，不宣称可逐字重现旧的不完整模型输入。
本轮不修改历史原始回答或快照内容，也不为修复前未捕获的请求补造证据。

M1 验收通过后停止，不自动推进 M2 能力解析、M3 工作集调度或 M4 摘要生成。M1通过不代表语义压缩质量、长会话表现或RAG答案准确率提高。

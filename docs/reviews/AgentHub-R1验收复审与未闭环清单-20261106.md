## 5. R1 的刻意保留边界，不要误记为重做缺陷

1. **没有持久派发/响应阶段。** 进程崩溃、取消或异常簿记也写库失败时，无 payload 的 RUNNING 仍可能被保守标为 unknown。这是已声明边界，不等于普通异常分类修复失败。
2. **已知响应但候选未保存不能自动恢复。** 该分支现在可区分，但原响应不存储；不能自动重调模型补回来。若要完整 durable 响应恢复，需另立合同与安全保存设计。
3. **没有 Memory 物理计费账本。** 本修复没有把后台提取消耗纳入单 case/平台预算，也没有将费用回填到原 Run。usage、估算与 bill 闭环仍未完成。
4. **有限金额与摘要门不变。** 继续 INTERACTIVE_COST_RESERVATION_UNAVAILABLE、SUMMARY_QUALITY_GATE_NOT_MET；不能为了证明 R1 可用而移除它们。
5. **强撤权线性化与 malformed 输出分类不在 R1。** 前者仍需先冻结并发合同再做真库反例；后者保留既有容忍行为。不得把它们升级为已证实事故，或在 R1 收尾中顺带大改。

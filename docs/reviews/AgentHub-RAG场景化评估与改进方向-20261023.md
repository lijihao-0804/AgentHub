# AgentHub RAG 场景化评估与改进方向

日期：2026-10-23。本轮为源码、既有结果与成熟项目实现的分析；没有新增模型调用、测试成绩、策略上线或自动路由。

**后续执行更新**：用户随后授权后，QASPER 与 MuSiQue 已实际运行并通过冻结确认，新增可选证据字节预算接入；以下是执行前分析的历史状态。当前成绩、分母、四跳不足与生产边界见[2026-10-23 验收](AgentHub-RAG场景优化验收-20261023.md)。没有实现自动路由或证明最终回答提高。

## 总体判断

已有权限/快照/版本/上下文预算等治理底座和可追溯的单次检索评测，得到一次真实提速及一次跨语料排序改进。
尚未证明一个覆盖不同文档、查询类型和业务目标的场景化RAG系统已经完成。当前主要配置仍是DENSE/HYBRID/HYBRID_RERANK与若干预算，更多是同一链路的选择，而不是不同任务的完整策略。

## 已经做对与尚未覆盖

- 快照SQL JOIN：SciFact test排序与质量不变，热均值减9.95%；是清楚的工程收益。
- 预算分离/来源配额：提供必要控制面，四变体未支持替换默认，不能把功能完成称质量改善。
- Onyx来源选择：SciFact DEV nDCG0.75331→0.79743、FiQA test0.41337→0.45320，区间支持正向差；每题新增API约0.73–0.74秒，仍为benchmark适配器。
- learned sparse/父文档前置重排/DBSF：固定组合未过门槛，保留负结果合理；不能据此否定这些机制在其它任务上的价值。
- 两个公开实验都围绕英文文本、单次检索、文档级qrels。SciFact检索成绩不是科学主张真假判断；FiQA金融文本检索不是财报表格计算。中文、长文档、多跳、时间约束、跨轮与全局归纳尚缺本轮公开质量证据。
- 原小型合成客服/政策回归依然有价值，不能替代真实业务或跨领域质量证明。

## 应按什么场景分策略

| 场景 | 建议先验证的策略 | 当前证据/缺口 | 关键验收指标 |
|---|---|---|---|
| 低延迟FAQ、术语解释 | 简单单次召回、短证据；按收益决定是否本地重排 | 有单跳基线，LLM选择器不宜因全局均分更好而统一开启 | 回答正确率、P95、费用、拒答错误 |
| 编号/专名/政策条款 | 词法/精确匹配通道、显式版本与生效时间条件、语义补充 | 当前tokenizer logTF+IDF不是成熟BM25或精确匹配专用路径；尚无编号/时间分层证据 | 精确条款命中、版本正确、不可回答识别 |
| 长文档定点问答 | 结构化分块、标题路径、小块召回后局部父/邻块回填 | 既有父实验是给reranker更长父文本，非生成阶段上下文扩展 | 证据span覆盖、答案F1/语义正确、引用支持、输入成本 |
| 跨文档比较/综合 | 来源级选择、维度覆盖、相关性与多样性兼顾 | Onyx排序有依据，多来源内容利用尚未验 | 必要来源/论点覆盖、错误合并、忠实性、费用 |
| 多跳问题 | 有预算的分解与迭代检索，每一步保留证据依赖 | 单次召回不证明能覆盖依赖链；不能给所有问题增加Agent循环 | 全链证据齐备率、答案F1、调用数、停止/拒答 |
| 表格/财报数值 | 表头/单位/期间结构保留，检索定位后受控计算 | FiQA结果不能用于此场景验收 | 数值容差、单位/年份正确、可追溯计算和引用 |
| 全库趋势/主题归纳 | 分层目录与摘要，必要时图或社区摘要索引，再回到原文 | TopK相关文档容易偏向高频主题；尚无相应实验，不宜直接全量GraphRAG | 主题覆盖、事实支持、来源代表性、维护成本 |
| 多轮客服/时效知识 | 受限指代消解、查询改写、明确时间/版本；动态事实用授权工具 | 不能拿Memory或冻结快照自动充当实时知识；尚缺跨轮公开质量轨 | 约束继承、旧事实误用、跨轮证据一致性、工具结果准确 |

这些是待验证的场景假设，不是已经实现或被证明优于基线的结论。
策略应同时考虑文档结构、问题依赖、语料语言、时效性与延迟预算，不能只按“科研/金融”领域名分类。

## 成熟项目的实际启示

- [LangChain ParentDocumentRetriever源码](https://github.com/langchain-ai/langchain/blob/langchain%3D%3D0.3.27/libs/langchain/langchain/retrievers/parent_document_retriever.py)：检索小块后按parent ID返回较大上下文，区分检索粒度与回答上下文粒度。我们先前长父文本rerank实验不是这一用途的完整检验。
- [Onyx来源选择源码](https://github.com/onyx-dot-app/onyx/blob/4f64a0c4ca029532fc3e04475fe0fe1d44cee540/backend/onyx/secondary_llm_flows/document_filter.py)：来源/section选择与输入预算是独立环节。值得保留为高质量可选路径，而非每次请求必经的开销。
- [LightRAG QueryParam源码](https://raw.githubusercontent.com/HKUDS/LightRAG/main/lightrag/base.py)：区分local/global/hybrid/naive/mix并单列图与文本预算；[实际操作实现](https://raw.githubusercontent.com/HKUDS/LightRAG/main/lightrag/operate.py)分实体、关系和原文检索。启示是明确不同查询路径和预算，不是直接照搬其默认mix或收益宣称。

## 现阶段三个更关键的问题

1. FiQA两路并集标注相关来源覆盖59.89%，融合20后48.63%，丢203个相关问题—文档对。可确定损失位置，不能由此直接断定embedding、ANN或分块中哪项导致最初漏召回。改排序不能找回被丢候选。
2. 评测与消费者有距离：主评测为20个原始子块，工具默认5块且snippet最多1000字符，API默认6块，随后还经ContextBudgetPolicy。已做5/6块描述诊断，但未测整段证据截断、最终准入和生成答案的联合效果。
3. 交付尚未闭环：工具层仍会按BGE分数二次排序；Onyx若直接插入可能被覆盖，usage也需并入Run预算。必须先解决接入与真实端到端验证，不靠增加benchmark分支掩盖未交付状态。

## 改进顺序

第一里程碑：以现有单跳场景为范围完成Onyx版本级opt-in，保留轻量基线；工具保序、ContextBudget、usage/费用和失败行为完整接入。用真实消费者路径对比质量、P95、tokens与费用。无检索、实际检索、gold上下文上限对照分离检索不足和生成不足；gold对照只能用于离线诊断，不进入真实检索链路。结果不支持净收益则保留可选项，不改全局默认。

第二里程碑：从业务用途和已准备资源出发新增一个长文档轨，优先QASPER的指定论文问答，比较当前文本块与结构/父子上下文方案。指定论文内问答与全库论文搜索必须分开。这里才能验证父子检索解决上下文缺失的价值。

第三里程碑：需要跨步骤研究时再做MuSiQue多跳轨；财报表格按Analyst实际需求另开。每次只新增一个场景及其验收，不同步铺开图、表格、Agent循环和查询路由。

召回改善可作为单独受控实验：精确检索排除ANN近似损失、评估更强embedding/late interaction、通道并集覆盖与候选保留，分别控制变量。新方法在独立DEV选择；SciFact/FiQA已暴露test不再用于重选，保留新的确认集。

## 路由与评分

先按AgentVersion/知识库用途显式指定策略与成本档位，再考虑问题级自动路由。所有路径都保留租户/快照授权与版本固定，不能因路由切换扩大数据范围。
自动路由需与固定轻量、固定高质量策略比较，计入路由模型自身延迟/成本、误路由损失和拒绝行为。离线人工标注场景可用于诊断路由上限，不能当生产可得信息。

最终账本分检索、准入、使用、业务结果四层：候选覆盖→必要证据实际进入上下文→答案是否被证据支持→任务/计算/拒答是否正确。
分场景报告有效题数、失败回退、按文档族/问题依赖分组区间，以及P50/P95、tokens、费用。公开基准加独立业务留出；新增语义裁判需要抽样校准，不将一个LLM裁判分数当无误差真值。


## 已下载资源是否实际使用（2026-10-23核对）

原始批次位于data/external/rag-public-20261021，后来另补FiQA/NFCorpus。获取清单是历史时点，不能把其中当时experiments_run=false解释为目前从未运行。

| 资源 | 当前使用阶段 | 已有/缺少的结果 |
|---|---|---|
| SciFact | 全语料建独立索引，完成809 DEV/300 test以及多轮机制实验 | 已用于SQL、预算/多样性、learned sparse、父文档、融合、Onyx等检索评测 |
| FiQA（后补） | 全57,638文档、71,576块，648 test | 完成冻结Onyx方法独立确认 |
| QASPER | 三split、官方evaluator本地可用；尚无本轮索引/问答运行结果 | 1,585论文/5,049问题，是下一长文档轨现成资源；不是全部论文PDF已收齐 |
| MuSiQue | 本地文件已获取，尚无本轮多跳执行/评分结果 | 支持材料和分解标注可供多跳DEV；本地test没有答案，不能冒算本地test答案准确率 |
| NFCorpus（后补） | 本地可用，尚未用作评测 | 查询与qrels仍未解析，不消耗保留的独立样本 |
| RAGChecker | 源码已获取；当前venv未安装ragchecker | 它是评估工具，不是语料；尚未运行claim级检查 |

这些是开发/评测资源，已建索引的也在隔离benchmark库与collection，没有自动进入日常业务知识库或已发布AgentVersion。
结论是“部分资源已经充分用于检索实验，长文档/多跳资源尚未转化为对应能力与质量证据”。
因而现阶段更应复用QASPER与MuSiQue扩展场景验证，而不是继续下载更多同类数据或仅在SciFact重复比较组件。

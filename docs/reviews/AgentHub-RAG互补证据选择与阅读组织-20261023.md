# 互补证据集合选择与阅读组织

2026-10-23。**联合选择在受控 MuSiQue 开发与来源隔离确认上均通过预登记门槛，已实现项目内显式组合接口；阅读顺序没有可靠额外收益，未采用。默认和业务 AgentVersion 不变，本里程碑收口。**保持原文、来源、最多 5 个原子证据、已验收 `rag_records_v1` 格式和 8000 预算。

## 调研依据与取舍

本轮直接阅读项目源码，区分项目已有机制和 AgentHub 自己提出的实验假设。

| 项目与源码 | 实际机制 | 本轮取舍 |
|---|---|---|
| [Onyx search_tool.py](https://github.com/onyx-dot-app/onyx/blob/f1fa7005725263df1bbdc6278b62ed804225a75d/backend/onyx/tools/tool_implementations/search/search_tool.py)、[document_filter.py](https://github.com/onyx-dot-app/onyx/blob/f1fa7005725263df1bbdc6278b62ed804225a75d/backend/onyx/secondary_llm_flows/document_filter.py)、[search_prompts.py](https://github.com/onyx-dot-app/onyx/blob/f1fa7005725263df1bbdc6278b62ed804225a75d/backend/onyx/prompts/search_prompts.py) | 融合后一次给模型多份候选，保留间接支持，随后选择性扩展上下文、合并重叠片段；最终阅读文本和完整来源对象分离 | 借鉴联合观察多份材料；不再按段落各自相关性取前 5。这里的依赖链排序是 AgentHub 实验假设，不能说 Onyx 已证明该排序有效 |

| [HippoRAG](https://github.com/OSU-NLP-Group/HippoRAG/blob/main/src/hipporag/HippoRAG.py) 的 `rerank_facts`、`graph_search_with_fact_entities` | 选择关系事实作为图搜索种子，结合段落相似度与个性化 PageRank 连接证据；需要关系提取和图索引 | 说明多跳应关心关系连接，而非只有问题—段落相似度。本轮候选池完整率已高，先用一次集合选择验证价值，不新增图索引或导入其框架 |

Onyx 使用已核对的固定提交；另外两份为当日读取的默认分支源码，未声称跨版本复现或与其完整系统同台对比。未复制项目代码、依赖或其评分结论。

## 机制与归因

共享的 `EvidenceSetSelector` 接受最多 20 个原始候选，只向选择模型展示局部整数编号、1000 字符内原文、标题、安全位置和文档生命周期。问题 ID、答案、gold 支持标签、跳数、分解问题、私有来源标识不进入该模型。一次请求返回最多 5 个互异原子编号；本地严格检查输出，拒绝重复、越界、额外答案或自由推理文本。选择器生成的说明或答案从不传给答案模型。

选择目标是互补：覆盖题目需要的不同关系、桥接实体和比较对象，避免重复相关段落挤占缺失环节。相同文件的多个不同段落允许共存，不用“一文档最多一段”冒充互补性。模型返回的阅读顺序是待检验建议，不是已核实的关系图或事实。

| 组 | 选择集合 | 答案端顺序 | 用途 |
|---|---|---|---|
| legacy5 | 原 BGE 顺序及字节选择 | 原顺序 | 已验收基线 |
| set_rank5 | 新联合选择 | 保持 BGE 相关性顺序 | 唯一主比较，隔离集合变化 |
| set_read5 | set_rank5 最终实际可见的同一批原文 | 选择模型建议的阅读顺序 | 描述性顺序诊断，不参与胜者重选 |

阅读诊断在原 tool 排序之后、runtime observation 之前显式排列，随后继续真实 observation、ContextBudgetPolicy 和 provider 消息转换。下游再次按 BGE 排序会消除顺序变化，因此没有仅改变上游列表就宣称阅读组织生效。尚未给生产工具新增隐式顺序协议或公开配置；应用模块可供明确组合接入，默认链路继续原方案。

## 预登记与止损

固定此前已暴露的 MuSiQue train 160 题、143 个共享支持原文组，给定题目候选段落，保留干扰项。这是开发实验，不是开放维基检索或新盲测。[协议](../../benchmarks/public_rag/results/evidence-set-20261023/protocol.json)在调用选择模型前登记。

第一道门比较最终可见上下文的完整支持段落集：至少提高 5 个百分点，按共享支持原文组进行 5000 次配对 bootstrap 的 95% 区间下界为正，平均支持段落召回损失不超过 1 个百分点，选择器有效率至少 95%，顺序诊断必须实际保持同一批原文。全部通过才进行答案 API 评分。

第二道门的唯一主比较为 set_rank5 对 legacy5：官方短答案 aliases 的 token F1 至少提高 3 个百分点且分组 95% 区间为正；全部失败保留、有效率至少 95%、未知结果为零。还要求观测用量覆盖至少 95%，选择请求加答案请求的平均输入 tokens 不超过基线 4 倍、增量模型流水线 P95 不超过 3 倍。并非完整 live Run 延迟或价格承诺。set_read5 的结果只能描述顺序效应，不能主比较失败后拿它重选。

API 按题—实际消息去重，相同问题相同消息复用同一个结果，包括失败。不同问题不复用。温度 0 也不假设模型绝对确定。固定模型 `deepseek-v4.1-flash-1017`、单次请求、无自动重试或备用模型；未知执行结果立即停止。已知拒绝使用明确标记的基线证据回退，其发生率计入有效率与账本。

确认条件仅在开发验收通过时启动；排除历史已暴露的 300+200 官方 dev 问题，另检查来源族重叠并记录边界，不能把过去的 200 题重新称为新确认集。没有数据或答案支持就不宣布生产质量提高。

## 请求格式故障记录

最初的 160 次选择请求均收到已知 HTTP 400。程序按基线证据回退，相关零变化不能作为算法质量成绩。首次仅返回一题后，继续任务只派发剩余未尝试题，未重试该题；但对整批拒绝缺乏更早的停机限制，造成了可避免的失败请求。

检查后发现原提示虽然展示了输出对象，却没有 JSON 模式要求的显式 JSON 字样。仅补齐格式指令，登记[请求格式修复协议](../../benchmarks/public_rag/results/evidence-set-20261023/protocol-request-repair.json)，保留此前全部拒绝；没有调整选择标准、模型、段落数、预算或验收门槛。这是接口格式修正，不是有效样本评分后的提示搜索。原拒绝未保存服务错误正文，因此不能将具体拒绝原因当作已核实的服务端诊断。

后续调用先检查首个请求；若仍未取得有效选择，立即停止，避免再放大整批格式错误。格式修复前后请求单独统计，失败使用量未知不当作零费用。

## 开发集实测

请求格式修复后的有效开发运行包含全部 160 题。选择器 157 VALID、3 次已知服务拒绝；3 次均保留基线证据回退，没有重试。所有方法保持最多 5 段、相同格式和预算。

| 指标 | 已验收基线 | 联合选择＋原相关性顺序 | 同集合阅读顺序诊断 |
|---|---:|---:|---:|
| 答案 token F1 | 47.89% | **61.22%** | 61.13% |
| 答案 EM | 39.38% | **49.38%** | 48.75% |
| 最终支持段落召回 | 81.15% | **90.99%** | 90.99% |
| 完整支持段落集 | 61.88% | **76.88%** | 76.88% |
| 证据 payload bytes 均值 | 6246.84 | 3357.94 | 3357.94 |

主比较 F1 提高 **13.33 个百分点**，共享支持原文分组配对 95% 区间 **[+8.02, +18.78] 个百分点**。完整支持集提高 **15.00 个百分点**，区间 **[+6.75, +23.60]**。开发预登记各门槛通过，但已暴露开发集不能代替独立确认。

选择器和答案合计、具有完整观测用量的 156 个配对问题上，平均输入 tokens 为基线 **2.040 倍**。选择加答案的增量模型流水线 P95 为 **1645 ms**，基线答案请求 P95 为 **973 ms**，比值 **1.690**。这不是更便宜或更快的方案；答案阅读内容变少，但额外读取候选池的选择请求必须计入。

154/160 题的候选池包含完整支持集；基线在其中完整保留 99 题，新选择保留 123 题，条件命中率 **64.29% → 79.87%**。新增恢复 34 题，同时损失原来完整的 10 题，净增 24。最终证据集合在 157 题变化；阅读诊断在 57 题改变顺序，160 题最终可见原文集合与 set_rank5 相同。

阅读诊断 F1 61.13% 与原顺序 61.22% 很接近，不能把主要增益归因于排列。确认冻结 **set_rank5**，不增加顺序策略或改提示词。

**4 跳局限明显**：13 道 4 跳题完整证据集从 3/13 降为 0/13；2 跳 112 题为 75.00% → 88.39%，3 跳 35 题为 34.29% → 68.57%。当前机制对较长链可能过早停止选择。此分层仅诊断，未据此改变采样、提示、门槛或路由；不能泛化宣称所有多跳场景都改善。

答案实际 **374 次请求**产生 480 个题—组结果，106 份相同问题相同消息结果直接复用，包含失败复用。不能将复用结果当作新增独立样本。[开发答案报告](../../benchmarks/public_rag/results/evidence-set-20261023/development-answers-1/report.json)、[结构报告](../../benchmarks/public_rag/results/evidence-set-20261023/development-prepared-3/structure.json)、[分层诊断](../../benchmarks/public_rag/results/evidence-set-20261023/development-diagnostics.json)保留分母及失败。

## 独立确认采样

开发通过后冻结方法，再从官方 dev 候选中排除旧 500 题，并排除与已暴露 train160＋dev500 的支持原文有相同规范化标题或相同规范化全文的题。另排除 1383 题，剩余 **534 题**；以固定随机种子一次抽取 **200 题**。标签仅用于隔离过滤，不进入选择或答案模型，未按新方法得分抽题。抽样记录在新候选生成与评分之前保存于[确认采样凭据](../../benchmarks/public_rag/results/evidence-set-20261023/confirmation-sampling.json)。

来源隔离强于只排除问题 ID，但改变了确认子集分布；不是整个官方 dev 的无偏全量估计。没有承诺干扰段落、网络已有语料、模型预训练或语义近重复完全隔离。官方 test 未访问。确认只比较基线与冻结 set_rank5，不为顺序诊断再付费。

## 项目实现与审查

新增[联合选择应用服务](../../packages/knowledge/evidence_set.py)及[可组合检索器](../../packages/knowledge/evidence_set_retriever.py)。后者保留原 Retriever 的 snapshot、知识库、query、阈值及生命周期处理，拿到至多 20 个候选后调用选择器，再按原相关性顺序和原 DTO 字节规则返回证据。会拒绝被改写的来源、无预算配置及混用未验收的紧凑投影。完整来源对象、分数和 locator 保留；安全 trace 只增加独立的 `evidence_set` 阶段，不记录原文或生成理由。

组合接口可以通过 `EvidenceSetKnowledgeRetriever(base_retriever, EvidenceSetSelector(gateway, frozen_model_plan))` 显式使用；本轮没有注册为 API 或 runtime 的全局默认，没有发布业务 AgentVersion。生产 Gateway 的重试、模型能力、工作空间和凭据校验不被替换；本轮直接 HTTP adapter 仅存在于公共语料 benchmark。应用服务使用标准文本模型契约和本地严格 JSON 校验，benchmark adapter 另要求 JSON-object 模式；不能把受控适配器评测当作所有 Gateway 的完整兼容验证。

组合接入后离线重放 157 份有效开发选择，真实 builtin → observation → ContextBudgetPolicy → provider 消息与已经付费评分的主比较逐项相同；3 份服务拒绝的明确基线回退保持原样。因此没有再次付费调用。确认阶段使用该项目组合接口。阅读顺序仍是原文排列的独立诊断，未作为已验证默认。

DeepSeek 独立审查提出了续跑仅绑定路径和单组置信推断未阻断的问题：后续续跑现要求原问题、原文和候选行快照逐项相同；结构门同时检查推断有效。另补充未知结果的显式终态检查。主开发运行是单次完整运行，且 143 个有效分组，不受这些修正影响；160 份最终选择请求和 374 份实际答案/复用账本均已离线核对，无新 API。

审查中“每题必须改变顺序”的建议没有采用：不需要改变的排列应允许保持原样，已实际报告 57/160 题改变顺序、106 份相同消息复用，并把顺序比较限定为诊断。原代码对未知结果已有立即 stop，未发现已完成运行混入 UNKNOWN 的实例；额外终态检查属于防御性加固。原始格式错误批次独立保留，不与修复后的质量运行混算为连续可靠性。

## 确认结果与最终决定

来源隔离的官方 dev 200 题、134 个共享支持原文分组，只评测开发阶段冻结的 set_rank5 与基线。相同问题、答案指令、模型、原文格式和预算；服务拒绝与无效答案不删分母。

| 指标 | 基线 | 互补集合＋原相关性顺序 | 差值 |
|---|---:|---:|---:|
| 答案 token F1 | 36.34% | **52.49%** | **+16.15 个百分点** |
| 答案 EM | 29.00% | **45.00%** | **+16.00 个百分点** |
| 支持段落召回 | 82.58% | **90.67%** | **+8.08 个百分点** |
| 完整支持段落集 | 63.50% | **80.00%** | **+16.50 个百分点** |
| 证据 payload bytes 均值 | 6185.19 | 3034.11 | -50.95% |

主比较 F1 的分组配对 95% 区间为 **[+10.16, +22.82] 个百分点**；完整集增益区间 **[+8.25, +25.53]**。选择器 199 VALID、1 已知拒绝后回退，所有 400 个题—组答案均有效。实际答案请求 **399 次**，1 份相同消息复用，没有重复调用已取得结果的请求。最终门槛全部通过。

198/200 题候选池完整；基线其中保留 127 个完整集，新方法保留 160 个，条件命中率 **64.14% → 80.81%**。恢复 47 题、损失 14 题，净增 33。说明改进主要来自已有候选的集合选择；依然损失 38 个候选池本可提供的完整集，尚未接近上限。

新方案最终平均 **2.45 段**，基线 5 段；没有增加原子数量或暗中合并全文。选择模型额外读取最多 20 段，必须计入计算量。199 个输入用量完整配对上，选择＋回答的平均输入为基线 **1.979 倍**；增量模型流水线 P95 **1617 ms**，基线答案请求 **999 ms**，比值 **1.619**。不是端到端 Run 的 SLO 或货币成本对比。

**适用范围仍有限。**确认集 177/200 为 2 跳，16 为 3 跳、7 为 4 跳。3 跳完整集 37.50%→31.25%；4 跳完整集 0→71.43%，但答案 F1 仍均为 14.29%。结合开发 4 跳的反向表现，不能认为长推理链已稳定解决，也不能用证据召回代替答案能力。确认引用 ID 均合法，但没有语义引用支持/faithfulness 评分；开发候选组还产生 2 个越界引用 ID，已计入原报告，未删题。

最终采用决定是：**保留互补选择的显式项目组合能力，保留原相关性顺序，暂不推广成全局默认。**单个 PINNED snapshot、受控检索 I/O、一次固定 search 调用、英文短答的质量证据成立；真实 SQL/Qdrant、租户授权、检查点、多次自主搜索、跨知识库聚合、中文业务与所有生产 Gateway 的 JSON 行为仍未做完整 E2E。生产组合服务对失败直接抛出；本实验的已知拒绝基线回退是 benchmark 的显式策略，不是已发布的新生产容错保证。

机器产物：[确认报告](../../benchmarks/public_rag/results/evidence-set-20261023/confirmation-answers-1/report.json)、[最终验收](../../benchmarks/public_rag/results/evidence-set-20261023/acceptance.json)、[显式预设](../../benchmarks/public_rag/evidence-set-presets-20261023.json)、[确认分层](../../benchmarks/public_rag/results/evidence-set-20261023/confirmation-diagnostics.json)。本轮停止，不再用已曝光确认集调整提示词或参数。

## 验证与完整费用账本

**36 个不同的定向用例通过**：18 个新增用例覆盖原文/私有身份/生命周期、错误 ID、上下文预算、单次 Gateway、组合检索器保留快照与阈值、拒绝伪造原文、失败用量、额外计算预算、固定主比较、消息复用、两臂确认与单组推断；另 18 个既有知识 API/trace 投影用例验证新增内部阶段不改变公开响应。9 个相关 Python 文件格式检查与差异空白检查通过。没有新哈希测试或无依据的重复全库检查。

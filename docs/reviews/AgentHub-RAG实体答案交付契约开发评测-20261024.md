# AgentHub：论文实体答案交付契约开发评测

**已施工并完成实测，未通过开发推广门槛。** 32次真实调用全部完成。共享实体短值基线完整集合命中7/8，新契约6/8；后者在两题保住了正确部分状态，但也新增两次关系越界的部分交付，格式/名称锚定有效14/16，低于95%门槛。增加JSON状态与逐字引文，没有自动解决事实关系判定。本里程碑收口，停止调这批问题，不接入生产默认。

本轮落实[答案路径诊断的下一步](AgentHub-RAG答案路径三条件诊断-20261024.md)：将问题需要的实体事实、逐字来源与交付状态放到同一条可检查链路。实现隔离于benchmark实验目录，复用生产模型网关与ContextBudgetPolicy；没有新增公开API、自动问题分类器、自动改写或生产默认reader。

## 设计与公平比较

借鉴此前实际源码审阅中的PaperQA“读取、回答、完成”职责分离和RAGFlow可见证据身份管理，保留它们没有承诺的边界：模型报告“完成”与引用存在都不证明语义正确。固定源码入口见[架构调查](AgentHub-RAG完整问答架构与瓶颈诊断-20261024.md)。

**两组都输出实体短值与说明。** 基线使用实体列表、说明、不可回答标记与引用ID；新方案增加逐实体原文引文，以及完整、部分、缺据、需澄清四种状态。共同输入包括原问题、事先按问题确定的关系类型和相同原文包。这样，分数差异不能简单归功于新方案把长解释移出了答案字段。

候选的每个名称必须出现在所引原文中，引文必须逐字存在于当前实际可见来源；部分交付必须带缺口说明；材料超预算时在模型调用前拒绝，而不是悄悄截短后仍称充分。这只保证格式、名称与来源归属，**不保证引文建立了所问关系，也不保证模型已找全所有实体**。

原型与读取服务：[entity_delivery.py](../../benchmarks/public_rag/experimental/entity_delivery.py)；单批执行器：[entity_delivery_live.py](../../benchmarks/public_rag/entity_delivery_live.py)。关系类型在本开发切片由问题文本复核后显式传入，未实现任意用户问题的自动理解。一次有界补读留待这层契约通过验证后，不在本轮同时实现。

## 数据与预登记

从已有QASPER TRAIN缓存按固定问题文本规则选择14个候选，每篇最多一题，排除前两批生成问答的36篇论文。选题不使用旧答案、F1或人工标签；选定后才读取人工参考和原文。保留全部14题台账，最终活动8题：5个缺据对照、3个部分实体来源保留对照，两个方案、两种来源条件，共32次预定调用。选中的实际问题均为数据/语料问题，不外推成已覆盖模型实体任务。

排除原因包括作者自采Twitter流不适于原子名称判定、缺表格及原文、12数据集未完整列出、任务名与数据集名歧义、合成数据与WMT语种/划分粒度不清。没有看过本轮模型输出后换题。8题中有一题的原人工段落只写两个数据集，但同一提供原文包还明确描述ScienceIE开发集评估，因此事先将其纳入新实体标注；原参考字符串完整保留，不能把它当新人工金标。

完整与删除条件均为精确原文阅读视图，不是本轮真实向量检索结果。删除条件保留原身份、文本、顺序和相关干扰：例如保留词向量训练语料名称，却移除分类器评估语料，检验同名存在与任务角色的区别。部分对照包括问题明确要求三个Twitter语料但只保留两个名称。这些是受控证据删除诊断，不代表真实召回系统已经改善。

调用前登记了两处边界：SST按语料家族层级评分，SST-1/SST-2映射到SST家族，不据此宣称枚举完了所有子变体；PTB/Text8的字符级段落可显得局部完整，但完整材料还有WSJ10句法任务，因此全篇范围的部分交付存在争议。主分母保留8题，同时预定排除这两题观察6题核心切片；质量收益不能仅由这两题驱动。

来源复核是机器辅助，并非专家校准。独立子代理仅看到删除材料，认可8组保留实体的角色归属；其中11段引文有9段逐字匹配，另2段存在大小写或标点空格差异，原审阅保留，主执行者另存精确原文补充。引文检查没有被包装成语义准确率。

## 评分与运行边界

两组共同计算实体别名集合精确匹配、实体P/R/F1、短值对原始参考的EM/token F1。完整材料要求实体集合匹配且报告完整交付；缺据材料看错误完整交付、安全拒答，部分材料另看已支持实体的保留。原始值、说明与失败均保留，未完成或格式错误记零，不算成功拒答。金额没有可靠价格绑定时保持未知。

别名只按NFC、大小写和空白归一；没有任意子串命中、事后抽取正确片段或看答案后扩别名。这是预先标注实体和交付契约的评分，不是一般语义准确率；完整用户可见说明的支持仍需逐题复核。

开发门槛在调用前固定：完整实体集合表现不降、错误完整交付不增，且至少在完整集合、错误交付或安全部分覆盖上有一项严格收益；候选格式有效率至少95%，总观测tokens不超过基线1.6倍，32次请求完整且同一原始主模型，质量收益还需在6题核心切片保留。开发通过也不自动推广。

首选本机Magpie `auto/deepseek-v4.1-flash`，保留既有阿里云备用，但发生备用、未知传输或错误模型身份后停止后续派发。temperature=0、thinking disabled、每次输出1024tokens、原文预算8000个UTF-8保守单位，不重试、不以改提示补跑追分。

## 原始执行失败与补充登记

首批在第一道题外部派发前失败：当前模型档案的解析类型缺少冻结计划所需provider字段，退出码2，物理请求0、响应0。该批32题目的原始失败/未完成分母和报告保留；它不是成功完成的原登记批次。

修复仅将解析档案转换成带工作区和provider身份的冻结执行档案，并增加真实配置网关的离线`prepare_resolved`预检及回归测试。预检核对32份登记消息保持一致后，另登记只允许零派发情况下的新批次；第一批任何已发送或未知请求都不能走此修复路径。问题、来源、别名、提示、评分与预算未改。对应补充：[execution-amendment-1.json](../../benchmarks/public_rag/results/entity-delivery-20261024/execution-amendment-1.json)。

## 评分仪表修复

新批32次调用全部返回，随后发现评分器把网关`ModelUsage`中合法的可选`cached_tokens`字段当成未知字段，导致原`report.json`错误地将所有结果列为无效、用量未知。保留这份错误报告，修复只接受该正式契约中的可选非负字段，并增加带真实网关用量结构的回归检查；未改变实体别名、答案、状态判定、指标定义或门槛，也未再调用模型。

正确核算另存[report-v2.json](../../benchmarks/public_rag/results/entity-delivery-20261024/development-run-2/report-v2.json)，修复依据和前后评分源码分别保留在[评分修复记录](../../benchmarks/public_rag/results/entity-delivery-20261024/scoring-repair-1.json)及归档中。候选的两次真实契约失败仍记零，没有借仪表修复免除模型错误。

## 实际结果与决定

| 指标 | 同样输出实体短值的基线 | 新交付契约 |
|---|---:|---:|
| 完整材料实体集合命中并报告ANSWERED | 7/8 | 6/8 |
| 全部契约有效 | 16/16 | 14/16 |
| 缺据/部分材料安全交付 | 5/8 | 4/8 |
| 错误交付：完整冒领或值超出支持集合 | 3/8 | 3/8 |
| 正确PARTIAL状态 | 0/8 | 2/8 |
| 输入tokens | 13,980 | 16,668 |
| 输出tokens | 1,653 | 2,850 |
| 合计tokens | 15,633 | 19,518 |

新方案总tokens约**1.249倍**，满足1.6倍用量限制，但完整集合表现下降、契约有效率87.5%，未通过两项硬门槛。预定6题核心切片中，完整集合5/6对4/6，安全交付均4/6；错误交付2/6对1/6，正确部分状态0对2。局部状态收益确实存在，并非全部由两道争议题产生，但没有抵消整体失败。

字段名`wrong_full_delivery`沿用评分器记录，实际定义包含“报告ANSWERED”**或**“返回超出支持集合的实体”，因此不能读成新方案也有三次完整冒领：新方案是一次完整冒领加两次错误部分实体，基线是三次完整冒领。PARTIAL不是正确性的豁免状态。

短值对原始人工长参考的token F1为13.75%对10.07%，严格EM均0；原参考有整段解释、引用标记和多条独立文本，不能拿这一列与前轮47.15%/40.74%直接比较，更不能把新实体集合命中率称为用户语义准确率。按预登记未扩展别名：基线一处“CoNLL 2014 shared task test data”和候选一处带逗号的ScienceIE名称确实表达了正确标识，但不匹配冻结的原子别名。这一测量敏感性逐题保留，没有通过事后清洗提分。

实际派发32、接收32，原始返回模型均为Magpie `deepseek-v4.1-flash`，无备用接管、未知传输或服务错误。累计输入30,648、输出4,503、合计35,151 tokens，未知用量0，金额未知。全批P50约2.44秒、P95约3.22秒，不作小样本尾延迟保证。监督作业首批退出2/派发0，修复批退出0；不能把两次本地执行包装成原登记的一次连续成功。

## 逐题解释：有益部分与失败机制

**正确的部分状态有明确用途。** Twitter题明确问三个语料，材料只保留STS和HCR；两组均识别出两个，但基线同时报告ANSWERED并在说明中承认缺第三个，新方案报告PARTIAL并声明缺口。CoNLL题保留本模型的CoNLL2003小样本实验，同时留下此前工作中的CoNLL2000/PTB对比；新方案正确只保留当前关系中的CoNLL2003并报告部分状态。它们说明值、说明、状态需要保持一致，也为未来按缺口补读提供了可用接口；本轮没有真的执行补读。

**PARTIAL也被用来收纳仅仅相关的名字。** 分类器评估题删除了评估数据来源，新方案却把用于训练词向量的ukWaC放入部分答案，同时在说明中写它不是分类评估语料。另一题把背景中的“CoNLL shared tasks”放入部分答案，同时说明它只是历史上下文、不能确定本论文的评估集。两个例子名称与引文都可以逐字匹配，但关系不成立；这直接证明字面来源校验不能代替任务关系判定。基线在这两题拒答反而正确。

**两个严格契约失败是真实交付损失。** 一次CoNLL2014回答的事实内容正确，但展示名称拼合了原文不同位置的限定词，未作为完整名称连续出现在引文中，被逐字名称约束拒绝；另一次缺据回答遗漏必需的`explanation`键，被JSON契约拒绝。前者说明应区分原文实体提及与展示名称，后者说明新增必需字段会引入额外交付失败。这两次均未改提示或补跑，仍记零。

上述是可追溯个案分析，不是新增模型裁判准确率。实体集合指标检查注册别名，来源检查核对原文归属，用户可见说明和关系正确性仍需不同检查，不能再压成一个“引用正确”的指标。

## 留下什么，停止什么

保留隔离原型、明确的交付状态契约、真实来源约束、冻结执行计划与评分器，作为后续可复用实验基础；**本候选不注册为生产reader，不改变Citation QA或历史AgentVersion，不继续扫提示或在这8题上寻找通过版本**。本轮没有新增哈希测试或无关验收。

后续应先解决两个职责边界：原文实体提及与展示名称分开，避免把名称修饰当事实错误；交付实体必须支持所问关系，不能把MENTION_ONLY/RELATED当作PARTIAL。后一项需要独立、可校准的关系支持证据，不能只加一个模型自报字段或再让同一个模型说“有据”。在这一层通过清楚的新开发题验证前，不启动自动补读来放大错误状态，也不同时加入改写、拆解或图。

这次结果支持保留“有缺口的部分答案”这一产品语义，但否定了“加复杂JSON、逐实体引文和模型自报状态就足以可靠交付”的实现假设。下一次若实施，需要新的来源明确样本和固定验收，不覆盖本轮负结果。

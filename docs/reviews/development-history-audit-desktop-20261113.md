# Development History 桌面宽屏布局审查（2026-11-13）

> 原始布局供稿。尺寸观察已纳入 [最终审查报告](<E:/JAVA/AI+agent/AgentHub/docs/reviews/AgentHub-开发历程学习文档审查报告-20261113.md>)；最终报告将宽屏问题统一列为 P2，并优先建议图与步骤说明并排。下文具体断点和多栏结构属于备选设计，尚未实现或做原型验证，不要求照搬。

## 1. 审查边界

本次只审查 docs/development-history/index.html 在电脑宽屏下的空间分配，重点是：

- 1920px 与 2560px 桌面宽度；
- 正文、本章目录、学习动画和源码查看区域之间的宽度关系；
- 2K 屏右侧留白是否被布局规则放大；
- 普通阅读与“动画演示/源码对照”是否需要一个明确的宽屏模式。

本次不审查手机布局、业务含义、术语、文案准确性、视觉品牌或交互语义。报告中的“问题”均指布局能力不足；后文“建议”均为尚未实现的设计方案，不能视为已修复。

## 3. 实测与静态规则（观察）

### 3.1 1920px 与 2560px 的关键尺寸

三个 1920px 页面与三个 2560px 页面的正文、目录尺寸一致。下表取 business 页面作为代表：

| 指标 | 1920 CSS px | 2560 CSS px | 观察 |
|---|---:|---:|---|
| 左侧学习目录 | 270 | 270 | 固定宽度 |
| 阅读区 | 1650 | 2290 | viewport 减 270 |
| book-layout | 1320 | 1320 | 两种宽度完全不变 |
| book-layout 左边缘 | 427.4 | 747.4 | 在阅读区内居中 |
| 正文 | 840 | 840 | 宽度完全不变 |
| 正文左边缘 | 472.4 | 792.4 | 跟着居中外框移动 |
| 本章目录 | 180 | 180 | 宽度完全不变 |
| 正文左余 | 202.4 | 522.4 | 阅读区左缘到正文左缘 |
| 目录右余 | 385.6 | 705.6 | 本章目录右缘到阅读区右缘 |
| 正文占阅读区 | 50.9% | 36.7% | 宽屏占比进一步下降 |

结论是明确的：从 1920px 增加到 2560px 时，阅读区增加 640px，而 book-layout、正文和本章目录的宽度都没有增加。2560px 截图中的大面积右侧空间不是单个页面的内容长度造成，而是稳定复现的容器上限和固定栏目组合造成。

对应 DOM 位置在第 17 行：book-layout 直接由 article.chapter-article 和 nav.chapter-toc 两个格子组成。学习实验由第 71 至 93 行挂载在同一 article 内，因此没有机会跳出 840px 正文轨。

### 3.3 正文行宽本身是合理的

当前 17px 正文配合 840px 宽度，换算约为 49.4em；切到大字阅读 19px 后约为 44.2em。对于中文长文，这个数量级尚未失控，尤其 19px 状态仍在可读范围内。

因此，不能把“正文只有 840px”本身列为缺陷，也不应为了让 2K 屏看起来“填满”而把全部长文铺到 1500px 以上。真正需要修正的是：普通正文没有可用的宽屏结构，学习实验也没有从正文轨中 breakout 的机制。

### 3.4 学习实验当前仍被锁在正文卡片里

history-browser-evidence.json 的 approvalGeometry 给出了实际尺寸：

- learning-lab 容器宽：840px；
- 流程图实际宽：794.4px；
- 步骤说明宽：794.4px，高：704.75px；
- 控件宽：794.4px。

这与 CSS 一致：840px 正文减去 learning-lab 两侧各 22px padding 和边框后，内部约 794px。第 88 行动态写入 SVG 时使用 min-width:Math.min(w,780)px，因此当前流程图在约 780px 左右形成稳定图形宽度。

history-approval-graph-desktop.png 也显示当前阅读顺序是：控件、流程图、图例、步骤条、说明全部纵向堆放。内容本身完整，但在更宽的屏幕上没有任何空间上的对照关系。

### 3.5 源码查看是模态浮层

第 50 行 showSource 将源码写入 sourceDialog；第 19 行的对话框在第 3 行第 6368 列定义为 width:min(1050px,94vw) 的居中浮层。它适合临时查看源码，却不支持“步骤解释保持在左侧、源码保持可见、当前动画仍可操作”的常驻对照。

## 4. 优先级问题（观察与影响）

### P1：1750px 宽屏断点没有重新分配空间

**观察：** @media(min-width:1750px) 只改变 padding-top 和 h1 字号；book-layout 的 1320px 上限、840px 正文和 180px 目录都没有变化。

**影响：** 规则名称让人以为页面已有宽屏布局，实际 2K 屏只得到“更靠中间的同一条 840px 阅读列”。2560px 下目录右余 705.6px，正文占阅读区 36.7%。

**位置：** docs/development-history/index.html 第 4 行第 1 列；基础规则在第 3 行第 1912 列。

### P1：学习实验不能从正文轨 breakout

**观察：** article、learning-lab、lab-graphic、lab-explanation 和 sourceDialog 是彼此分离的结构；常驻页面中没有任何格子让实验使用正文右侧空间。

**影响：** 动画、解释和源码只能在 794px 左右的内容宽度里纵向排列。2K 屏幕增加的宽度不能提升流程可见性，也不能建立动画与源码的并列关系。

**位置：** .learning-lab 第 7 行第 16 列；.lab-graphic 第 7 行第 833 列；动态挂载第 75 行；SVG 写入第 88 行；说明写入第 91 行。

### P2：本章目录在宽屏上仍固定为 180px

**观察：** 2560px 截图中很多目录项仍然换行，而目录右侧仍有 705.6px。目录轨没有在宽屏获得 220 至 260px 的可读宽度。

**影响：** 可用空间与导航可读性没有形成交换关系。这里不是文案问题，而是固定轨道没有响应可用宽度。

**位置：** .book-layout 第 3 行第 1912 列；.chapter-toc 第 3 行第 4634 列。

### P2：源码对照没有空间模式

**观察：** 源码浮层最宽可到 1050px，说明源快照本身适合桌面查看；但用户必须中断当前动画上下文，关闭浮层后再回到步骤说明。

**影响：** 宽屏已经具备永久并排显示“动画/说明 + 源码”的空间，却没有相应模式。这既是学习效率问题，也是可验证的布局缺口。

**位置：** 对话框 DOM 第 19 行；showSource 第 50 行；dialog CSS 第 3 行第 6368 列；source-code CSS 第 3 行第 6843 列。

## 5. 设计建议（均未实现）

### 5.1 总原则

1. 普通阅读保留 800 至 860px 的正文宽度，默认沿用当前 840px。
2. 宽屏增加的是有用途的布局容量：可读目录、学习实验、源码对照。
3. 不新增装饰卡片，不在空白处塞统计块、渐变块或无内容侧栏。
4. 用阅读区宽度做 container query，而不是继续依赖“看起来像宽屏”的 viewport 断点。
5. 对照模式需要显式进入和退出；普通滚动不应突然改变整页阅读 geometry。

### 5.2 模式 A：普通阅读

建议在阅读区宽度小于 1800px 时保留当前 geometry。因此 1920px viewport 的 1650px 阅读区不自动变化。

阅读区达到 1800px 后，可采用以下宽屏普通阅读布局：

| 区域 | 建议宽度 |
|---|---:|
| 固定学习目录 | 保持 270px |
| book-layout 外框 | max-width 建议 1440px，两侧居中 |
| 正文轨 | 800 至 860px，默认 840px |
| 本章目录轨 | 220 至 260px |
| 最小栏间距 | 48px；宽屏可让目录靠近外框右缘 |
| 横向 padding | 56 至 64px |

在 2560px 下，建议 book-layout 从 1320px 增至约 1440px，正文仍为 840px，本章目录可增至约 240px。外框内部可使用 space-between 让目录靠近右缘；预计目录右余由实测 705.6px 降至约 489px，同时正文不被拉宽。

这个模式仍然允许正文周围存在留白。留白是维持行宽的结果；只要左右视觉重心平衡、目录不再因固定 180px 而过度换行，就不需要为了“填满”而添加装饰。

建议布局示意：

~~~text
viewport 2560

┌──────────── 270 ────────────┬──────────────────── reading 2290 ────────────────────┐
│ 固定章节导航                │            建议 book-layout 约 1440，居中          │
│                             │   [ 正文 840 ][ 可伸缩间隔 ][ 本章目录 220-260 ]  │
│                             │   正文不再加宽；目录可读；余白左右平衡             │
└─────────────────────────────┴──────────────────────────────────────────────────────┘
~~~

建议的 CSS 落点不是新增装饰结构，而是修改现有：

- .reading-area 设置 container-type:inline-size，供后续查询；
- .book-layout 在阅读区宽屏条件下重设 max-width、grid tracks、gap 和 justify-content；
- 复用现有 .chapter-article 与 .chapter-toc，不改变两栏 DOM 顺序。

### 5.3 模式 B：动画演示/源码对照

建议在阅读区宽度达到 2100px 时提供“对照”入口。1920px viewport 的阅读区只有 1650px，不进入此模式；2560px viewport 的阅读区为 2290px，满足条件。

该模式用于当前正在操作的学习实验。进入后：

- 本章目录收进顶部工具或抽屉，退出对照时恢复；
- 正文左侧保留当前章节上下文，宽度 680 至 720px；
- 右侧出现学习工作台，宽度 1280 至 1360px；
- 工作台内部左侧是动画与步骤说明，宽度 780 至 820px；
- 工作台内部右侧是常驻源码快照，宽度 480 至 540px；
- 两栏间建议 24px；
- 页面外框 max-width 建议 2160px，横向 padding 40px。

这套宽度组合在当前 2560px 证据下是可行的：阅读区 2290px 大于外框 2160px；外框仍留约 65px 左右的外侧空间。工作台左侧 800px 左右可以保持当前流程图约 780px 的图形尺度，右侧 500px 左右足以显示源码，并由源码自身负责横向滚动。

建议布局示意：

~~~text
viewport 2560；模式 B

┌──── 270 ────┬──────────────────────── reading 2290 ──────────────────────────────┐
│ 固定章节导航 │                 建议对照外框 max-width 约 2160                  │
│              │                                                               │
│              │ [正文上下文 680-720][40][ 学习工作台 1280-1360 ]             │
│              │                          [动画/步骤 780-820][24][源码 480-540]  │
│              │                                                               │
│              │ 本章目录改为工具入口，不占用第三列                              │
└──────────────┴───────────────────────────────────────────────────────────────┘
~~~

工作台内部建议保持现有内容顺序：

~~~text
学习工作台
├─ 控件、场景与步骤条
├─ 左列：流程图
├─ 左列：当前步骤说明与状态变化
└─ 右列：现有源码快照
   ├─ 路径、符号与哈希元数据
   └─ 可独立滚动、复制的 source-code
~~~

源码面板应复用现有 source/source-code 数据和选择入口，不要求本轮设计改变数据含义。若当前步骤没有可用的源码关联，本报告不建议临时发明映射；空间上可以只提供本章源码清单，具体关联逻辑应另按产品契约处理。

在阅读区小于 2100px 时，不进入并排模式，保留当前正文内 stacked 实验和 sourceDialog。这个 fallback 与 1920px 证据相容。

### 5.4 建议阈值与退化顺序

| 阅读区宽度 | 建议状态 |
|---:|---|
| 小于 1250px | 沿用现有窄屏单列规则；手机不在本次审查范围 |
| 1250 至 1799px | 当前普通桌面布局 |
| 1800 至 2099px | 宽屏普通阅读；正文仍不超过 860px，目录可加宽 |
| 2100px 及以上 | 提供显式“动画/源码对照”入口；未进入时仍是宽屏普通阅读 |

阈值应优先写在 .reading-area 的 container query 中。若项目运行环境不允许 container query，再使用与 270px 固定目录匹配的 viewport 阈值作为 fallback；不要只写 min-width:1750px 却继续保留所有固定栏宽。

## 7. 审查结论

当前桌面阅读本身没有明显行宽灾难，840px 正文应被保留。主要问题是布局缺少“宽屏容量如何使用”的第二层规则：1750px 断点只修饰标题，学习实验仍留在 840px 正文内，源码只能模态查看，180px 目录即便在 2560px 也不扩张。

因此建议采用两个明确模式：普通阅读以约 1440px 外框、840px 正文和可读目录维持舒适行宽；学习对照模式在阅读区达到 2100px 时，将现有正文、动画和源码重新组织为“上下文 + 工作台双栏”。2K 屏的价值应体现在实验与证据对照上，而不是把所有长文铺满屏幕。

# 原文片段定位与答案生成：实施与评测

2026-10-23。用户要求进一步优化“拿到材料后如何得到答案”，并要求机制有开源依据。本轮实现一个固定的两阶段 reader，完成真实 API 开发评测。**质量门槛未通过，保留原直接回答默认；不开新确认、不调提示或预算，本里程碑收口。**

## 结果与决定

固定使用此前已曝光的 MuSiQue train 160 题、143 个共享支持原文组，以及已验收互补选择产生的相同最终可见原文。没有改变召回、候选集合、原文、来源或顺序；不能与上一轮来源隔离的 200 题成绩混算。

| 指标 | 历史直接回答 256，上轮结果复用 | 同批直接回答 768，主对照 | 先定位 512＋回答 256 |
|---|---:|---:|---:|
| 答案 token F1 | 61.22% | **60.78%** | **63.06%** |
| 答案 EM | 49.38% | 48.75% | 52.50% |
| 支持段落召回 | 90.99% | 90.99% | 90.99% |
| 完整支持段落集 | 76.88% | 76.88% | 76.88% |
| 实际答案请求证据 payload bytes 均值 | 未重新发送 | 3357.94 | 3855.02 |

唯一主比较为“两阶段”对“同批直接回答 768”：F1 **+2.28 个百分点**，按共享支持原文分组进行 5000 次配对 bootstrap 的 95% 区间 **[-1.11, +6.00] 个百分点**。既未达到预登记的 +3pp，也没有正区间。EM 净增 6 题：新增完全匹配 10 题，同时损失原来完全匹配的 4 题。不能将点估计上涨表述为已验证的稳定提升。

原文定位 **154/160 有效**；3 次已知服务拒绝、3 次本地片段校验失败，均按预登记使用相同原始 256 请求的旧结果回退，包含旧失败。总输出上限相同只是控制最大输出配额，不等于实际计算量相同。157 个用量完整配对问题上，两阶段总输入为直接对照的 **2.216 倍**；增量模型流水线 P95 **3008 ms 对 1008 ms，2.983 倍**。这是模型流程比较，不是完整业务 Run 的 SLO。

门槛还要求最终引用 ID 全部可见。两阶段管线有 1 题、2 个越界 ID，**来自历史直接回答回退**；154 个有效两阶段请求没有新增越界 ID。对照和历史组也在同一题有相同的 ID 问题。没有删掉该题或修补模型生成的 UUID 来让门槛通过。

最终冻结选择为原直接回答；新服务保留实验实现，未注册为公开 API 或全局 runtime 默认，没有发布业务 AgentVersion。[预登记协议](../../benchmarks/public_rag/results/attributed-reader-20261023/protocol.json)、[开发报告](../../benchmarks/public_rag/results/attributed-reader-20261023/development-run-1/report.json)、[冻结决定](../../benchmarks/public_rag/results/attributed-reader-20261023/development-run-1/frozen-selection.json)保留全部分母及失败。

## 方法来源：实际开源管线，不把借鉴当复现

1. **Attribute First, then Generate**：[实际完整管线](https://github.com/lovodkin93/attribute-first-then-generate/blob/main/few_shot_experiments/run_full_pipeline.py)先执行 content_selection，再执行 clustering＋iterative_sentence_generation，或直接执行 fusion_in_context；[来源片段定位和高亮处理](https://github.com/lovodkin93/attribute-first-then-generate/blob/main/few_shot_experiments/utils.py)检查原文范围，再构造带高亮的阅读文本。其原任务为多文档摘要/长答案；这是研究型开源实现，不等同成熟企业产品。迁移到我们的英文短答是待检验假设，本轮不借用其指标或声称完整复现。
2. **HippoRAG**：[MuSiQue 回答模板](https://github.com/OSU-NLP-Group/HippoRAG/blob/main/src/hipporag/prompts/templates/rag_qa_musique.py)明确区分阅读分析和最终短答案；[IRCoT reason_step](https://github.com/OSU-NLP-Group/HippoRAG/blob/main/src/hipporag/utils/qa_utils.py)还会利用中间内容继续检索。本轮只借鉴“阅读与最终输出分开”的职责，没有复制其 few-shot 样例，没有使用数据集金标分解，也没有新增检索循环。

以上为当日读取的公开源码，不声称固定提交复现。没有导入其框架、照抄完整提示或更换模型，也没有复制上游重试、宽松文本匹配和其它与本项目约束不一致的行为。

## 实际实现

新增实验区的[AttributedEvidenceReader](../../benchmarks/public_rag/experimental/attributed_reader.py)，通过标准 ModelGateway 契约提供 `prepare` / `read` 两阶段接口。实验适配器保持固定 `deepseek-v4.1-flash-1017`、temperature 0、thinking disabled、JSON-object 模式，每阶段只尝试一次，无模型 fallback。

第一阶段只选择问题需要的**原文引用片段**，包括中间实体的识别和题目所问属性，最多 8 条、每条 8～600 字符、合计不超过 2000 字符。输出只能包含来源 ID 和逐字引用，不允许输出答案、自由生成事实或推理文本。本地检查来源确实可见、引用是 snippet 的精确子串，并由服务器计算位置。复制不准确、超过预算、来源不明或空计划都不能当作可靠材料。

第二阶段在原有记录中附加 `reading_quotes`，**原 snippet、顺序、refs、locator、标题、生命周期和全部原始字段保持不变**。继续使用相同 8000 证据预算及 ContextBudgetPolicy；若高亮造成原文或原消息被裁剪，则拒绝该准备结果。没有用生成摘要替换原文，没有通过一条“笔记”暗中加入新的事实。

最终交付另加严格答案结构与可见引用 ID 校验：会拒绝未知/重复引用、无证据编号的非空回答以及矛盾的拒答字段，错误不会变成新请求重试。**精确片段存在和引用身份合法都不证明语义蕴含或答案正确。**本轮没有增加在线语义判官，也未改动既有 Citation QA 的严格结构化输出能力要求。

生产服务直接传播准备或模型失败；上述历史回退是实验的明确策略，不是新发布的生产容错保证。实验只使用 `prepare` 后的相同生成契约评分；最终交付守卫的严格结果另做离线描述性诊断，不事后改写预登记主分数。

## 评分如何隔离“更多计算”的影响

主对照直接回答允许最多 768 输出 tokens；新方案两阶段分别 512 和 256，合计同为 768。原 256 请求的全部历史结果仅作描述性对照，在检查原准备目录、配置、消息往返转换一致后复用；没有为了增加一个对照组重复支付 160 次相同请求。

两阶段不能因先看到答案或评分再决定方法。已知拒绝、非法片段和预算失败按预登记回退；未知结果、错误模型或非 400 服务错误立即停止，所有在途请求等完并记账。模型温度 0 也不视为绝对确定。

在首个真实两阶段题完整通过之后才分派其余题。全部 160 题进入评分，未按是否答对、是否有引文或是否 API 成功删样本。候选方法、提示、总配额、F1/EM、引用、用量覆盖及延迟门槛在调用前登记；只做这一个主比较。没有用已曝光的前两轮确认集反复选方法，也没有新留出曝光。

## 失败归因与下一步边界

独立 DeepSeek 先审阅固定 DEV 中最多 8 个失败案例，再为服务编写独立测试，主执行者负责实现、实验与最终审查。有限案例显示了几种不同问题：可见的跨段关系没有连接、题目属性与相邻日期混淆、行政层级停在中间实体、原文关键跨度缺失、别名词形不被官方词面评分覆盖，以及 provider 拒绝。没有将这些都归成推理错误。

新方法有局部帮助：例如“Francys 的死亡地对应哪座山，再问其被发现前的最高山”一题，直接对照拒答，新方法得到 `Kangchenjunga`。但“海生普查的执行时期”仍被回答为结果发布年份 `2010`；目标 regional municipality 仍被回答为 province；rural district 与 district 的区分也没有解决。名字拉丁化差异同样保留原词法分数，未用语义重判把新成绩抬高。

因此，当前证据只说明**原文定位可能帮助部分连接，尚不足以稳定完成问题所要求的属性和层级判断**。同一批原文里的事实有多个时间、地点或行政层级，标出句子不能自动选对关系；某些官方答案本身也存在歧义，需要人工核对。单纯再加一次通用阅读调用没有充分成本收益证据。

完整支持段落的 123 道开发题中，直接对照 EM 命中 64 题、新方法 70 题；这一子集是事后描述，段落完整不等于 gold 事实 span 完整，不能另立一个“子集显著”结论来覆盖主门槛失败。

后续若继续质量研发，应先把“问错属性/层级”“实体别名”“关键事实未实际可见”“真正缺证据”分开标注，再决定针对哪个可验证问题引入回答机制。当前 160 题只可用于开发诊断；本轮不立刻改变指令重测、不新加一轮模型自评、不宣布语义支持已实现。[事后诊断](../../benchmarks/public_rag/results/attributed-reader-20261023/development-diagnostics.json)保留原输出及严格交付守卫结果。

## 验证与成本

22 个不同定向测试通过：19 个 reader 用例覆盖精确片段、来源、总量、消息/引用/生命周期保留、预算、两阶段调用和能力要求、错误模型、无重试及最终引用守卫；3 个实验评分用例覆盖主对照不可替换、失败准备/原文改变不能通过、缺失用量不能当零开销。160 份真实已准入消息通过离线兼容检查；这只是结构验证，不作为质量成绩。没有哈希测试、全库重复回归或 GPU 重建索引。

本轮实际 **474 次新请求**：**465 VALID、6 已知 HTTP 400、3 次 HTTP 成功但片段校验失败**，UNKNOWN_OUTCOME 0。观测 total tokens **710,026**，468 次用量可见、6 次未知；没有价格快照，不估货币金额。历史对照复用 160 份，回退复用 6 份，均不计作新物理请求；逻辑部署成本中仍计入回退答案的历史观测成本/时延，避免把复用当成免费。

新 reader 已隔离在 `benchmarks/public_rag/experimental`，没有留在生产 knowledge 包中；质量未通过的机制不增加生产策略开关。默认未切换，本轮没有公开 API、业务 AgentVersion、其它知识版本或索引变更。受控的英文给定候选、固定单次搜索，不覆盖真实 SQL/Qdrant、租户授权、检查点、完整 Run、中文业务或不可回答负样本。不是平台 Formal Experiment，也没有人类校准的语义引用分数。预登记质量失败后不开确认，任务没有后台作业等待。

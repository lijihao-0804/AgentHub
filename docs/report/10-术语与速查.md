## 2. 八个节点（背下来）

```
prepare → model → tool_proposal → policy → {read_execute | action_execute} → observation → finish
```

| 节点 | 做什么 |
|---|---|
| `prepare` | 三重完整性校验 + 按语义顺序装配消息 |
| `model` | 调模型 |
| `tool_proposal` | 解析工具提议，查上限（`max_tool_calls` / `max_identical_calls`） |
| `policy` | `ToolPolicy.decide()`，分流 |
| `read_execute` | READ 自动执行 |
| `action_execute` | 批准后的 WRITE 执行 |
| `observation` | 结果回灌上下文 + 触发 Artifact 投影 |
| `finish` | 收尾 |

**固定边只有四条**：`__START__→prepare`、`read_execute→observation`、
`action_execute→observation`、`finish→__END__`。其余全是条件边。

## 9. 十条「不做会怎样」（最高频的追问形态）

| 做了什么 | 不做会怎样 |
|---|---|
| 冻结快照 | 三天前的 Run 无法解释 |
| 默认拒绝 | 字段缺失/拼错会静默变成自动执行 |
| 持久中断 | 审批挂住协程，进程重启丢状态 |
| 同 Run 恢复 | 审计要跨 Run 拼；预算被重置绕过 |
| 双维度审批状态 | "批了但失败"表达不出来 |
| UNKNOWN_OUTCOME | 重复退款 / 假成功 |
| 保留参数名 | 模型注入 `workspace_id` 越权 |
| 信任盖章 | payload 自我提权（提示注入） |
| 结构化截断 | 模型以为看到了全部，报错误的总数 |
| 按组驱逐 | 孤儿 tool 消息，API 直接 400 |
| 知识快照 | 评估结果差异无法归因 |
| 留出集暴露计数 | 沉默地过拟合到留出集 |
| SSE 白名单 | 工具返回值泄漏到浏览器日志 |
| 单一 head | 两条分支各加五个迁移后无法确定合并顺序 |
| 记忆快照 | 开了记忆之后 Run 就不可重放了——「它当时拿到了哪几条」事后再也答不上来 |
| 检索模型预热 | 每次部署后第一次 `search_knowledge` **必然** TOOL_TIMEOUT，而且表现成"知识库里没有这条" |

## 10. 五句「原话」（能背下来最好）

1. *"A literature assistant that invents a DOI, an incident agent that invents a
   deployment SHA, an analyst that invents a row count and a support agent that
   invents a refund deadline are **the same defect wearing four costumes**."*
   —— 反幻觉规则为什么四个应用共用

2. *"The contract is immutable; the credential is not, and **that asymmetry is
   deliberate**."*
   —— 为什么契约冻结但密钥不冻结

3. *"**Never allow a payload to promote itself.**"*
   —— 工具结果为什么强制 UNTRUSTED

4. *"The parser is the **explanation**... the read-only connection is the
   **guarantee**."*
   —— SQL 双层守卫为什么不冗余

5. *"A host that answers with one public and one private record is **rejected
   outright**: accepting it would mean the decision was made by whichever record
   the connection happened to pick."*
   —— DNS rebinding 为什么要整体拒绝

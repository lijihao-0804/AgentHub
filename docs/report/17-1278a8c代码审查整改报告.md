## 二、P1 修复详情

### F-01 — ORM metadata 必须与迁移建出的 schema 一致

**问题实质**：`0023` 建了复合外键 `fk_agent_runs_thread_workspace`，`0026` 建了带谓词的局部索引 `ix_documents_superseded_by`，但两者都只存在于迁移脚本里。对 `alembic check` / autogenerate 来说，“迁移里有、metadata 里没有”的对象就是**应当被 DROP 的对象**——下一次自动生成迁移会把它们删掉。这是一个会在未来某次例行操作中静默发生的破坏。

**修复**：

- `packages/agent_runtime/models.py`：在 `AgentRun.__table_args__` 中补上同名 `ForeignKeyConstraint`，指向 `agent_threads.(workspace_id, id)`，`ondelete="SET NULL"`，与 `0023` 完全一致。
- `packages/knowledge/models.py`：在 `Document.__table_args__` 中补上 `Index("ix_documents_superseded_by", ..., postgresql_where=...)`。**谓词必须写进来**：检索路径几乎对每个 chunk 都要问一次“是否已被取代”，而绝大多数行的答案是 NULL，谓词是这个索引身份的一部分；漏掉谓词等于声明了另一个索引。

**验证**：程序化读取 `Base.metadata`，确认 `agent_runs` 的外键集合包含 `fk_agent_runs_thread_workspace` 且解析到 `['agent_threads.workspace_id', 'agent_threads.id']`、`ondelete: SET NULL`；`documents` 的索引集合包含 `ix_documents_superseded_by`，列为 `['superseded_by_document_id']`，`where: superseded_by_document_id IS NOT NULL`。新增单元测试固化这两条（见第五节）。未新增任何迁移，Alembic 仍是单一 head `0027_agent_run_events`。

### F-02 — 重复 `client_token` 必须落到它已经创建的那次 Run

**问题实质**：`open_turn` 对重复 token 返回 `None`（它拒绝创建第二个 turn），而 `stream_turn` 拿到 `None` 之后直接返回了一个什么都不会发生的空流。调用方于是既拿不到 run id，也拿不到任何事件——幂等性在同步路径上是对的，在流式路径上等于失效。

**修复**：

- `packages/threads/service.py` 新增公开方法 `token_turn(context, thread_id, client_token)`，把已有的内部 `_require_token_turn` 暴露出来。这是让调用方“找到 token 已经创建的那个 turn”的唯一正当入口。
- `apps/api/routes/threads.py`：重复 token 分支改为取回既有 turn，并对它的 `agent_run_id` 调用 `attach_stream` 从 **sequence 0 重放**。因为事件日志是持久化的，这次重放与“第一次请求没有断线时本该收到的流”逐帧等价。
- 竞态兜底：turn 已存在但 `agent_run_id` 还没挂上（两个请求同时进来），返回 `409 THREAD_TURN_IN_PROGRESS`，让调用方带同一个 token 重试——而不是给一条永远不会有内容的流。
- 响应头继续带 `X-AgentHub-Run-Id` / `X-AgentHub-Turn-Id`，所以 `Run #xxx / View Run` 在重试路径上同样可用。

### F-03 — `workspace_read` 不该买到 prompt 与模型输出

**问题实质**：`/agent-runs/{id}` 只要求 `workspace_read`（VIEWER 就有），却把 `input_text` 和 `final_output` 原样返回。这两个字段是用户输入的原文和模型写回的正文，和 M6 可观测性投影刻意只给“身份/状态/计数/用量/成本”的安全面是两回事。

**修复**（`apps/api/routes/agent_runs.py` + `apps/api/schemas/agent_runs.py`）：

- 新增 `_run_response(context, run)`：持有 `agent_run` 权限的调用方拿到完整对象；只有 `workspace_read` 的调用方拿到同一个对象，但 `input_text` / `final_output` 为 `None`。
- `AgentRunResponse` 的这两个字段改为 `str | None`。**字段本身的存在是冻结契约的一部分，内容不是**——所以是置空而不是删字段。
- 四个返回 Run 的端点（create / get / cancel）统一走这个投影。
- **没有新增任何 RBAC permission**：复用既有的 `agent_run`——能运行这个 Agent 的人，才能读发给它的内容。

**前端连带修改**（否则类型层面会掩盖这个边界）：

- `apps/web/lib/api/agent-runtime.ts`：`input_text` 改为 `string | null`。
- Playground 恢复路径：`setInputText(run.input_text ?? "")`，避免把 `null` 渲染成字符串。
- Run 详情页“重跑”：输入为 `null` 时抛出 `PERMISSION_DENIED`，并给出中英文提示（新增 `run.replay.inputWithheld`）。**没有原始输入的重跑是一次顶着同一个名字的不同运行**，拒绝比猜测诚实。
- Run 对比页：两侧都为 `null` 时不再判定为“输入相同”——看不见两个 prompt，不构成它们相同的证据。

## 三、P2 修复详情

### F-04 — 前端必须使用 `after_sequence` 重放

**问题实质**：后端已经有 `GET /agent-runs/{run_id}/stream?after_sequence=N` 和持久化事件日志，前端一行都没用：刷新时只读一次持久化对象（活动时间线全部丢失、运行中的 Run 直接冻结在快照上），断线时直接报错。持久化事件日志的价值等于没兑现。

**修复**：

- `apps/web/lib/api/agent-runtime.ts`：
  - 把 `streamAgentRun` 的读循环、错误信封解析和取消处理抽成共享的 `consumeEventStream`；
  - 新增 `followAgentRun(input, { runId, afterSequence, signal, onEvent })`，走 GET + `Authorization` + `after_sequence`。
- `apps/web/app/agents/[agentId]/playground/playground-client.tsx`：
  - 新增 `lastSequenceRef`，在 `handleEvent` 这一个入口统一推进游标（live 和 replay 都经过这里）；
  - `?run=` 恢复：先读持久化 Run（它是状态/用量/归属的权威），随后**从 sequence 0 重放**把活动时间线补回来；如果 Run 还没结束，重放会直接接进实时流——刷新是“接回这次运行”，不再是“只报告这次运行”；
  - 实时流断开：带 `lastSequenceRef` 重连，最多 3 次、线性退避；服务端明确拒绝（HTTP ≥ 400）不重试，无 run id 不重试；
  - `pushActivity` 按 `sequence-type` 去重，重放与实时重叠时不会出现重复条目。

**关键正确性依据**：`message.delta` **不入库**（`event_store.py` 明确排除，否则日志规模会随 token 数增长，只为买回一个打字动画）。所以重放重建的是运行的**结构与最终输出**，不是键入过程——这正是重放不会把答案追加两遍的原因。

**兼容性**：Playground 仍是单次调试面板，`thread_id IS NULL` 的运行行为未变；恢复路径在重放开始前就释放 `busy`，否则会把“刷新本该交还的取消按钮”一直禁用着。

### F-05 — `/runs?status=...` 深链首次加载

**问题实质**：URL 里的筛选条件被 `setStatus` 写进了控件，但首次加载捕获的 `refresh` 闭包里还是空值——于是深链拉回全部 Run 且不再重新请求，页面显示的恰好是用户没要的东西，直到手动点一次 Apply。

**修复**（`apps/web/app/runs/page.tsx`）：把解析出的筛选条件额外存进 `urlFilters` 状态，首次加载等它就绪，并把筛选条件显式传给 `refresh(null, urlFilters)`，不依赖闭包。

### F-06 — 读路径不该上行锁

**问题实质**：`get_run` 里的 `.with_for_update()` 让详情页、步骤列表和每一个重连的流跟随者都去排队等待正在写 status/usage/output 的 worker。

**修复**（`packages/agent_runtime/runtime.py`）：读路径改为普通 `select`。加锁属于真正修改这一行的变更路径。

### 附带重构：SSE 组帧只保留一份

`apps/api/routes/agent_runs.py` 与 `apps/api/routes/threads.py` 各有一份心跳 + 取消处理的组帧实现。已统一收敛到 `packages/agent_runtime/sse.py::sse_frames(stream, *, heartbeat_seconds)`。两份拷贝就是两个让心跳与取消语义各自漂移的地方。关闭该生成器（即客户端断开）关闭的是订阅，不是运行。

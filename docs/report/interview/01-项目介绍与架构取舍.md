# 01 · 项目介绍与架构取舍（12 问）

基线与使用方法见 [本组入口](README.md)。这一篇先把项目讲成一个能理解的系统，再解释为什么需要这些模块。

## A01｜一分钟介绍这个项目

**可这样回答：**

> AgentHub 是一个用于管理和执行 Agent 的工程项目。它覆盖工作区权限、知识库、工具接入、Agent 版本发布、运行记录、人工审批和评测。核心场景是：用户提出一个问题，Agent 可以检索文档、查询业务系统；需要执行受治理动作时暂停并等待审批，完成后保留版本、工具和产出的证据。上层有科研、故障排查、分析、客服四类界面，共用运行时。项目重点是让执行过程能被解释、被限制、被恢复和被验证。

**继续追问：这有什么实际用途？** 用客服作为例子：查客户信息、检索处理规则、提出开工单动作、人工审批、查询最终状态。这里用的是可演示业务链路，不等于已经在真实企业生产落地。

**证据：** [应用说明](../04-四大应用.md)、[运行时](../../../packages/agent_runtime/runtime.py)、[工具执行](../../../packages/tools/actions.py)。

## A02｜你究竟实现了哪些东西，哪些是框架提供的？

**可这样回答：** LangGraph 提供图执行和 checkpoint 能力，LiteLLM 适配模型调用，Qdrant 承担向量索引，Celery 承担任务投递与执行。项目自己的部分是领域对象和规则：AgentVersion 的冻结内容、工具治理判定、审批与执行状态、动作身份、上下文准入、记忆快照、实验身份、对账以及应用产出投影。

**继续追问：所以你只是拼框架？** 不要回答“没有用框架”。应该拿一个框架无法直接决定的规则证明边界：远端写请求超时后是否重试，是业务安全语义；LangGraph 的 checkpoint 不会替我们证明远端没有执行，也不会决定工作区成员可看哪些字段。

**证据：** [框架边界 ADR](../../adr/ADR-003-langgraph-adapter-boundary.md)、[网关](../../../packages/model_gateway/gateway.py)、[审批契约](../../../packages/approvals/contracts.py)。

## A03｜最值得讲的三个技术点是什么？

**可这样回答：** 第一，发布时生成不可变解析快照，解决配置变化后无法解释历史运行的问题。第二，把审批、动作执行和运行状态分开，配合幂等与对账处理崩溃窗口。第三，把知识、记忆、模型、评测数据和定价的版本证据保留下来，让“这次换配置是否更好”有可核验的依据。

**继续追问：哪个最难？** 选你真正读熟的一条。例如审批最难的部分不是显示确认按钮，而是“批准已经持久化，进程却在恢复前崩溃”“外部动作执行了，结果却没落库”等中间状态。后续可以转到 B07，而不是背全部技术栈。

**证据：** [发布服务](../../../packages/agent_runtime/publish.py)、[审批对账](../../../packages/approvals/reconciliation.py)、[实验可复现约束](../../../packages/evaluation/reproducibility.py)。

## A04｜为什么用模块化单体，不拆微服务？

**可这样回答：** 这个阶段最需要验证的是跨模块语义。例如一个工具提议怎样变成审批、怎样恢复同一 Run、怎样生成评测证据。模块化单体让这些链路可以在同一代码库里测试，减少 RPC、分布式事务和部署协同成本。API、worker、web 可以分别运行，但这不自动成为微服务。

**继续追问：以后怎样拆？** 这是演进设想：先量化哪个模块需要独立扩容，再让已有 adapter/contract 成为边界候选。不能为“看起来高级”直接把审批与动作拆开，制造更多一致性窗口。

**证据：** [ADR-001](../../adr/ADR-001-modular-monolith.md)、[目录架构](../../architecture.md)。

## A05｜数据库、Redis、向量库分别负责什么？

**可这样回答：** PostgreSQL 存用户、成员、Agent 版本、Run、审批、任务状态、快照和评测等业务事实。Redis 主要承担 Celery 所需的队列相关基础设施。Qdrant 提供 dense/sparse 检索索引。文件内容通过 blob store 边界保存。业务对象的真相不能只放在缓存或向量 payload 中。

**继续追问：向量库里有 chunk，为什么还回查数据库？** 索引可能陈旧、可能处于重建中；工作区、revision 和 snapshot 的有效性是业务规则。检索命中后回查业务记录，是避免把旧索引等同于当前可用证据。

**证据：** [存储职责 ADR](../../adr/ADR-002-storage-responsibilities.md)、[检索器](../../../packages/knowledge/retrieval.py)、[知识模型](../../../packages/knowledge/models.py)。

## A06｜为什么需要 AgentVersion，直接修改 Agent 配置不行吗？

**可这样回答：** Agent 草稿用于编辑，发布版本用于执行。发布时解析 prompt、模型档案、工具 revision、知识绑定和 runtime 规则，形成版本化 canonical JSON，并计算 SHA-256 哈希。否则历史 Run 指向一个后来被改掉的模型档案或工具，就解释不了当时执行了什么。

**继续追问：冻结以后还会变化吗？** 模型服务的行为和外部业务系统仍可能变化；凭据引用也不等于把明文密钥写进快照。冻结的是项目定义的运行配置及相关证据，不是冻结整个世界，更不是保证模型重复输出同一段文字。

**证据：** [publish.py 的 `_resolved_spec`](../../../packages/agent_runtime/publish.py)、[冻结规格](../../../packages/agent_runtime/frozen.py)、[ADR-007](../../adr/ADR-007-agentversion-resolved-snapshot.md)。

## A07｜哈希为什么不直接 hash 一个 JSON 字符串？

**可这样回答：** 同一个对象可能序列化为不同键顺序或空白。项目明确使用排序键、紧凑分隔符、UTF-8 和禁止 NaN 的 JSON，再计算 SHA-256，并把 schema 版本放进规格身份。这样哈希反映约定的序列化内容，而不是随手生成的 JSON 文本。读历史对象时还需要校验内容与存储哈希一致。

**继续追问：这是通用 JSON 规范化标准吗？哈希相同就代表效果相同？** 当前是项目自己的序列化契约，没有额外把整数 1 与浮点 1.0 或不同 Unicode 表示统一，也不应宣称实现了通用标准。哈希说明约定内容的身份，不证明模型服务、知识选择时点、外部系统、硬件或随机生成过程全部一致。讨论实验效果时还要检查实验绑定和实际 Run 输入。

**证据：** [canonical JSON 实现](../../../packages/core/canonical/json_hash.py)、[发布单测](../../../tests/unit/test_agent_publish.py)。

## A08｜四个应用真的共用运行时吗？

**可这样回答：** Research、Incident、Analyst、Support 的差异主要放在 Agent 配置、工具、应用产出投影和专属面板中。Thread 的 kind 是界面归属标签，不负责切换另一套运行算法。research 后来还迁移到了共享线程外壳，减少了两份流式会话逻辑的漂移。

**继续追问：是否任何新应用都不用改运行时？** 当前抽象适合这些已有应用。如果新场景要求新的执行语义，例如并行协作或实时控制，就可能需要扩展契约。不能把“当前四个共用”泛化成“任何产品都零改动”。

**证据：** [AppThreadShell](../../../apps/web/components/apps/app-thread-shell.tsx)、[research 入口](../../../apps/web/app/research/[threadId]/research-thread-client.tsx)、[产出投影](../../../packages/artifacts/projections.py)。

## A09｜Thread、Run、Artifact 的区别？

**可这样回答：** Thread 是持续会话，Turn 是其中一次用户输入，Run 是回答这一轮的一次执行。Artifact 是可单独查询、引用和溯源的工作产物。会话下一轮可以采用更新的发布版本，因此可复现与审计的核心单位是 Run，不能假设整条 Thread 永远执行一个版本。

**继续追问：Artifact 都是模型写的吗？** 工具事实型产物由工具结果投影，带执行来源；通用 artifact API 也存在人工创建路径。需要按类型和入口回答，不能说数据库里所有 Artifact 都不可能由用户写入。

**证据：** [ThreadService 的 `resolve_agent_version`](../../../packages/threads/service.py)、[ArtifactService](../../../packages/artifacts/service.py)、[recorder](../../../packages/artifacts/recorder.py)。

## A10｜为什么要做评测平台，直接看几次回答不行吗？

**可这样回答：** 看几次回答适合发现问题，不能可靠地归因。项目支持版本化数据集、实验变体、指标和发布门禁，可以固定比较对象并留住证据。例如只改检索策略时，应避免同时换模型、知识快照和价格基准，否则改善或退化都说不清原因。

**继续追问：这是否有点过度设计？** 对一个简单聊天 demo，确实可以先不做完整评测平台。本项目选择了控制平面与治理的目标，所以投入了这一部分。代价是交付复杂度上升，后续应以真实使用需求控制功能增长。

**证据：** [实验服务](../../../packages/evaluation/experiments.py)、[门禁](../../../packages/evaluation/release_gate.py)、[取舍反思](../06-取舍与短板.md)。

## A11｜为什么 Python 后端和 Next.js 前端？为什么不用 Java？

**可这样回答：** 当前模型、检索和图执行的实现采用 Python 生态，FastAPI 负责类型化 HTTP 边界，Next.js 提供管理和会话界面。选型对应的是这个项目的研发需求和已有 adapter，而不是认为某个语言天生能解决 Agent 可靠性。若面试 Java 岗，仍应解释事务、租户隔离、幂等、异步任务和状态机的可迁移设计。

**继续追问：重写成 Java 会保留什么？** 保留领域状态、唯一约束、快照规范、错误信封和测试场景；替换传输与框架 adapter。LangGraph 的恢复行为不能仅凭接口长得相似就认为等价，需要重新验证失败窗口。

**证据：** [API 入口](../../../apps/api/main.py)、[架构与数据流](../02-架构与数据流.md)。

## A12｜你个人负责什么，怎么证明不是把 AI 生成的代码堆起来？

**回答模板，先填真实事实：** “我负责的是〔实际模块〕。最关键的决策是〔一个不变量〕，实现落在〔函数/约束〕。第一次验证暴露了〔真实问题〕，通过〔修复与回归〕确认。框架、资料和 AI 帮助了〔实际环节〕，但我能解释这条链路和它的限制。”

**继续追问：给我打开代码讲一段。** 从 `compute_logical_action_id`、`claim_ingestion_job` 或 `ContextBudgetPolicy.admit` 中选一个，解释输入、状态变化、异常分支和测试，不要随机选最大文件。若不是自己做的部分，就明确说是后来阅读并参与修复。

**证据：** [复审报告](../../reviews/AgentHub-最新迭代复审-20261002.md)中的代表提交可用 `git show <sha>` 查看；实际贡献需你自己核实，仓库本身不能证明你的开发时长和参与比例。

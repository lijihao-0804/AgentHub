## 怎么用这些回答

先用自己的话讲清主回答；面试官追问时再展开。不要一上来把所有模块念一遍。每个答案都应该能继续接上这四件事：

1. **触发场景**：谁在什么情况下遇到了什么问题。
2. **具体动作**：哪个模块、哪个状态或约束阻止了错误。
3. **选择理由**：如果采用更简单的方案，会失去什么。
4. **证据与边界**：在哪个文件或测试里能确认，仍然不能保证什么。

这里的“可这样回答”是项目讲述模板，不代表作者替你确认了个人履历。团队规模、开发时长、本人负责的模块、AI 参与程度、生产流量与商业收益，只能填写你能核实的事实。个人项目可以直接说“在本项目中实现并验证了……”，不要自动改成“线上服务了很多客户”。

代码入口使用仓库相对链接，方便从 GitHub 或编辑器打开；链接以文件和函数为主，不依赖容易漂移的行号。读完应至少打开一次对应函数，否则只记答案仍然经不起现场翻代码。

## 网上参考了哪些问法

参考的是公开题库的**提问方向**，不是已核实的公司真实题频统计，也没有照搬网上示范答案：

- [zero2Agent：简历项目拷打](https://onefly.top/zero2Agent/learn-agent-interview/13-project-deep-dive/)：启发连续追问结构，包括选型理由、个人贡献、失败复盘与工程边界。
- [ai-agents-from-zero：AI 智能体与大模型应用开发面试题库](https://github.com/didilili/ai-agents-from-zero/blob/main/AI%E6%99%BA%E8%83%BD%E4%BD%93%E4%B8%8E%E5%A4%A7%E6%A8%A1%E5%9E%8B%E5%BA%94%E7%94%A8%E5%BC%80%E5%8F%91%E9%9D%A2%E8%AF%95%E9%A2%98%E5%BA%93.md)：启发项目介绍、RAG、工具与业务闭环等主题。

技术背景只参照官方资料；**本项目到底怎样做，以基线代码为准**。官方在线文档可能已经介绍比本项目更新的 API，不应把官方示例当成本项目实现：

- [LangGraph Persistence](https://docs.langchain.com/oss/python/langgraph/persistence)：区分图状态持久化与跨会话存储。
- [LangGraph Interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts)：中断、恢复及节点重入规则。
- [Celery Tasks](https://docs.celeryq.dev/en/stable/userguide/tasks.html)：重复执行与确认策略的关系。
- [Qdrant Hybrid Queries](https://qdrant.tech/documentation/search/hybrid-queries/)：混合检索与排名融合的背景。

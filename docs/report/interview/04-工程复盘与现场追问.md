# 04｜工程复盘与现场追问

> **2026-10-05 更新口径**：以 [当前状态](../../current-state.md) 和 [收口报告](../../reviews/AgentHub-closure-memory-quality-20261005.md)解释已完成、未知与延期。原始调研/案例保留；功能开发已停止，建议不构成开工计划。

基线与阅读方式见 [总入口](README.md)。本章用真实代码和复审案例回答工程问题。文中的修复故事描述仓库发生过的工作；面试时是否能用第一人称，取决于你实际承担的工作。

## D01｜多租户隔离是不是给 SQL 加一个 workspace_id 就够了？

**可这样回答：** 不够。组织成员和工作区成员是两种关系，组织身份不能直接替代工作区授权。请求先得到服务端解析的工作区执行上下文，应用服务再检查对应权限和资源归属。列表筛选、详情查询、修改操作都要守住边界；用户能看运行元数据，也不代表能看输入和输出。前端禁用按钮是体验，后端检查才是安全边界。

**继续追问：** “模型能传 workspace_id 绕过吗？”工具参数中的身份类保留字段会被拒绝，执行身份来自可信上下文。“切换工作区后旧请求返回呢？”这是前端状态隔离问题，还要用 session/scope/generation 守卫，不能只依赖后端鉴权。

**证据：** [RBAC](../../../packages/control_plane/rbac.py)、[审批参数契约](../../../packages/approvals/contracts.py)、[会话路由与字段裁剪](../../../apps/api/routes/threads.py)、[工作区数据 hooks](../../../apps/web/hooks/use-workspace-data.ts)。

## D02｜MCP 已经是标准协议，为什么还要做工具治理？

**可这样回答：** MCP 解决连接和发现，不替工作区决定谁能执行、是否有副作用、是否需要审批。项目从远端发现真实工具契约，再由工作区配置治理参数并导入。远端提供的名称、描述或 schema 都不应自动变成授权结论。READ 与风险也是两个维度，读取敏感信息同样可能有风险。

**继续追问：** “远端工具声明自己安全呢？”那是输入信息，不能覆盖本地治理。“工具描述能否改变运行身份？”不能；身份来自可信执行上下文。不同工具仍需分别评估实际副作用和远端幂等能力，不能把 MCP 接入当作全局安全证明。

**证据：** [MCP 服务](../../../packages/mcp/service.py)、[运行适配](../../../packages/mcp/runtime.py)、[工具策略](../../../packages/tools/policy.py)、[导入页面](../../../apps/web/app/tools/mcp/page.tsx)。

## D03｜允许用户填写远端地址，怎么防 SSRF 和密钥泄露？

**可这样回答：** 创建连接时校验地址形态，传输时还要检查实际目标和解析结果；重定向也不能跳过校验。否则一个看起来正常的域名可能导向内网。MCP bearer token 用版本化密文保存，异常只返回稳定失败代码，避免把地址和 token 带进日志。生产环境缺少密钥配置应失败，不能使用开发默认值。

**继续追问：** “首次校验后永远安全？”不是，DNS 与跳转都是动态边界，要读传输守卫而不是只看表单校验。“能说所有提示词注入都解决了吗？”不能。身份隔离、参数校验和审批降低影响，但不证明模型不会受恶意内容影响；还需恶意文档、工具返回和越权动作的专项评测。

**证据：** [目标校验与密文实现](../../../packages/mcp/security.py)、[客户端传输](../../../packages/mcp/client.py)、[MCP 安全测试](../../../tests/unit/test_enhancement3a_mcp_security.py)、[安全输出](../../../packages/observability/safe.py)。

## D04｜讲一个“类型检查和构建都过了，但仍然有 bug”的例子

**可这样回答：** Agent A 的聊天页面曾按应用 kind 查询整个工作区，可能展示 Agent B 的会话，还允许创建时选 B。界面标题与真正执行的 Agent 不一致。类型检查只能确认参数类型，无法发现业务范围漏传。修复把 agentId 贯穿列表、创建和详情：列表按 Agent 筛选，创建锁定 Agent，详情确认归属后才挂载可提交消息的组件。

**继续追问：** “只在列表加筛选够吗？”不够，用户仍可以直接访问详情 URL，也可能从别处创建。“怎么避免同类问题？”围绕业务身份列出入口、创建、详情三条路径，再为错误归属建立回归场景，而不是只测试正常页面。

**证据：** [复审 R01](../../reviews/AgentHub-最新迭代复审-20261002.md)、[共享列表](../../../apps/web/components/apps/app-threads-page.tsx)、[共享外壳](../../../apps/web/components/apps/app-thread-shell.tsx)、[专项回归](../../../scripts/test_web_review.cjs)。

## D05｜分页为什么到了第三页才坏？切换工作区又为什么会串数据？

**可这样回答：** 实验列表的 offset 曾一直使用首页长度，第二次加载更多仍请求 offset=50。去重隐藏了重复，因此用户看到的是按钮没有进展。修复按首页与追加页的总长度计算 offset，并按 total 判断结束。另一个独立问题是旧工作区的分页响应晚到，写回新工作区页面；需要在请求和回写之间核对会话及请求代次。

**继续追问：** “去重为什么不能解决？”它不能推进错误游标。“怎么测？”用 121 条数据走三页、检查第三次 offset 和末页；人为控制请求完成顺序，验证切换工作区或刷新后的旧响应被丢弃，同时检查 render 没有修改原 state 数组。

**证据：** [复审 R02–R04](../../reviews/AgentHub-最新迭代复审-20261002.md)、[实验列表](../../../apps/web/app/evaluations/experiments/page.tsx)、[数据集列表](../../../apps/web/app/evaluations/datasets/page.tsx)、[专项回归](../../../scripts/test_web_review.cjs)。

## D06｜Markdown 为什么不能“先转义再给 React”？

**可这样回答：** React 文本节点已有转义机制，再手工转义会把实体作为文本展示，也可能改坏链接查询参数。项目曾出现这个问题，还在有序/无序列表切换时覆盖上一列表。修复让文本走 React 节点，链接保持 http(s) 协议限制，列表类型变化前先输出上一列表。

**继续追问：** “这等于完整 Markdown 标准和完整安全审计吗？”不是。当前是受限渲染器，不能宣称支持任意 HTML 或完整语法。回归脚本用真实 React 服务端渲染核对文本、查询参数、危险协议和混合列表；滚动、焦点与浏览器交互还需要另外覆盖。

**证据：** [Markdown 实现](../../../apps/web/components/ui/markdown.tsx)、[复审 R06](../../reviews/AgentHub-最新迭代复审-20261002.md)、[专项回归](../../../scripts/test_web_review.cjs)。

## D07｜用户说首字很慢，你会先优化哪里？

**可这样回答：** 先拆请求链路，区分鉴权/取配置、检索、rerank、模型建连和首 token，再看冷启动与热请求的差别。项目已有检索与问答基准文档，可用于提出假设，但历史样本不能直接当作当前生产 SLA。减少候选集、复用模型资源或预热，都要分别检查首字时间、总耗时、内存和回答质量，不能只看一个总平均数。

**继续追问：** “已经提高多少百分比？”只有相同数据、相同模型、相同硬件及冷热条件的对照才能回答；没有证据就说明待测。“流式是不是让计算更快？”流式改善可见响应时间，不必然减少模型总计算时间。

**证据：** [报告目录中的性能与评测材料](../README.md)、[检索流水线](../../../packages/knowledge/retrieval.py)、[模型网关](../../../packages/model_gateway/gateway.py)、[观测指标](../../../packages/observability/metrics.py)。

## D08｜你怎么证明审批恢复真的可靠，而不是 mock 全绿？

**可这样回答：** 单元测试覆盖状态转移、逻辑动作身份和失败分支；集成测试用真实 PostgreSQL/checkpoint 存储检查恢复路径，重点注入审批持久化与 checkpoint 之间的崩溃窗口。前端还要单独验证异步状态与作用域，构建成功不能替代行为测试。每个结论都要说出覆盖的是哪条路径。

**继续追问：** “所有依赖都真实启动了吗？”2026-10-02 的集成记录是 185 通过、4 跳过；4 项真实 Celery worker 环境用例未执行，不能算通过。前端 7 组专项回归不是完整浏览器 E2E。那轮用了独立测试库并显式部署 checkpoint schema，不在 API 启动时自动建表。

**证据：** [checkpoint 集成测试](../../../tests/integration/test_m5a_checkpoint_runtime.py)、[审批集成测试](../../../tests/integration/test_m5a_approval_runtime.py)、[验证记录](../../reviews/AgentHub-最新迭代复审-20261002.md)。

## D09｜Dashboard 的成功率、成本这些数字怎么防止误导？

**可这样回答：** 指标必须有明确窗口、分子和分母。没有样本时比例应是未知，而不是 0%；成本缺失也不代表免费。多币种应分别呈现，不能把 USD 与 CNY 直接相加。指标适合汇总运行状态，事件帮助追踪过程，业务内容 trace 则按 opt-in 和脱敏规则处理，不能为了排障默认记录所有提示词与文档。

**继续追问：** “运行成本上限就是精确账单吗？”不是。供应商 usage、定价快照、币种和未知数据都会影响估计；预算策略也不等于预付费硬扣款。“消息流能当可靠审计日志吗？”不能；当前 delta 不持久化，事件写入也有有界队列和降级边界，见 B12。

**证据：** [指标聚合](../../../packages/observability/metrics.py)、[安全记录](../../../packages/observability/safe.py)、[事件存储](../../../packages/agent_runtime/event_store.py)、[运行限制](../../../packages/agent_runtime/runtime.py)。

## D10｜如果真的上线、访问量涨十倍，你准备怎么做？

**可这样回答：** 当前是模块化单体，API、前端和异步 worker 可分别部署；数据库、队列、向量库和文件存储承担不同职责。先根据瓶颈测并发与资源占用，再考虑 API/worker 副本、外部调用并发限额、数据库索引和检索容量。扩副本前必须验证审批 claim、任务 lease 和幂等约束在竞争下仍然成立。schema 迁移与 checkpoint 初始化属于显式部署步骤。

**继续追问：** “已经支持多少 QPS？”目前不能用测试数量推导吞吐，也不能把上面的容量方案说成已验证的生产能力。“为什么不马上微服务？”先有故障域、团队边界或独立扩容需求，再评估拆分收益；否则会额外引入跨服务一致性问题。

**证据：** [项目部署说明](../../../README.md)、[入库 lease](../../../packages/knowledge/ingestion.py)、[审批服务](../../../packages/approvals/service.py)、[项目语义与部署要求](../../../plan/plan.md)。

## D11｜大量使用 AI 写代码，你的能力体现在哪里？

**可这样回答：** 按真实分工回答：我怎样提出业务约束，怎样判断模型建议是否符合契约，怎样定位并验证失败，以及怎样控制改动范围。可以用一个可复现案例说明“现象→根因→修复→验证→仍有边界”。例如 D04 的错误 Agent 归属，或 B08 的未知外部副作用。不要把仓库存在的全部代码自动算作个人贡献。

**继续追问：** “现场改一个相关问题行不行？”应能打开相应入口，解释状态与参数，再提出最小修改和回归场景。“AI 参与比例多少？”只提供能核实的事实，没有统计不要编百分比。验证工具的结果也需要人理解：静态检查通过不等于需求完成，跳过测试不等于通过。

**证据：** [项目规则](../../../AGENTS.md)、[真实复审](../../reviews/AgentHub-最新迭代复审-20261002.md)、[专项回归脚本](../../../scripts/test_web_review.cjs)。

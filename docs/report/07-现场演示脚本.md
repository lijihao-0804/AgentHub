# 07 · 现场演示脚本

如果面试允许带电脑或共享屏幕，**演示比讲述强十倍**。
但演示有一条铁律：**演示的是治理，不是聊天。**
任何人都能演示一个会说话的框，没人能演示一个会停下来等人批准的框。

> **备份方案**：[18-截图演示.md](18-截图演示.md) 是同一套流程的 37 张实拍截图。
> 服务起不来、网络不通、或者对方不方便看屏幕时，直接翻那一章，
> 顺序是一样的，数字是真的。

## 0. 启动清单（面试前 20 分钟做完）

| 进程 | 本机方式 | 容器方式（`docker compose -p agenthub`） | 端口 |
|---|---|---|---|
| PostgreSQL | 本机服务 | `db` 服务 | 5432 |
| Redis | 本机服务 | `redis` 服务 | 6379 |
| Qdrant | 本机服务 | `qdrant` 服务 | 6333 |
| API | `python -m apps.api` | `api` 服务（宿主端口可能要改，见下） | 8000 |
| Celery worker | `celery -A apps.worker worker` | `worker` 服务 | — |
| Web | `npm run dev`（apps/web） | 仍在本机起 | 3000 |
| 文献 MCP | `python -m apps.literature_mcp` | 本机 | 8931 |
| 运维 MCP | `python -m apps.ops_mcp` | 本机 | 8941 |
| 数仓 MCP | `python -m apps.warehouse_mcp` | 本机 | 8942 |
| 商务 MCP | `python -m apps.commerce_mcp` | 本机 | 8943 |

**两种方式各有一个只在它身上出现的坑，现场前都要知道**：

- **本机方式**：Windows 上 uvicorn 在 `sys.platform == "win32"` 时**硬返回**
  `ProactorEventLoop`，而 LangGraph 的 Postgres checkpointer 用的 psycopg
  明确拒绝在 Proactor 上跑——每一次 agent 运行都会抛
  `Psycopg cannot use the 'ProactorEventLoop' to run in async mode`。
  处置是自己建 `SelectorEventLoop` 再把 `server.serve()` 交给它。
  **这是 Windows 本地开发独有的，容器是 Linux，不会遇到**（已实测）。
- **容器方式**：仓库自带的 `.env` **起不了容器**——里面还是
  `DEFAULT_AUTH_JWT_SECRET` 占位符，而 `environment=docker` 不在
  `DEVELOPMENT_ENVIRONMENTS` 里，`Settings` 会直接拒绝启动。
  从命令行注入一个真密钥（shell 环境变量优先于 `.env` 插值），不要去改共享的 `.env`。
  另外 worker 容器必须有 `AGENTHUB_CREDENTIAL_MASTER_KEY`，
  否则 worker 里**每一次模型调用**都以 "Credential encryption is not configured" 失败。
  宿主 8000 若被占，把 api 映射到别的端口（实测用过 8020）。

**先决条件：`HF_HUB_CACHE` 必须指向权重所在目录。**

知识检索要加载 `BAAI/bge-m3` 和 `BAAI/bge-reranker-v2-m3`，两个加起来约 6.5 GB。
这个变量**不走 Settings**——`huggingface_hub` 在 import 时就把它读成模块常量了，
所以它必须在进程环境里，写进 `.env` 没用。本机上：

```
HF_HUB_CACHE=E:\JAVA\AI+agent\hf_cache
```

已设为用户级环境变量。没设的话，程序会去 `~/.cache/huggingface` 找，
找不到就**重新下载一遍 6.5 GB**——我就踩过这个坑，白下了一份。

验证权重可用（离线加载，不通网就证明本地是全的）：

```bash
HF_HUB_OFFLINE=1 python -c "from sentence_transformers import SentenceTransformer; print(SentenceTransformer('BAAI/bge-m3').get_embedding_dimension())"
```

**检查项**：
- [ ] `HF_HUB_CACHE` 已设，且上面那条离线加载命令能打印 `1024`
- [ ] **`knowledge_warm_models_on_start=true`，或者已经手动跑过一次检索把模型预热掉**
      —— 否则现场的第一次检索**必然超时**：冷进程要在工具自己的 30 秒预算里
      加载两个模型（实测约 35 秒），对外表现成「知识库里没有这条」，
      而不是「系统还没准备好」。这是最容易毁掉一场演示的一条，
      因为它看起来像是你的知识库有问题
- [ ] `.env` 里的模型 key 有效且有额度（现场失败比没演示更糟）
- [ ] 四个应用页面各有至少一个**已有内容**的 Thread（网络慢时有东西可看）
- [ ] 浏览器缩放调到 110%，字够大
- [ ] **关掉所有无关标签页**
- [ ] 准备离线兜底：截图或录屏，网挂了照样能讲

## 1. 主线演示：故障排查（8 分钟）

**这是唯一必演的一条。** 因为它一条链路同时展示治理的全部要素。

### 步骤

| # | 操作 | 同时说的话 |
|---|---|---|
| 0 | 先停在首页 `/`，**只花 20 秒** | 「四个应用在上面，下面是它们共用的那一套运行时——Runs、审批、Agent 版本、知识、评估。这个首页的层级本身就是我想讲的架构：**四个应用，一套运行时**。」 |
| 1 | 打开 `/incidents`，指三栏布局 | 「左边是会话，中间是对话，右边是产出物。四个应用都是这个骨架，只有第三栏不同。」 |
| 2 | 新建 Thread，输入：**「支付成功率从 14:00 开始下降，帮我查一下原因」** | 「注意我没有告诉它去查什么，工具选择是模型做的，但工具能不能执行不是它说了算。」 |
| 3 | 观察 SSE 流：`tool.requested` → `tool.started` → `tool.completed` 连续四次 | 「query_metrics、query_logs、get_deployments、get_commit —— 四个都是 READ，`ToolPolicy.decide` 判为 ALLOW_AUTO，直接执行。」 |
| 4 | **指右栏**：incident.timeline 卡片出现 | 「这些不是模型写的，是从工具返回值**投影**出来的，每一条带 run_id 和 tool_call_id。模型没有写事实的权限。」 |
| 5 | 模型提议 `rollback_deployment`，**界面出现审批卡片，流停住** | ⭐「**这里是整个项目的核心。** 这个工具是 WRITE / HIGH / ALWAYS。同一个判定函数，这次返回 REQUIRE_APPROVAL。」 |
| 6 | **切到数据库或 Run 详情页，指 Run 状态 = `WAITING_APPROVAL`** | 「LangGraph 的 checkpoint 已经落库了。」 |
| 7 | 🔥 **（可选高能）把 API 进程杀掉再启动** | 「我现在重启整个后端。……好了。状态还在，因为它不在内存里。」 |
| 8 | 点「批准」 | 「批准是一次数据库抢占，两个人同时点只有一个能成功。」 |
| 9 | 观察执行继续，**指 Run ID 没变** | ⭐「**同一个 run_id。** 不是新开一次执行。因为审计上一次 Run 必须是一个完整故事，而且 max_tool_calls 这类预算不能被重置绕过。」 |
| 10 | 点 `View Run` 进 Run 详情页 | 「每一步、每次工具调用、上下文按类别的预算用量，全部可查。」 |

**如果只有 3 分钟**：只做 2 → 5 → 8 → 9，其余口述。

## 3b. 备选演示 C：前端质量（2 分钟，只在对方是前端方向时用）

| # | 操作 | 说的话 |
|---|---|---|
| 1 | 打开 `/approvals`，展开一张卡片的「技术参数」 | 「这里原来会爆——文档宽度从 1014px 撑到 2099px，整站出现横向滚动条。根因是 `min-width: auto`：隐式 grid 轨道按 max-content 定宽，**不受容器约束**。」 |
| 2 | 把窗口拖到手机宽度 | 「顶栏原来也会垮。工作区选择器拒绝收缩，压力全转嫁给两个固定尺寸的开关，它们被压到 2px。修法不是加 `overflow: hidden`，是**明确指定谁让步**。」 |
| 3 | 指工作区名的截断 | 🔥「这条不是排版问题是语义问题：原来截断留的是组织名，丢的是工作区名。但**『我在哪个工作区』是审批界面里唯一不能被压掉的上下文**。所以我把它拆成两个 span，让组织名先走。」 |
| 4 | 切浅色主题，指状态徽章 | 「这族颜色比『在白底上好看』深一档，因为它们从不在白底上——徽章自己画一层半透明底，底又叠在已着色的块上。实测最差 4.11，加深后 4.96。」 |
| 5 | 用 Tab 键走到语言开关 | 「焦点环原来是**看不见**的——药丸 `overflow: hidden`，内部余量 0.8px，而全局焦点环是 4px 光晕，整个被裁掉。改成 `outline-offset: -2px` 画到内部。」 |

**结尾必说**：「这 8 个问题里有 5 个只有展开真实数据才会出现，静态审查一个都抓不到。
但我也要说清楚——我做的是审计不是回归保护，下次改 CSS 没有东西会自动告诉我它又爆了。」

## 3c. 备选演示 D：记忆可见，而且人可以推翻它（4 分钟）

**什么时候用**：对方问「你的 agent 有没有记忆」，或者问「怎么防止它学坏」。
这条演示的价值不在「它记住了」——那谁都能演——而在**它记住的东西被冻住了，
人能推翻它，但推翻不等于抹掉**。

前置：挑一个 agent，在运行时配置里把 `long_term_memory` 打开并发布一版
（默认是关的，这一点本身就要说出来）。

| # | 操作 | 说的话 |
|---|---|---|
| 1 | 指出这个开关默认关 | 「两个记忆开关默认都是 false，而且全 false 时 `memory` 从 `resolved_spec` 里整体省略——所以**既有 agent 的冻结哈希和这个功能存在之前一模一样**。新功能不许让历史版本的哈希漂移。」 |
| 2 | 跑一轮对话，说一件值得记的事（比如「我们团队周五不发版」） | 「抽取不在这条请求的链路上，它在运行完成之后入队，由 worker 做。而且 worker 会**重新校验**这个开关——伪造一条队列消息也不能让没开开关的 agent 偷偷学东西。」 |
| 3 | 进 agent 详情页 → **memories 标签页**，看到那条记忆 | 「内容、类型、状态、来源运行都在。`source_run_id` 指回教它的那次运行——『它为什么会这么认为』是可查的。」 |
| 4 | **另开一个全新会话**问一个相关问题 | 「注意这是新会话，窗口里没有上一轮的任何东西。它仍然知道。」 |
| 5 | 打开这次 Run 的 `effective_memory_snapshot` | ⭐「这次用了哪几条记忆，id 在这里冻住了。之后任何一次重放——审批恢复、评测 A/B——都按这几个 id 装载，**包括后来被取代或被人关掉的**。重放要回答的是『它当时拿到了什么』，不是『它现在会拿到什么』。」 |
| 6 | 回 memories 页，点「停止使用」（invalidate） | 「注意没有删除按钮，只有停用。」 |
| 7 | 再跑一轮，指新 Run 的 `effective_memory_snapshot` 里它消失了 | ⭐「新的运行不再用它，但**刚才那次运行的快照里它还在**。」 |

**台词落点（这句是这条演示的全部）**：

> **「记忆是证据不是指令——它被强制盖成 UNTRUSTED，走的是可驱逐的类别，
> 不是必留的系统提示。而且人可以推翻它，但不能抹掉它：
> 删掉一条记忆，就等于删掉了『那次运行为什么会那么说』的答案。」**

🔥 可能的追问「那对一条已经在用的记忆调 reactivate 会怎样」→
409 `MEMORY_NOT_INVALIDATED`。不是 500，也不是静默成功——
「这个操作对当前状态没有意义」本身是一个要回答的信息。

## 4. 代码走读（5 分钟，比跑起来更重要的一环）

**很多候选人只会演示界面。翻代码并且知道翻哪一行，是区分度最高的动作。**

准备好这八个文件，编辑器开好标签页：

| 顺序 | 文件 | 展示什么 | 一句话 |
|---|---|---|---|
| 1 | `packages/tools/policy.py` | 全文 26 行 | 「整个治理的判定就这一个函数。默认拒绝。」 |
| 2 | `packages/mcp/security.py:197` | `authorize_endpoint` | 「必须解析 DNS，多条记录有任意一条私网就整体拒——防 rebinding。」 |
| 3 | `packages/mcp/runtime.py:105` | `execute_write` 的注释 | 「这里我明确写了不声称 exactly-once。因为这边做不到。」 |
| 4 | `apps/warehouse_mcp/sql_guard.py:1` | 模块 docstring | 「解析器是解释，只读连接是保证，两者不冗余。」 |
| 5 | `packages/agent_templates/base.py` | `GROUNDING_RULES` docstring | 「同一个缺陷穿了四件衣服。」 |
| 6 | `packages/memory/service.py` | invalidate 的注释 `"Stop using this memory. Not a delete -- see ADR-011."` | 「只停用，不删除。删掉一条记忆就等于删掉了『那次运行为什么会那么说』的答案。」 |
| 7 | `packages/agent_runtime/context_budget.py` | `MEMORY` 类别那段注释 | 「记忆是证据层、可驱逐，而且**按位置而不是按 role 归类**——它顶着 system 的 role，但绝不能被当成系统提示保留。」 |
| 8 | `apps/web/app/styles/tokens.css:79` | 浅色状态色那段注释 | 「如果对方问前端：这里我写的是**为什么这族颜色比『在白底上好看』要深一档**——因为它们从不显示在白底上。」 |

**翻代码时的技巧**：不要念代码，念**注释**。
这些注释写的是「为什么」，而代码只写了「是什么」。

## 5. 如果演示挂了

**冷静，且把它变成加分项。**

- 模型超时 → 「正好，这就是为什么运行时要有超时和重试策略，而 WRITE 类调用超时之后我们不重试，是标记 UNKNOWN_OUTCOME 交给人。」
- MCP 连不上 → 「这个报错码是 `MCP_CONNECTION_NOT_FOUND`，属于 NOT_DISPATCHED——请求根本没发出去，所以可以安全地直接判失败，远端没有副作用。」
- 网络全挂 → 切截图/录屏，转 4（代码走读）。

**不要说「平时是好的」。** 说「这个失败路径我设计过，它现在的表现是符合预期的」。

## 6. 演示的三条铁律

1. **演治理，不演聊天。** 审批停住那一刻是整场演示的高潮，
   前面所有步骤都是为了铺垫它。
2. **每一步都说「不做会怎样」。** 观众看到的是界面，
   你要讲的是界面背后被挡住的那个坏结果。
3. **留代码走读的时间。** 界面证明你做出来了，
   代码注释证明你**想过**。后者才是面试要考的。

# 07 · Hero Demo：Incident 的受控回滚

2026-10-09；源码基线 `a12e8ab`。本轮 **DOCUMENTED_ONLY**：核查流程、fixture 和代码，未启动服务或调用真实模型。历史截图/测试是历史证据，不能当作本轮成功记录。主演示控制在 5–8 分钟，后面的备选章节保留供追问使用。

## 0. 实际启动条件与安全范围

1. 使用独立本机 `lab-portfolio` 工作区和可丢弃的 lab 数据库/Redis namespace/blob 目录，API、worker 与 checkpoint bootstrap 指向同一 lab 库。不要改共享 `.env`；在独立终端用进程变量覆盖地址。完整默认启动见 [根 README](../../README.md#本地启动)，其中默认库名 `agenthub` 不是隔离库，演示前必须替换。
2. lab 库先创建，再运行 `uv run --locked alembic upgrade head` 和 `uv run --locked python -m scripts.bootstrap_langgraph_checkpoint`。依赖 PostgreSQL/Redis，API、worker、Web；若应用 Agent 绑定知识，还需 Qdrant、完成入库与模型预热。beat 用于入库对账。仅工具链演示不需要额外上传知识。
3. 有效 JWT/加密主密钥，API 与 worker 相同主密钥；通过登录/注册选择 lab 工作区，配置有效供应商凭据和支持工具调用的模型档案。不要在屏幕或日志中显示 token/key。
4. Windows 原生 API 需兼容 psycopg 的 Selector loop；推荐 Linux 容器 API。容器访问宿主 Ops MCP 用 `http://host.docker.internal:8941/mcp`，API 在宿主时用 `http://127.0.0.1:8941/mcp`。`host.docker.internal` 依赖 Docker Desktop，其他平台要先核实实际可达地址。
5. 只在隔离 API 进程显式设置 `AGENTHUB_MCP_ALLOW_PRIVATE_TARGETS=true` 后重启，允许本机 fixture。该开关是现有测试配置，不是生产默认；本轮不改安全实现。Compose 未透传该开关时不能仅在宿主设变量就以为容器生效；用隔离的本机 API 或本地临时 Compose override 显式注入并核对实际进程环境，不提交该 override。不要放开生产网络。
6. 独立终端在仓库根目录启动现有安全模拟：

```powershell
$env:OPS_MCP_HOST = '127.0.0.1'
$env:OPS_MCP_PORT = '8941'
$env:OPS_MCP_ROLLBACK_MODE = 'succeed'
uv run --locked python -m apps.ops_mcp
```

容器访问宿主时按本机网络条件绑定可达接口（如 `0.0.0.0`），只对演示环境开放端口；默认 loopback 不能保证容器访问。服务路径 `/mcp`。fixture 源码：[incident_data](../../apps/ops_mcp/incident_data.py)、[_rollback](../../apps/ops_mcp/server.py)。底层是字面量和 `plan_rollback` 返回记录，无真实生产回滚调用；响应的 `production` 标签是虚构场景，成功记录也不修改真实部署。

### 从空工作区配置

- `/tools/mcp`：创建连接 → 测试/发现 → 导入 `query_metrics`、`query_logs`、`get_deployments`、`get_commit`、`rollback_deployment`。前四个设置 `READ / LOW / NEVER`；回滚设置 `WRITE / HIGH / ALWAYS`，发布工具修订。远端 annotation 不能替代工作区治理配置。
- Agent 模板入口选择 Incident，或使用 [incident prompt](../../packages/agent_templates/incident.py)创建 lab Agent，绑定上述已发布工具和模型档案；预算至少允许调查与回滚。发布 AgentVersion，并在 `/incidents` 创建 Thread/选择这个 Agent。确认运行版本，不使用旧截图中的 UUID。
- `/approvals` 使用有审批权限的账号；提交者与审批者可用两个 lab 用户验证权限。演示不需要修改 RBAC。
- UI 未建立好时先做代码/截图展示，不绕过发布和策略创建假 Run。当前无一条命令完成全部租户、模型和工具配置的自动 seed。

`apps/ops_mcp/incident_data.py` 的服务是 `checkout-api`，仓库 `acme/checkout-api`，数据窗为 **2026-03-14T20:50:00Z～21:20:00Z**，部署在 21:01Z，版本 5.4.2/5.4.1。使用下面的输入，不用“今天”或“14:00”猜时间：

> 调查 checkout-api 在 2026-03-14T20:50:00Z 到 2026-03-14T21:20:00Z 的错误与时延上升。查询指标、日志、部署及 acme/checkout-api 的相关提交，给出证据。若确认发布导致异常，请提议回滚到之前部署的版本，并说明理由；操作必须等待人工批准。

模型可能先解释再提议，不保证四工具各调用一次或固定顺序；没有提议时如实记录，再通过已有多轮会话要求“基于已查询证据提议回滚到 5.4.1”。每个新 Turn 是新 Run，应记录真正发生审批的那个 Run。不可伪称首轮必定完整通过。

检查当前记录可使用只读查询（UUID 替换为本次真实值；连接 lab 库）：

```sql
SELECT id, agent_version_id, status FROM agent_runs WHERE id = '<run UUID>';
SELECT * FROM approvals WHERE run_id = '<run UUID>';
SELECT * FROM run_steps WHERE agent_run_id = '<run UUID>' ORDER BY sequence_number;
```

checkpoint 由框架 schema 持久化，不在界面展示原始 payload/敏感输入；检查 setup 和 adapter，不复制 checkpoint 内容到公开材料。事件名以 [AgentEventType](../../packages/agent_runtime/events.py)为准，只有选定生命周期事件持久化，不能说 token delta 全部落库。异步事件 recorder 在有界队列满时会丢帧告警，不能声称事件完全无损。trace 内容默认关闭/脱敏，未连接外部观测平台也能查看 Run 投影。

### 可选恢复/失败展示（主 Demo 不强制）

- 先在真正 WAITING_APPROVAL 后重启同一个 lab API，再批准，记录 Run ID/审批状态/时间。未执行该步骤不能声称本次验证重启恢复；已有 [持久化故障测试](../../tests/integration/test_m5a_checkpoint_runtime.py)可静态核查。
- `OPS_MCP_ROLLBACK_MODE=hang` 会模拟已接收但不回答；只在另一次隔离演练中开启。已派发写入超时应检查 UNKNOWN_OUTCOME 和 NEEDS_ATTENTION，不点击重复回滚。恢复 `succeed` 只影响下一次调用，不能确认原动作结果。
- 关闭 lab 服务，移除仅本终端设置的 `OPS_MCP_*` / MCP 私网开关；停止临时 override，恢复原 lab 配置。保存记录用于比较，不删除共享数据，不篡改发布版本。

### 常见失败排查

| 现象 | 核查 | 不能这样解释 |
| --- | --- | --- |
| MCP 私网拒绝 | 当前 API 的私网开关、URL、DNS/协议守卫 | 不能为了演示改 SSRF 默认 |
| 连接不上 | loopback 与容器可达性、端口、防火墙、`/mcp`、Ops 进程 | 不把所有连接错误都说成 MCP_CONNECTION_NOT_FOUND；是否派发要查实际失败码 |
| READ 也等待审批 | 当前发布修订的 READ/NEVER，与选择版本 | READ 不保证安全自动执行 |
| 无调查结果 | 固定时间窗、服务名、参数、模型/工具能力 | 不编造日志/指标或把空结果当成功 |
| 回滚后没继续 | 审批 actor、checkpoint setup、同一 lab DB、主密钥、模型费用/上下文预算 | 批准不保证动作/模型后续成功 |
| 外部写入超时 | 派发阶段、execution_status、Run 状态 | UNKNOWN_OUTCOME 不等于“没发生，可重试” |

## 3c. 备选演示 D：记忆可见，而且人可以推翻它（4 分钟）

**什么时候用**：对方问「你的 agent 有没有记忆」，或者问「怎么防止它学坏」。
这条演示的价值不在「它记住了」——那谁都能演——而在**它记住的东西被冻住了，
人能推翻它，但推翻不等于抹掉**。

前置：挑一个 agent，在运行时配置里把 `long_term_memory` 打开并发布一版
（默认是关的，这一点本身就要说出来）。

| # | 操作 | 说的话 |
|---|---|---|
| 1 | 指出这个开关默认关 | 「两个记忆开关默认都是 false，而且全 false 时 `memory` 从 `resolved_spec` 里整体省略——所以**既有 agent 的冻结哈希和这个功能存在之前一模一样**。新功能不许让历史版本的哈希漂移。」 |
| 2 | 跑一轮对话，说一件值得记的事（比如「我们团队周五不发版」） | 「抽取不在这条请求的链路上，它在运行完成之后入队，由 worker 做。而且 worker 会**重新校验**这个开关——伪造一条队列消息也不能让没开开关的 agent 偷偷学东西。」 |
| 3 | 进 agent 详情页 → **memories 标签页**，看到那条记忆 | 「内容、类型、状态、来源运行都在。`source_run_id` 指回教它的那次运行——『它为什么会这么认为』是可查的。」 |
| 4 | **另开一个全新会话**问一个相关问题 | 「注意这是新会话，窗口里没有上一轮的任何东西。它仍然知道。」 |
| 5 | 打开这次 Run 的 `effective_memory_snapshot` | ⭐「这次用了哪几条记忆，id 和内容哈希都冻在这里。之后任何一次重放——审批恢复、评测 A/B——都按快照装载并校验，**包括后来被取代或被人关掉的**。重放要回答的是『它当时拿到了什么』，不是『它现在会拿到什么』。」 |
| 6 | 回 memories 页，点「停止使用」（invalidate） | 「注意没有删除按钮，只有停用。」 |
| 7 | 再跑一轮，指新 Run 的 `effective_memory_snapshot` 里它消失了 | ⭐「新的运行不再用它，但**刚才那次运行的快照里它还在**。」 |

**台词落点（这句是这条演示的全部）**：

> **「记忆是证据不是指令——它被强制盖成 UNTRUSTED，走的是可驱逐的类别，
> 不是必留的系统提示。而且人可以推翻它，但不能抹掉它：
> 删掉一条记忆，就等于删掉了『那次运行为什么会那么说』的答案。」**

🔥 可能的追问「那对一条已经在用的记忆调 reactivate 会怎样」→
409 `MEMORY_NOT_INVALIDATED`。不是 500，也不是静默成功——
「这个操作对当前状态没有意义」本身是一个要回答的信息。

## 5. 如果演示挂了

**冷静，且把它变成加分项。**

- 模型超时 → 核对模型错误与可见 token 前重试/fallback；不要把模型超时当成写入结果不确定。只有已派发且无法确认的外部写入才进入 UNKNOWN_OUTCOME。
- MCP 连不上 → 查真实失败码和派发阶段。缺连接配置与请求发出后的超时不同，不能统一归为 NOT_DISPATCHED。
- 网络全挂 → 切截图/录屏，转 4（代码走读）。

**不要说「平时是好的」。** 说「这个失败路径我设计过，它现在的表现是符合预期的」。

## 6. 演示的三条铁律

1. **演治理，不演聊天。** 审批停住那一刻是整场演示的高潮，
   前面所有步骤都是为了铺垫它。
2. **每一步都说「不做会怎样」。** 观众看到的是界面，
   你要讲的是界面背后被挡住的那个坏结果。
3. **留代码走读的时间。** 界面证明你做出来了，
   代码注释证明你**想过**。后者才是面试要考的。

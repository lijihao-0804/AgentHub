## 三档自我介绍

**30 秒版**

> AgentHub 是一个企业级 Agent 运行时与控制平面。它解决的不是「怎么让大模型回答问题」，
> 而是「怎么让一个会调用工具、会改动真实系统的 Agent，在企业里可审计、可审批、可复现、
> 可评估」。全栈自研：Python/FastAPI 后端 4.4 万行，Next.js 前端，25 个 Alembic 迁移，
> 92 个测试文件。上面跑着四个应用——科研助理、故障排查、数据分析、客户支持——它们共用
> 同一套运行时，没有第二套。

**3 分钟版**

> 核心判断是：Agent 产品的难点不在模型，在**治理**。所以整个项目围绕四个不变量来建：
>
> 1. **发布即冻结**——AgentVersion 一旦发布，prompt、工具契约、模型档案、上下文预算全部
>    快照化不可变，因此一次 Run 永远可以解释「当时用的是什么」。
> 2. **工具即数据**——工具不是代码里的 if-else，而是带 `effect / risk / approval_policy`
>    的数据库记录；WRITE 类工具走审批闸门，READ 类不走，这个判定在 `ToolPolicy.decide()`
>    一个函数里。
> 3. **审批是持久中断**——命中 WRITE 工具时，Run 进入 `WAITING_APPROVAL`，LangGraph
>    checkpoint 落库，进程可以重启；人批准后**在同一个 run 内恢复**，不是新开一次。
> 4. **不确定就说不确定**——远端 WRITE 调用发出去之后连接断了，系统不重试、不猜，
>    标记 `UNKNOWN_OUTCOME` 并把 Run 置为 `NEEDS_ATTENTION` 交给人。
>
> 再往上，Thread 承载多轮，Artifact 承载可引用的产出，而 Artifact **不是模型写的**——
> 是从工具结果里投影出来的，带 `{run_id, tool_call_id, tool_identity, step_sequence}`
> 溯源戳。这一条是整个防幻觉设计的地基。

**10 分钟版**

按 [02-架构与数据流.md](02-架构与数据流.md) 的五张图讲：
系统分层 → Run 生命周期 → 审批中断与恢复 → MCP 远程工具调用 → 四应用共用运行时。

## 一句话记住每个重点

- **冻结快照**：可解释性的前提是「当时的定义还在」。
- **上下文预算**：截断必须是有语义的取舍，不是从头砍字符串。
- **审批中断**：`interrupt()` + checkpoint = 人类进入循环而不阻塞进程。
- **UNKNOWN_OUTCOME**：分布式系统里最诚实的状态是「我不知道」。
- **SSRF 防护**：必须解析 DNS 再判断，多记录不一致直接拒绝。
- **密钥三律**：静态加密、只写不读、永不出现在响应与日志。
- **知识快照**：RAG 的可复现性来自快照 ID，不是「LATEST」。
- **Artifact 投影**：模型永远不写 Artifact。
- **Thread ≠ Run**：会话是耐久单位，Run 是一次执行。
- **ThreadKind 只是路由标签**：没有任何运行时行为分支在它上面。

# AgentHub 项目报告（面试向）

这一组文档的目的只有一个：**让你在面试里能把 AgentHub 讲清楚，并且经得住追问。**

它不是使用手册，也不是 API 文档（那些在 `docs/api-contracts.md`、`docs/milestones/`）。
它是「项目讲述稿 + 深挖问答集 + 自证证据链」。

> ### ⚠️ 先分清这里和 [`docs/learning/`](../learning/) 是两种东西
>
> | | `docs/report/`（本目录，20 章） | [`docs/learning/`](../learning/)（4 章） |
> |---|---|---|
> | 视角 | **结果视角**：做了什么、为什么这么设计 | **学习视角**：怎么一层一层把代码吃透 |
> | 回答 | 「这个项目是什么，凭什么成立」 | 「我今天只懂 30%，下一步该打开哪个文件」 |
> | 产出 | 读完**能讲** | 读完**能改**，并且知道改完会发生什么 |
> | 形式 | 我写完之后的总结 | 你自己边读边填的实验记录（每章都要先猜再读再动手） |
>
> **如果你的目标是面试前复习、证明设计合理、回答追问 —— 留在这里。**
> **如果你的目标是把 `runtime.py` 真正读熟到被随便指一段都不陌生 —— 先去 [`docs/learning/`](../learning/)。**
>
> 报告不能替代教材：看完 20 章报告仍然可能在面试官打开 `runtime.py` 随手一指时卡住，
> 因为你从来没有亲手让那段代码**变过**。

## 三档自我介绍

**30 秒版**

> AgentHub 是一个企业级 Agent 运行时与控制平面。它解决的不是「怎么让大模型回答问题」，
> 而是「怎么让一个会调用工具、会改动真实系统的 Agent，在企业里可审计、可审批、可复现、
> 可评估」。全栈自研：Python/FastAPI 后端 4.9 万行，Next.js 前端，29 个 Alembic 迁移，
> 105 个测试文件、890 个单元测试通过。上面跑着四个应用——科研助理、故障排查、数据分析、客户支持——
> 它们共用同一套运行时，没有第二套。

**3 分钟版**

> 核心判断是：Agent 产品的难点不在模型，在**治理**。所以整个项目围绕四个不变量来建：
>
> 1. **发布即冻结**——AgentVersion 一旦发布，prompt、工具契约、模型档案、上下文预算全部
>    快照化不可变，因此一次 Run 永远可以解释「当时用的是什么」。
> 2. **工具即数据**——工具不是代码里的 if-else，而是带 `effect / risk / approval_policy`
>    的数据库记录；WRITE 类工具走审批闸门，READ 类不走，这个判定在 `ToolPolicy.decide()`
>    一个函数里。
> 3. **审批是持久中断**——命中 WRITE 工具时，Run 进入 `WAITING_APPROVAL`，LangGraph
>    checkpoint 落库，进程可以重启；人批准后**在同一个 run 内恢复**，不是新开一次。
> 4. **不确定就说不确定**——远端 WRITE 调用发出去之后连接断了，系统不重试、不猜，
>    标记 `UNKNOWN_OUTCOME` 并把 Run 置为 `NEEDS_ATTENTION` 交给人。
>
> 再往上，Thread 承载多轮，Artifact 承载可引用的产出，而 Artifact **不是模型写的**——
> 是从工具结果里投影出来的，带 `{run_id, tool_call_id, tool_identity, step_sequence}`
> 溯源戳。这一条是整个防幻觉设计的地基。

**10 分钟版**

按 [02-架构与数据流.md](02-架构与数据流.md) 的五张图讲：
系统分层 → Run 生命周期 → 审批中断与恢复 → MCP 远程工具调用 → 四应用共用运行时。

**如果对方问「为什么做这么多」**：按 [00 章](00-从零到现在.md)的九幕讲因果链，
并主动交出自己认为溢出的三项（MCP 数量、手写 CSS、评估平台的时机）。
主动承认溢出比辩护更可信。

## 一句话记住每个重点

### 设计不变量

- **冻结快照**：可解释性的前提是「当时的定义还在」。
- **上下文预算**：截断必须是有语义的取舍，不是从头砍字符串。
- **审批中断**：`interrupt()` + checkpoint = 人类进入循环而不阻塞进程。
- **UNKNOWN_OUTCOME**：分布式系统里最诚实的状态是「我不知道」。
- **知识快照**：RAG 的可复现性来自快照 ID，不是「LATEST」。
- **Artifact 投影**：模型永远不写 Artifact。
- **Thread ≠ Run**：会话是耐久单位，Run 是一次执行。
- **ThreadKind 只是路由标签**：没有任何运行时行为分支在它上面。
- **信任盖章**：工具结果的 trust 由运行时写，不由 payload 自称。
- **审批终态**：决策一旦做出不可修改，撤回是新事件不是状态。
- **Run 导入评估集时，Run 只是证据不是标注**：`expected` 必须人来给——
  否则评估集会去拟合模型现有的错误。
- **记忆必须先可重放，才允许存在**：`effective_memory_snapshot` 冻结「这次用了哪几条」，
  不可重放的记忆等于亲手毁掉事后解释能力。
- **记忆是证据不是指令**：注入的记忆强制盖 `UNTRUSTED`，走可被驱逐的 `MEMORY` 类别，
  不是必留的系统提示。
- **记忆只能停用，不能删除**：删掉它就等于删掉了「那次运行为什么会那么说」的答案。
- **两个记忆开关默认关**：全关时 `resolved_spec` 整体省略 `memory`，
  既有 agent 的哈希与这个功能存在之前**一模一样**。
- **`ON DELETE SET NULL` 在复合外键上必须点名列**：不点名就会把 `NOT NULL` 的
  `workspace_id` 一起置空——症状是「删会话必 500」，迁移 `0029` 修的就是这个。
- **懒加载的模型要在启动时预热**：`knowledge_warm_models_on_start` 修掉的是
  「每次部署之后的第一次 `search_knowledge` 必然超时」。

### 安全与实现

- **SSRF 防护**：必须解析 DNS 再判断，多记录不一致直接拒绝。
- **密钥三律**：静态加密、只写不读、永不出现在响应与日志。
- **结构化截断**：投影成合法 JSON 并标 `truncated`，不切字符串。
- **幂等要防的是「同一次提议被重复提交」**，不是「同一个动作被重复提议」。
- **`min-width: auto` 是 CSS 布局爆破的头号元凶**：
  容器里可能出现宽内容就写 `minmax(0, 1fr)`。
- **对比度要对合成后的真实背景测**，不是对设计稿的白底测。

### 自证阶段学到的（第三篇）

- **写完不等于成立**：11 章真机第一次跑就挖出一个会让**所有**知识检索必然失败的 bug。
- **自动化审计的第一个发现必须手工复核**：实测误报率 43%，
  其中一个误报还是审计脚本自身的 bug。
- **判「模型有没有做坏事」的正则最不可靠**：模型*讨论*一件坏事和*做*一件坏事
  文本高度相似——实测把「主动驳回注入」误判成了「被注入攻陷」。
- **检索排序区分不了它不知道的东西**：v1 已废止、v2 现行，
  如果 `superseded_by` 没进数据模型，排序就只能靠语义，而这两份文档语义上几乎一样。
- **「答不了」是一个有分数的信号，别扔掉**：negative 与正例的 rerank 分布可分，
  缺的只是一个阈值——但**窗口只有 0.04，不是我先前算的 1.77**。
- **排序层的常量惩罚解决不了版本选择**：已实测证伪（2 对 3 错，分数差完全交错）。
  信号在**问题**里，不在文档里，所以该由看得见问题的模型来判。

### 第一档与外部审查学到的（第四篇）

- **最大的缺口往往不是缺能力，是造好的能力只接在一条路径上**：
  持久化恢复机制早就有了，但只服务审批；普通执行路径一天也没用上。
- **「迁移里有、metadata 里没有」等于「下一次 autogenerate 会把它删掉」**：
  这类破坏不会报错，它会在某次例行操作里静默发生。
- **权限的粒度不是「能不能看见这个对象」，是「能看见它的哪些字段」**：
  VIEWER 该看得到 Run 的状态与用量，不该看得到 prompt 原文和模型写回的正文。
- **断线重连能成立的前提是「不该存的别存」**：`message.delta` 故意不入库，
  所以重放重建的是结构与最终输出，永远不会把答案追加两遍。
- **测「默认值是什么」的测试必须与机器隔离**：读着开发者的 `.env` 去断言默认值，
  会在干净检出上通过、在有配置的工作机上失败——判断方向正好反了。
- **外部审查能压出自审压不出来的东西**：17 章 10 条 finding 全部属实、无一误报，
  其中权限越界那条，我自己压了三轮都没压出来。

### 截图实拍留下的（18 章）

- **自动化截图和自动化测试是同一类活动**：第一版点击助手点中了侧边栏的
  `<a>运行</a>` 而不是调试台的提交按钮，照样拍出了一张「成功」的图——
  只是拍的是错的页面。
- **界面上反复出现的一件事是「承认不知道」**：未知 token 单独计分母、
  成本不可测就留 `—`、门禁有 `INCONCLUSIVE`、客户信息块主动声明"这是你填的不是查的"。
- **截图证明它今天能跑，不证明它明天还能跑**——前端仍然是 0 测试。

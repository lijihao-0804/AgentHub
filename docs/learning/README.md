# AgentHub 按顺序学习

**从 [第 1 课：架构入门](00-architecture-first.md)开始。**

这个目录是主学习入口。第一遍按下表顺序学习，先不翻全部历史报告和面试题。2026-10-09 本轮已整合架构课；其他教材复用现有内容，后续可逐课整理。本轮没有修改业务实现。

## 学习顺序

| 顺序 | 学习文档 | 解决什么问题 | 学完应能做到 |
| --- | --- | --- | --- |
| **1 · 架构** | **[00-architecture-first](00-architecture-first.md)** | 进程、模块、存储、控制平面与 Runtime 如何协作 | 画系统图，从源码指出工具治理和持久恢复位置 |

## 第一天就做这三件事

1. 顺读架构课 §1–9；遇到“暂停自测”先回答，再继续。
2. 按 §10 打开六个代码位置，各写一句自己的解释；不需要启动服务。
3. 用 §11 自测：不看文档画系统图，再解释为什么审批后还是原 Run。

完成架构课再去一次 Run 文档。不是读完页数就算理解；讲不清时回到具体函数。

## 统一学习方法

每次只处理一个问题，写下：**预测 → 实际调用链 → 观察 → 为什么 → 边界 → 尚不理解的点**。

- 文档中的源码基线/旧行号是时点信息，按函数名找当前代码。
- 原样源码节选、流程示意、预计实验现象和实测证据分别标注；预计现象不能记作 PASS。
- 已有工程测试不代表你已亲自做过实验；面试模板也不能证明个人贡献。
- 第一遍先把执行骨架讲清，后续沿 Runtime → Policy → Approval → Durability → Domain Model → RAG/Memory → Evaluation 深入。

## 需要运行实验时

架构课只读代码，无需准备服务。到实验阶段再按 [Hero Demo 启动条件](../report/07-现场演示脚本.md#0-实际启动条件与安全范围)准备独立 lab 数据库、Redis namespace、blob 路径及工作区，API/worker/checkpoint 指向相同 lab 环境。

不覆盖共享 `.env`，不改发布版本、Runtime 或测试断言。调整只作用于 lab 草稿/新版本/fixture；结束后关闭自己创建的进程并撤销临时配置，保留比较记录。真实模型需要有效凭据，可能产生费用；本轮没有运行这些实验。
